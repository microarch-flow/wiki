# 反馈环的时钟约束：依赖、频率与启动间隔

## 反馈环是什么

累加器将上次结果送回加法器。设输入 `x[n]`、状态 `s[n]`：

```text
s[n+1] = s[n] + x[n]
      ┌──── register ◀──── + ◀──── x[n]
      └───────────────────▶┘
```

输入是新数据与旧状态；输出是新状态。若要求同一状态每拍更新，寄存器输出、加法与布线、目标寄存器 setup 必须在对应的采样窗口内完成。路径最小延迟还要通过 hold 检查。

## 增加寄存器为何改变依赖

若直接在反馈路径插入一拍，递推会变成依赖更早的状态。未经调度或修正时，顺序累加的语义不再相同。处理方法不只有缩短加法器：可使用多个交错累加器或改变归约树，最后合并部分和；也可降低单个依赖链的发射速率。这些方案要检查状态数、输入顺序、输出延迟、合并代价及数值语义。浮点加法和有溢出、饱和的定点运算尤其不能默认重排等价。

例如反馈结果需两拍才能返回，单一依赖链的 II 至少为 2 拍。若有两项本来独立的任务，两条累加链可交错发射：每链隔两拍更新，资源允许时总体每拍接纳一项；两项各自输出，无须合并。若将同一归约拆成两条部分和，则末尾必须合并，并验证重排是否保持浮点舍入或定点溢出、饱和语义。两种情况都要求运算单元和状态端口支持该交错。

## 一个时钟域的频率约束

同一时钟域内，**所有**有效的前馈和反馈 setup 路径共同决定周期要求，不能只检查反馈环。假设反馈路径的完整 setup 要求为 1.0 ns、某前馈路径为 1.4 ns，且不存在更慢路径，则 `T>=1.4 ns`，`f<=1/1.4 ns≈714 MHz`。该例忽略未列出的模式和路径，只用于说明求最大值。hold、脉宽、跨域和输入输出约束仍需独立检查。其他时钟域也要分别检查。

改变进位结构或插入流水级可能缩短某条路径，但布线、寄存器开销、其他关键路径和时钟约束会限制收益。不能假定前馈逻辑可无限切级提频。累加位宽与进位结构同时影响数值范围和路径延迟；具体关系应由实现与时序数据校准。

## 建模启示

```text
ClockDomain { setup_requirements_per_path, hold_checks, frequency }
Feedback { dependency_distance, latency_cycles, ii_per_chain,
           independent_accumulators, combine_cost, arithmetic_semantics }
```

模拟器应观察每次输入的接纳周期、状态更新、最终合并、输出延迟和实际 II。时序模型则应对该域所有路径取完整 setup 要求的最大值；不能把某个环的延迟直接当作整芯片的唯一频率上限。若没有 STA 数据，频率是明确标注的假设或外部输入，不是已验证结果。
