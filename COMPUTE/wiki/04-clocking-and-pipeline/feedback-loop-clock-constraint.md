# 反馈环的时钟约束:设定时钟周期的最硬约束

主线:[计算 / 通信比](../01-overview/compute-communication-ratio.md)——本篇:给频率项设一个无法用分母换取的硬下界。

---

## 这页在回答什么问题

[pipeline register 插入](./pipeline-register-insertion.md) 说"切逻辑插 register 就能提频"。但有一类逻辑**不能这么切**——带自反馈的逻辑(累加器、running sum、状态机)。本篇回答:为什么在反馈环里插 register 会**改变计算语义**(而不是单纯变慢),以及为什么反馈环的关键路径是整片芯片**时钟周期的最硬下界**。

---

## 1. 真正的硬骨头:带反馈环的逻辑

前面讲的"插 register 提频"是前馈流水线的简单情形。真正的硬约束是**自反馈逻辑**——输出回灌输入。最常见的例子:累加器(running sum),每周期把新数加到自己身上。

```
        ┌──────────────────────┐
   in ──▶(  +  )──▶│ reg │──────┤
         ▲                      │
         └──────────────────────┘   ← 输出回灌输入,下一拍继续累加
```

每个时钟沿:`reg` 锁存当前累加和,下一拍这个和回到加法器,和新的 `in` 相加。**这个 `+` 必须在一个时钟周期内算完**——因为它的输出下一拍就要作为输入用。

---

## 2. 为什么不能往中间插 register

假设这个 `+` 太慢(关键路径超了),想用上一篇的手段插个 register 提频。**会坏掉。**

```
        ┌────────────────────────────────┐
   in ──▶( + )──▶│reg_A│──▶│reg_B│────────┤   ← 中间多插了 reg_B
         ▲                                │
         └────────────────────────────────┘
```

**因为** 插了 register 后,回灌的值晚了一拍才到加法器,**所以** 语义变了:本该是"所有输入的单一累加和",现在变成**两条独立的累加和**——偶数拍的输入累加成一条、奇数拍的累加成另一条,互不相加。结果完全错误,不是慢一点,是算错了。

> ⚠️ 常见误解:以为"插 register 提频"对所有逻辑都适用。**跨越反馈边界插 register 会改变语义**,把一条累加链劈成两条交错的链。这不是性能问题,是正确性问题——所以它是硬约束,不是 trade-off。

---

## 3. 反馈环 = 时钟周期的最硬下界

任何芯片某处都有反馈环(累加器、状态机、控制逻辑)。**所以** 这些环的关键路径设定了时钟周期的**最硬下界**:整片芯片的时钟,不能快于最慢的那个反馈环能稳定的速度。前馈逻辑可以靠插 register 任意细分、追上任意高频,但反馈环不行——它是那个"无论怎么优化布局都绕不过去"的下界。

**一个重要细化**:`+` 本身不是原子的——它内部是一堆 full adder(见 [压缩树与进位结构](../02-datapath-foundations/dadda-and-adder-trees.md)),**可以在内部切**(优化进位结构、用 Kogge-Stone 缩短进位链)。能做的是**让这个加法器本身更快**(更好的进位结构),不能做的是**跨越反馈边界插 register**。

```
可以:  优化 + 内部的进位结构(ripple → Kogge-Stone),缩短这一拍的关键路径
不行:  在 + 和它的反馈之间插 register(破坏累加语义)
```

所以反馈环的提频手段不是"插 register",而是"把环内的组合逻辑本身做快"——这把压力传回到 [final CPA 的进位结构选择](../02-datapath-foundations/dadda-and-adder-trees.md#4-最后一步vector-merge-加法器的进位结构):在反馈环里,加法器的进位结构不只是面积问题,而是频率上限问题。

---

## 4. 这对 AI 加速器意味着什么

AI 加速器的反馈环主要在**累加/规约**路径:systolic array 的部分和累加、vector unit 的 reduction。这些累加器的精度(见 [精度非对称](../02-datapath-foundations/multiply-accumulate-from-gates.md#2-精度非对称乘法用低精度累加用高精度))越高,加法器越宽,反馈环关键路径越长,频率上限越低。

**所以** 累加精度不是免费的:它既影响数值正确性(分母侧不算),也通过反馈环关键路径影响**频率上限**。这是"高精度累加"在频率维度的隐藏代价——一个架构师必须在"数值精度"和"时钟频率"之间权衡的真实约束。

---

## 5. 本篇在主线上的位置

反馈环给[计算 / 通信比](../01-overview/compute-communication-ratio.md)里的**频率项设了一个硬下界**。回忆吞吐 = 每周期工作量 × 频率——前馈逻辑可以靠插 register(花分母)无限抬频率,但反馈环不行,它的关键路径是无法用分母换取的天花板。这也是本章和频率有关的最硬一条约束:**你能把芯片做多快,最终由最慢的那个反馈环决定,而它只能靠把环内逻辑本身做快(如更好的进位结构)来改善,不能靠流水化绕过。**

---

## 建模启示

- **反馈环是时钟/流水层里唯一不可折叠的部分。** 前馈流水线可折叠成 `(latency, throughput)`,但反馈环的关键路径是"这个微架构能跑多快"的硬上限,**直接决定 throughput = 每周期工作量 × 频率 中的频率项**。
- **必须显式建模的状态变量**:每个反馈环(累加器/规约器)的 `loop_critical_path_ns`,它由环内组合逻辑(主要是加法器,其 `acc_bits` 和 `carry_structure`)决定。`max_freq = 1 / max(所有反馈环的 loop_critical_path_ns)`。
- **建模规则**:前馈块和反馈块用**两套模型**——前馈块 `max_freq` 可通过增加流水深度提升;反馈块 `max_freq` 是固定下界,只能通过改环内逻辑(进位结构)提升,不能通过流水化提升。
- **关心频率估计时**:必须对累加器/规约这类反馈环**单独建模其关键路径**,而非把所有逻辑当可任意切分的流水线。把反馈环当前馈处理会高估频率上限。
- **事件/数据结构草图**:`FeedbackLoop{acc_bits, carry_structure} → loop_critical_path_ns`;整片 `max_freq = 1 / max_over_loops(loop_critical_path_ns)`。累加精度 `acc_bits` 同时进数值正确性模型和频率上限模型——这个耦合必须显式保留。
