# 权重载入与 trickle-feed:为什么"慢但窄"是对的

上级:[03 · systolic array](./README.md)
相关:[为什么要 systolic array](./why-systolic-array.md)、[dataflow 分类](./dataflow-taxonomy.md)、[阵列 sizing](./array-sizing-tradeoff.md)
主线:[计算 / 通信比](../01-overview/compute-communication-ratio.md)——本篇引出"配置流 vs 数据流"的分离:一次性载入只计带宽/面积,稳态流才计延迟。

---

## 这页在回答什么问题

[weight-stationary](./dataflow-taxonomy.md#2-weight-stationary复用权重基准长文的选择) 让权重就地驻留在阵列里反复复用。但驻留的权重**最初**怎么装进去?本篇回答:为什么载入要优化**带宽(= 面积 = 跨边界布线数)而不是延迟**,以及 trickle-feed(daisy-chain 慢速灌入)如何把载入布线压在 x 量级而非 x·y。

---

## 1. 关键认识:载入只发生一次,所以优化带宽而非延迟

权重什么时候载入?**只在切换模型(或换权重块)时,载入一次。** 之后这组权重要在阵列里待很久,处理大量激活。所以:

```
载入频率:  罕见(切模型时)         → 不在乎慢
载入对象:  整个 x·y 权重矩阵        → 在乎窄(布线 = 面积)
稳态运行:  每周期处理新激活向量      → 在乎快(这才是热路径)
```

**因为** 载入是一次性的、不在性能热路径上,**所以** 优化目标是**带宽 = 跨边界布线数 = 面积**,而不是延迟。能慢慢灌,就别为它铺宽布线——那些布线在 99.99% 的时间里(稳态运行时)是浪费的面积。

> ⚠️ 常见误解:以为"载入权重要快,所以要宽总线一次灌满"。恰恰相反。载入慢一点完全无所谓(切模型本来就罕见),但为快速载入铺的宽布线会永久占面积、拉低稳态时的计算 / 通信比。**正确的优化是:用尽量窄的通道,慢慢灌。**

---

## 2. trickle-feed:用 x 宽的通道灌满 x·y 的阵列

如果直接给每个 PE 铺一条载入线,布线是 x·y 量级——太贵。trickle-feed 用 daisy-chain(菊花链)把它压到 x:

```
cycle 0:  顶行 ← w_row0
cycle 1:  顶行 ← w_row1,   原 row0 ↓ 下移一格
cycle 2:  顶行 ← w_row2,   其余整体 ↓ 下移
  ...                                        ← 连续 y 个周期灌满
cycle y-1: 顶行 ← w_row(y-1), 阵列填满
          ───────────────────────────────────
          跨边界布线只需 x 宽(顶行宽度),而非 x·y
```

**机制**:每周期只往**顶行**灌一行权重(x 个值),其余行整体下移一格,腾出顶行。连续 y 个周期,权重一行行"滴入"(trickle)并下沉到位。**因为** 任何时刻只有顶行在跨边界接收,**所以** 布线只需 x 宽,载入耗时 y 个周期——用时间(y 拍)换了空间(布线从 x·y 降到 x)。

> Dwarkesh 的总结很精准:**载入只发生一次,所以优化带宽而非延迟;用更少的窄通道慢慢灌,因为这值要在里面待很久。**

---

## 3. 这是"配置流 vs 数据流"二分的原型

trickle-feed 揭示了一个贯穿全域、也贯穿你 DMA/NOC 笔记的二分:**同一个阵列上有两种语义完全不同的数据移动**:

| | 配置流(权重载入) | 数据流(激活向量) |
|---|---|---|
| 频率 | 罕见(切模型) | 每周期 |
| 优化目标 | 带宽 / 面积(窄、慢) | 延迟 + 带宽(快、宽) |
| 布线量级 | x(trickle 压窄) | x(进出向量) |
| 建模 | 只计带宽/面积,延迟可忽略 | 延迟和带宽都要计 |

**所以** 把这两种流混为一谈是建模错误:权重载入慢得多但只发生一次,激活流才是性能热路径。这正是 [01-overview 纲领篇](../01-overview/compute-communication-ratio.md#建模启示) 里 `Move{kind ∈ {config, steady}}` 那个字段的来源。

> 衔接 DMA:稳态激活流的"按节拍喂数 + double-buffering"和 DMA 的 tiling 同源,见 [`DMA/.../tiling-double-buffering`](../../../DMA/wiki/04-programming-model/tiling-double-buffering.md)。区别:trickle 是窄带一次性配置,DMA double-buffer 是稳态隐藏延迟。
>
> 衔接 3D / 互连:"窄而慢 vs 宽而快"的取舍,和 SerDes(窄而快串行) vs 并行宽总线的取舍是同源问题——载入流选了"窄而慢"这一极。

---

## 4. 本篇在主线上的位置

trickle-feed 是[计算 / 通信比](../01-overview/compute-communication-ratio.md)主线里一个精巧的局部优化:它认识到**不是所有数据移动都该按同一标准优化**。权重载入这条配置流,因为罕见,可以用最窄的布线(最小面积分母)慢慢完成,把宝贵的布线面积全留给稳态激活流。它把"分母"细分成"一次性配置成本"和"稳态运行成本",只在后者上花面积——这是对主线的精细化,而非新机制。

---

## 建模启示

- **配置流与稳态流必须用不同模型。** archax 的 Interaction 抽象应区分"一次性配置流"(权重载入:只计带宽/面积,延迟摊到 ~0,因为发生频率极低)与"稳态数据流"(激活:计延迟+带宽)。把权重载入按稳态流建模会高估它对吞吐的影响。
- **必须显式建模的状态变量**:`weight_load_cycles ≈ y`(载入耗时)、`weight_load_width ≈ x`(载入布线宽度/面积)、`model_switch_frequency`(切模型频率,决定载入成本摊薄程度)。
- **可折叠**:在稳态吞吐建模里,权重载入延迟通常可折叠成"切模型时的一次性开销",不进每周期的热路径——除非 model_switch_frequency 高(频繁切权重块,如 MoE 路由),此时不可折叠。
- **关心 MoE / 频繁切权重时必须保留**:载入成本不再可摊薄,`weight_load_cycles` 进入热路径。这正是 MatX 把权重放 SRAM 的动机——SRAM 驻留让"切权重块"的载入更便宜。
- **事件/数据结构草图**:`Move{kind: config, bytes: x·y·wbytes, width: x, when: model_switch}` vs `Move{kind: steady, bytes: x·vbytes, width: x, when: each_cycle}`。计算 / 通信比的分母 = 稳态流为主,配置流按频率加权摊入。
