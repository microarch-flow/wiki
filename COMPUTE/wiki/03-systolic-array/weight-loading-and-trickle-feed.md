# 权重载入与 trickle-feed：宽度、周期和重叠

上级：[03 · systolic array](./README.md)
相关：[dataflow 分类](./dataflow-taxonomy.md)、[阵列 sizing](./array-sizing-tradeoff.md)、[DMA 双缓冲](../../../DMA/wiki/04-programming-model/tiling-double-buffering.md)

## 机制与接口

在 weight-stationary dataflow 中，计算期间权重驻留在处理单元（PE）。启动首个 tile 或替换不再驻留的 tile 时，仍需把权重装入。trickle-feed 是一种接口：每拍从阵列顶部注入 `x` 个权重；在同一采样沿，每行已有权重向下一行移一格。阵列有 `y` 行，忽略供数停顿，连续 `y` 拍可装满。跨边界通道宽度为 `x` 个权重，不代表整个阵列内部的寄存器、连线和控制免费。

输入为按最终位置排序的权重行，输出是各 PE 的本地权重。首次注入的行最终位于底部。下面只是假设的 `x=2, y=3` 例子：

```text
拍 0 结束：顶 [a,b]，中 [空]，底 [空]
拍 1 结束：顶 [c,d]，中 [a,b]，底 [空]
拍 2 结束：顶 [e,f]，中 [c,d]，底 [a,b]  ← 装满
```

这是三拍，不是从拍号 0 到 2 的差值两拍。同步移位已包含在这三拍内，不能在灌满后再重复加 `y-1` 拍。若下游移位、采样或加载协议不同，应以该实现的接口日程重新计算。

## 首块、换 tile 与覆盖条件

首块冷启动如果没有预加载，计算要等权重就绪。切换 tile 时仍需新 tile 的载入；同一 tile 多次使用才可分摊该成本。一次性配置不是只计面积或带宽：它也消耗时间、能量，并可能阻塞计算。

若只有一套权重寄存器，装下一块会覆盖当前权重；除非实现提供安全并发机制，否则必须等当前计算用完。若有独立的双权重 bank、足够的供数带宽，且写入不争用计算资源，可以在计算当前 tile 时装下一块。只有同时满足这些条件，重叠的部分才可隐藏。

假设每个 tile 计算 6 拍、装载 3 拍，且没有其他开销：单 bank 先后执行两个 tile 需 `3+6+3+6=18` 拍。双 bank 可先装 3 拍，再用 6 拍计算 tile 0，同时装 tile 1，最后再算 6 拍，共 `3+6+6=15` 拍。首块的 3 拍仍存在。若载入超过计算时长，差额会形成等待；若供数中断，载入时间还会增加。

## 建模启示

```text
WeightLoad { tile, weight_count, lane_width, start, completion, target_bank }
Compute    { tile, required_bank, start, completion }
```

记录权重驻留、每 tile 装载次数、bank 竞争、加载宽度与完成时间，以及加载与计算能否重叠。模拟器应输出冷启动延迟、换 tile 等待、传输字节、bank 占用和总完成时间。若稳态平均吞吐可摊薄加载，也应保留首块延迟和分摊假设。
