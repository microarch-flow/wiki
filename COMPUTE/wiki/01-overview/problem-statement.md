## 这页在回答什么问题

在搭任何电路之前,先把问题摆正:**AI 算力单元真正要解决的,不是"怎么把乘加做快",而是"怎么在绝大部分面积都耗在搬数据的前提下,让做乘加的那一小块尽量满负荷"。** 这一页用一个具体的门数账,把这个问题量化出来——它是后面所有章节的共同出发点。

---

## 1. 一个会颠覆直觉的门数账

拿最朴素的算力单元:一个 register file(比如 8 个 entry)+ 一个乘加器(MAC),从 RF 读 3 个输入、写回 1 个结果。这正是 Volta 之前 GPU 的 CUDA core、以及 CPU 标量单元的结构。

软件视角下,这段代码是免费的:

```c
out = a[i] * b[j] + c[k];   // 看似:一次乘、一次加,仅此而已
```

硬件视角下,代价完全在别处。"选第 i 号寄存器"这个动作,是一个 **mux(多路选择器)**——一个 n 输入、p 位的组合电路,成本约 n×p 个门。MAC 有 3 个输入,就是 3 个 mux。算总账(n=8 entry,p 位宽,q=4 位乘数):

```
数据搬运(3 个 mux):   3 × n × p = 3 × 8 × p = 24p 个门
真正计算(乘加器):     p × q     =     4 × p =  4p 个门
                      ───────────────────────────────
比例:                 搬运 : 计算 ≈ 6 : 1
```

> **七八成的面积花在了软件完全不可见的数据搬运上,真正做乘加的逻辑只占零头。**

这不是某个糟糕设计的偶然,而是**通用算力单元的结构性事实**。灵活性(任意从 8 个寄存器里选数)的代价,就是这 24p 的 mux 门。

## 2. 问题的三个面孔

同一个"搬运吃掉面积"的问题,会在不同抽象层级换不同的面孔出现:

| 面孔 | 分母长什么样 | 在哪一章 |
|---|---|---|
| **选数** | mux 选寄存器,n×p 门,每次访问都付 | [mux-and-data-movement-cost](../02-datapath-foundations/mux-and-data-movement-cost.md) |
| **同步** | 时钟 register 占 ~6–10 门当量,远大于它锁存的逻辑 | [global-clock-synchronization](../04-clocking-and-pipeline/global-clock-synchronization.md) |
| **可配置布线** | FPGA 用 mux 在"现场"配置连接,~10× 门膨胀 | [lut-mux-and-10x-overhead](../05-fpga-vs-asic/lut-mux-and-10x-overhead.md) |

## 3. 为什么这个问题在 AI 上特别尖锐,也特别有解

通用 CPU 没法逃出这个困境——它必须支持任意控制流、任意数据访问,所以那 24p 的灵活性税躲不掉。但 **AI workload 有两个结构性特征,让我们能系统性地把分母压下去**:

1. **计算高度规则**:矩阵乘是三重循环,访问模式静态可知。→ 可以把循环固化进硬件(systolic array),不再每次从 RF 选数。
2. **权重长时间不变**:推理时权重矩阵固定。→ 可以让权重就地驻留在阵列里反复复用,跨边界的只剩输入/输出向量。

这两点正是 §03 systolic array 的全部动机:**把"灵活但搬运昂贵"的通用结构,换成"专用但搬运便宜"的固定结构**。代价是失去通用性(只会做矩阵乘),收益是比值从 6:1 的劣势翻转成 y 倍的优势。

> ⚠️ 常见误解:以为 AI 加速器的优势主要来自"更多更快的乘法器"。真正的优势来自**砍掉分母**——砍掉 mux 选数(systolic)、砍掉分支预测(见 [cpu-vs-gpu-core-area](../07-chip-organization/cpu-vs-gpu-core-area.md))、砍掉 cache 非确定性(scratchpad)。乘法器本身从来不是瓶颈。

## 建模启示

- **建模的第一性原理:把分母(数据搬运)当主体,分子(算术)当零头。** 任何"只数 FLOP、不数 bytes moved"的性能模型,都会系统性高估算力单元的效率——因为它只看到了 4p,没看到 24p。
- **必须显式建模的状态变量**:RF entry 数 `n`、位宽 `p`、每次访问跨 RF 边界的字节数。mux 成本随 `n` 线性增长,这是一个可参数化的旋钮。
- **可折叠的细节**:mux 内部的 AND/OR 门结构可折叠成"n×p 门"这一个面积数;真正要保留的是"每次算术伴随几次搬运、每次搬运多少字节"。
- **事件类型草图**:`RegRead{entry, bytes}` / `RegWrite{entry, bytes}` 与 `MAC{precision}` 成对出现的频率,直接给出该单元的计算 / 通信比。比值低于某阈值,就是该把循环上提、走 systolic 的信号。
