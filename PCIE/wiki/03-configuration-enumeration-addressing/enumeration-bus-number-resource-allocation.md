# 枚举、总线号与资源分配

上级：[03 配置、枚举与地址映射](./README.md)

相关：[配置空间、BAR 与 Capability](./config-space-bar-capability.md)

## 这页在回答什么问题

为什么设备插上去以后不是天然就能工作，主机到底做了哪些组织工作。

## 枚举在做什么

枚举过程通常要完成：

1. 发现拓扑中的设备和 bridge
2. 分配 bus number / device / function 视角
3. 读取配置空间信息
4. 为 BAR 分配地址资源
5. 打开需要的功能，例如 bus mastering、MSI-X 等

## 它为什么本质上是系统资源组织

因为主机不仅是在“找设备”，还在决定：

- 哪段地址留给哪个设备 BAR
- 哪些设备可以发 DMA
- 多级 switch / bridge 下资源窗口怎么切

## 为什么这里经常出问题

常见故障包括：

- BAR 空间不够
- bus number 规划不合理
- 某级 bridge 窗口没打开
- capability 配置不完整

这些问题表面像“设备不工作”，本质上常是资源组织没闭环。

## 一句话理解

枚举不是点名，而是把拓扑、资源和能力装配成一张可运行的系统地图。
