# Wiki 与博客设计规则

本文件记录整理本仓库 Wiki 和博客时的共同要求，供内容作者、维护者和协作工具使用。专题可以在本文件之外维护更具体的术语、模板和技术约束。

规则随需求调整。用户可以随时要求增加、删除或修改；维护者也可以在发现问题时提出调整。以本文件的当前内容为准，并用 Git 记录变更。当前任务中用户的明确要求优先，不把一次性的具体选择自动固化为长期规则。

## 1. 目标与内容范围

- 文章要**通俗易懂，也要直指本质**。让读者知道问题是什么、为什么发生、机制如何起作用，以及结论在什么条件下成立。
- 以中文为主，运用约 80% ASD-STE100 的写作原则：句子简短、表述明确，每段聚焦一个问题。术语保持准确、一致；重要术语首次出现时按需要解释。
- Wiki 是关联知识和技术上下文的来源，博客面向公开阅读。打磨文章时结合现有 Wiki，检查前后章节、术语和链接；不要默认已有内容一定正确。
- 按用户指定的范围和顺序逐篇打磨。已有内容可以逐步完善，不要求一次性改写整套 Wiki。

## 2. 技术内容与资料

1. 先梳理文章所在章节、相关概念及已有链接，再确定本文要解决的问题和阅读边界。跨章节内容优先链接到已有解释，避免无必要的重复。
2. 编写或实质性打磨技术内容时，结合 Wiki 上下文和联网检索核查关键事实。优先使用规范、器件厂商资料、官方文档和原始论文等一手来源；根据主题选择读者易于访问的资料。
3. 对重要事实、数据和外部观点提供可追溯的来源。核对来源的适用对象、版本、时间与条件，不把某一器件或实现的参数当作普遍规律。资料无法核实时，明确说明，不编造引用或数字。
4. 区分事实、假设、推论、建议和待验证结论。明确公式、模型和示例的前提、单位、观察边界及必要的边界条件；构造案例和理想估算不能写成实测结果。
5. 解释机制时，按需要说明输入、输出、状态、职责和执行过程。先说明约束和因果关系，再用合适的例子、公式、结构图或反例帮助理解。涉及不同方案时，说明适用条件、收益和代价。
6. 避免没有依据的绝对判断，例如“总是”“一定更快”或“最难”。类比只用于帮助理解；回到技术问题时，要说明类比的边界。

网页样式或导航等纯界面修改，不必为了满足本规则而强行增加技术内容或外部引用。

## 3. 文章组织与导航

- 正文优先回答一个清楚的问题。根据内容选择结构，不要求所有文章套用同一模板；解释应有足够细节，不用堆砌术语或列表代替推导。
- “接下来怎么读”等章节入口应与目标文章及侧边导航的名称对应。章节按顺序阅读时，正文列表与导航顺序保持一致；跨章节推荐可以按阅读目的组织，并说明选择理由。
- 具体文章应能在侧边导航中找到对应项，并有清晰的当前页面高亮。选中状态不应改变导航项的缩进或使相邻文字跳动。
- 文章标题前提供面包屑，反映实际层级；有目标页的上级可点击，当前页面可识别。导航和上级面包屑可以使用易识别的短名称，正文和当前页面面包屑可以保留完整标题；两者应清楚对应，悬停时可查看完整标题。
- 修改标题、路径或章节结构时，同步检查相关链接和导航。尽可能保留已有 URL 与锚点；确需变化时，为旧链接提供合理的兼容方式。

## 4. 视觉、图解与交互

- 保持正文、表格、公式、说明块和图形与网站整体风格协调，并保证文字对比度。避免出现与页面背景突兀割裂的大块纯白区域。
- 公式、事件路径和说明不是代码时，使用适合阅读的样式；真实代码仍应保留代码格式。布局应便于长文阅读，并适配桌面和手机。
- 图形应帮助理解关键结构、因果或过程，而不是仅作装饰。根据内容决定是否加入结构图、分步演示或动画；不要求每篇文章都使用动画。
- 图解的状态变化、方向和文字必须与正文一致。明确图中省略的条件，以及它是教学示意、模型结果还是实际测量；不要把动画当作电路仿真或性能证明。
- 图解应有可读的文字说明，并按需要支持键盘操作、减少动态效果和窄屏阅读。独立图解入口是否突出展示，取决于实际内容质量和用户意愿。

## 5. 网站结构与公开访问

- 当前微架构内容只是技术笔记中的一个系列。站点结构应允许未来增加其他系列；不要预先固定尚未确定的系列名称，也不要创建空栏目冒充已有内容。
- 优先保持系列配置和页面结构易于扩展。新增系列的实际名称、内容和发布方式由届时需求决定。
- 博客面向所有读者公开访问。经用户授权发布时，除本地预览外，还要检查构建、部署和公开地址上的实际结果；本地可访问不等于已经公开。

## 6. 验证与维护

- 内容修改后，按改动范围检查术语、数字与公式、前提条件、引用来源以及相关 Wiki 链接。不要把尚未验证的推断写成事实。
- 涉及网站时，检查文章标题、导航高亮、面包屑、阅读顺序、图文排版及适用的桌面和手机视图。改动交互时，检查相关状态与操作方式。
- 使用 [网站构建与维护](../website/README.md)中的构建和检查方法。只运行与修改相称的验证；生成目录不是正文维护位置。
- 新增独立博客仓库时，在该仓库的协作说明中显式引用或同步本规则；本仓库的 `AGENTS.md` 不会自动约束其他仓库。
