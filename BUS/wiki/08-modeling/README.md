这一章把前面各章页脚分散的"建模启示"收敛成一份可直接编码的参考，面向"用 BUS 知识做架构探索 / 系统建模工具"的读者，而不是第一次学概念的读者。

## 本章包含什么

## 本章主线

前面 01–07 章建立的是概念与工程判断：transaction 生命周期、仲裁 / 顺序 / 回压、协议族、系统路径、性能调试、检查清单。第 08 章回答的是另一个问题：**当这些知识要变成一个可仿真的模型时，应该保留什么、折叠什么、怎么校准。**

主线是五个决策：

1. 用哪条统一 transaction 状态机（`request_accept` 与 `completion_visible` 必须分开）
2. 选哪一层保真度（容量估算 / 近似时序 AT / 周期精确）
3. 每个组件带哪些参数（master / arbiter / bridge / slave / 拓扑 / DDR 边界）
4. 用哪些公式定容量（Little's Law / bandwidth-delay product / 服务时间模型）
5. 怎样映射到 SystemC TLM-2.0 / gem5，以及怎样分步校准

## 建模启示

如果一个 BUS 性能问题在模型里复现不出来，先按这章的"五张图"自查漏建了哪一张（地址 / 仲裁 / 数据 / 响应 / 顺序），再去怀疑参数系数。把一次访问压成单事件、或只给链路一个 aggregate 带宽，是最常见也最致命的两类简化。
