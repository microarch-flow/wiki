# 带宽、延迟、利用率与拥塞

上级：[05 性能与调试](./README.md)

相关：[位宽、时钟、Burst 与延迟](../02-fundamentals/width-clock-burst-latency.md)

## 这页在回答什么问题

分析 BUS 性能时，最应该盯哪些指标，而不是只看“跑满没跑满”。

## 四个核心指标

### 1. 带宽

看总吞吐和各 master / slave 吞吐分布。

### 2. 延迟

至少区分：

- request 被接受前等待多久
- 从发起到完成多久
- 平均值和尾延迟是否分离

### 3. 利用率

要分清：

- link busy 是因为有效载荷多
- 还是因为长 burst、回压和仲裁造成占路

### 4. 拥塞

拥塞不是一个点，而是一条链：

- 哪个 slave 最先忙
- 哪个 FIFO 先满
- 哪个 master 最先被反压

## 常见误区

- “利用率高说明设计优秀”
- “平均延迟正常就没问题”
- “总带宽够就不会 stall”

## 一句话理解

BUS 性能分析要同时看 `吞吐、排队、回压、尾延迟`，否则很容易误把共享拥塞看成局部小问题。
