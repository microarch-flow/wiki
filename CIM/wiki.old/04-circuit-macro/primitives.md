# 基础电路对象

## 为什么必须先统一这些术语

CIM 论文里很多图看起来差不多，但实际差异往往就藏在 bitcell、位线、读出链路和外围电路里。如果这些基本对象不清楚，后面很容易把“阵列内计算”和“外围做了大部分工作”混为一谈。

## 基础术语与作用

| 术语 | 作用 | 在 CIM 中为什么重要 |
| --- | --- | --- |
| `Bitcell` | 最小存储单元 | 决定是否能让存储与计算共存 |
| `Wordline` | 控制一行单元的激活 | 决定输入如何进入阵列 |
| `Bitline` | 数据读出与累加路径 | 经常是阵列计算真正发生的地方 |
| `Sense Amplifier` | 放大小信号并判决 | 决定读出可靠性，部分方案中紧贴计算路径 |
| `ADC` | 模数转换 | 模拟 / mixed-signal 设计中的关键瓶颈 |
| `DAC` | 数模转换 | 将数字输入送入模拟阵列，可能代价很大 |
| `Accumulator` | 局部或全局累加 | 负责多 bit、多周期和多 tile 的结果整合 |
| `Peripheral Circuit` | 驱动、控制、缓存、转换等外围逻辑 | 很多宏的面积和能耗大头其实在这里 |

## 从论文图里应该优先看什么

读任何一张 macro 图，建议先看四件事：

1. 输入从哪里进，落在 `WL`、`BL` 还是外围寄存器
2. 权重存在哪里，是 bitcell 本身还是额外电路
3. 求和发生在 bitline、电荷域还是数字树上
4. 结果在什么位置被数字化和归约

## 术语之间的典型关系

```text
Input -> Wordline / Driver
      -> Bitcell Array
      -> Bitline Accumulation
      -> SA / ADC
      -> Accumulator / Buffer
      -> Next Tile / Host
```

这个链条越长，越要警惕“虽然叫 CIM，但真正节省的数据搬运可能有限”。
