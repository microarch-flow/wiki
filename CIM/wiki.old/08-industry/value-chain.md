# 产业链结构

## 为什么这一页不能只列环节

如果只是把产业链写成：

- 材料
- Foundry
- 设计
- 封装
- 系统

那么它更像半导体行业通用模板，还不足以解释 `CIM` 为什么会在不同路线下表现出完全不同的产品化难度。

`CIM` 的关键不在于“它也要流片”，而在于：

- 不同路线对工艺兼容性的要求不同
- 不同路线对器件一致性和测试校准的压力不同
- 不同路线对 `memory vendor`、`foundry`、`OSAT` 的依赖强弱不同
- 不同路线的供应链主导权并不在同一个角色手里

因此，这一页的目的不是罗列公司，而是建立一套能判断：

1. 一条路线为什么技术上成立
2. 它为什么工程上可能卡住
3. 它的供应链控制权掌握在谁手里

## 先把 CIM 供应链看成六个层级

### 1. 材料与器件

关注：

- 存储器件本身是什么
- 是否依赖新材料或特殊器件行为
- 器件一致性、漂移、写入窗口是否可控

这一层对 `ReRAM / Flash / PCM / MRAM` 路线尤其关键。

### 2. 工艺与制造

关注：

- 是否能兼容标准 `CMOS`
- 是否需要额外工艺步骤
- 是否依赖特定 `foundry` 或 memory fab 能力
- 良率和器件一致性问题是否会被放大

### 3. 设计与 EDA / IP

关注：

- 阵列、电路、controller、NoC、interface 是否有成熟设计路径
- 是否有现成 `IP` 可复用
- 模拟 / mixed-signal 设计复杂度有多高

### 4. 封装与集成

关注：

- 是普通 SoC 封装，还是先进封装
- 是否涉及 `HBM`、2.5D、stacking、module 级集成
- host、memory、accelerator 如何连成系统

### 5. 测试、校准与量产验证

关注：

- 测试只是数字功能测试，还是还要做模拟校准
- 漂移、温度、老化是否需要额外验证
- 量产测试时间和成本是否过高

### 6. 系统与客户导入

关注：

- 卖的是 `macro`、`chip`、`card`、`module` 还是 `system`
- 是否容易接入现有主板、主机和软件栈
- 客户导入周期会不会被验证成本拖长

## 四类路线的供应链差异

## 1. SRAM-CIM

### 这条路线的核心特点

`SRAM-CIM` 最接近标准数字芯片产业链。

它的关键优势不是理论阵列最强，而是：

- 更兼容标准 `CMOS`
- 更容易放进现有 `SoC / MCU / NPU`
- 更容易沿用传统 `fabless -> foundry -> OSAT -> customer` 路径

### 供应链依赖结构

- 材料与器件：弱依赖新型器件
- 工艺与制造：强依赖标准逻辑工艺
- EDA / IP：可较多复用数字设计流程
- 封装：通常不要求最激进封装
- 测试：相对更接近传统数字芯片验证

### 谁掌握主导权

主导权更容易在：

- `fabless chip startup`
- `SoC` 厂商
- 具备片上集成能力的系统公司

而不是器件厂或 memory vendor。

### 主要卡点

- 片上面积成本
- 容量有限
- 宏收益是否能在系统中保留下来
- 软件与模型映射是否足够自动化

### 更像什么商业路径

更像：

- 片上加速宏
- Edge AI SoC
- MCU / low-power inference chip

### 这条路线为什么更容易先落地

因为它最少依赖“供应链新增能力”，更多是在已有 `CMOS` 产业链中做架构和电路创新。

## 2. ReRAM-CIM

### 这条路线的核心特点

`ReRAM-CIM` 最接近“阵列原生存内矩阵乘”的理想图景，但它的供应链难点也最集中。

它难的不是画出 crossbar，而是把：

- 器件一致性
- 写入可控性
- 漂移
- 良率
- 校准

一起做成可量产体系。

### 供应链依赖结构

- 材料与器件：强依赖新型非易失器件能力
- 工艺与制造：可能需要额外工艺步骤或特殊集成
- EDA / IP：模拟 / mixed-signal 与阵列建模负担更重
- 封装：未必最难，但系统集成会受测试和校准影响
- 测试：通常比数字路线复杂得多

### 谁掌握主导权

主导权往往不完全在设计公司手里，而取决于：

- 器件平台掌握者
- 可支持该器件路线的制造伙伴
- 是否有能力长期做硅后校准和建模

如果 startup 自己不掌握器件和制造协同，路线会很脆弱。

### 主要卡点

- 器件一致性
- 写入 / verify 成本
- 漂移与 retention
- 大阵列误差累积
- 量产测试复杂度
- 客户对精度稳定性的信任门槛

### 更像什么商业路径

更像：

- 固定权重 edge inference
- 特定低功耗模块
- 长期研究转产品的高风险路线

### 为什么它最容易出现“论文强、产品弱”

因为论文可以先证明：

- 局部阵列能算
- MVM 能成立

但产品必须再证明：

- 长期稳定
- 可重复制造
- 可测试
- 可交付给客户

这些门槛很多都在供应链和制造体系，而不在论文图里。

## 3. DRAM / HBM-PIM

### 这条路线的核心特点

`DRAM / HBM-PIM` 的价值主要来自 memory-side processing，而不是单看阵列级模拟乘加。

因此它更像：

- memory product 的能力扩展
- memory system 的架构升级
- 与主处理器协同的近存计算方案

### 供应链依赖结构

- 材料与器件：依赖成熟 DRAM / HBM 体系
- 工艺与制造：强依赖 memory vendor 的制造能力
- EDA / IP：依赖 memory interface、controller、stack integration 能力
- 封装：先进封装和高带宽内存集成能力非常关键
- 测试：既要测 memory，又要测 processing logic 和系统协同

### 谁掌握主导权

主导权通常更集中在：

- `memory vendor`
- 掌握 `HBM / GDDR` 路线的原厂
- 能控制 memory stack、逻辑层和接口定义的厂商

这不是普通 `fabless startup` 容易主导的链条。

### 主要卡点

- 是否能真正修改 memory product 路线
- host、controller、runtime 如何协同
- 先进封装成本
- 系统接口兼容性
- 收益是否真来自 memory-bound workload

### 更像什么商业路径

更像：

- memory vendor 向 AI 基础设施延伸
- module / card / solution 级产品
- 针对 `KV cache`、long context、HPC memory-bound workload 的系统路线

### 为什么这条路线更偏大厂主导

因为它依赖的不是单点芯片设计，而是：

- memory 制造
- 高带宽封装
- 系统接口
- 生态控制力

这些天然更靠近 `Samsung`、`SK hynix` 这类角色。

## 4. Flash / PCM / MRAM-CIM

### 这条路线的核心特点

这类路线通常介于 `SRAM-CIM` 和 `ReRAM-CIM` 之间：

- 比标准 `SRAM` 更依赖器件特性
- 又不一定像 `HBM-PIM` 那样由 memory vendor 完全主导

不同介质之间差异很大，但共同点是：

- 需要认真评估器件成熟度
- 需要看工艺兼容性
- 需要看待机功耗、写入成本、可靠性

### 供应链依赖结构

- 材料与器件：中到强依赖特定器件平台
- 工艺与制造：取决于是否已有成熟量产路径
- EDA / IP：通常需要同时理解器件和电路
- 测试：比纯数字路线更重

### 主要卡点

- 工艺成熟度是否足够
- 量产一致性
- 写入、擦写、保持特性
- 客户是否接受该路线的边界条件

## 一张实用的对比表

| 路线 | 供应链主导者 | 工艺兼容性 | 封装依赖 | 测试校准压力 | 更典型的商业起点 |
| --- | --- | --- | --- | --- | --- |
| SRAM-CIM | SoC / fabless / system company | 高 | 中低 | 中低 | Edge SoC / 片上宏 |
| ReRAM-CIM | 器件 + 制造协同方 | 低到中 | 中 | 高 | 固定模型低功耗推理 |
| DRAM / HBM-PIM | memory vendor | 中 | 高 | 中高 | memory-side module / card |
| Flash / PCM / MRAM-CIM | 取决于介质路线 | 中 | 中 | 中高 | 特定低功耗或嵌入式场景 |

## 哪些环节最容易成为真正卡点

## 1. 工艺兼容性

技术上能做，不代表能进入成熟制造流程。

要继续问：

- 是否兼容主流逻辑工艺
- 是否需要新增掩膜或额外步骤
- 是否会拉低良率

## 2. 测试与校准

很多路线死在这里，而不是死在原理。

要继续问：

- 测试只是功能测试，还是还要做模拟校准
- 校准是一劳永逸，还是运行中还要持续补偿
- 量产测试时间是否会把成本拉高

## 3. 封装与系统集成

尤其是 `HBM-PIM / AiM` 路线，要看：

- 是芯片问题还是系统问题
- 是否依赖先进封装
- 是否要改板卡和 host 接口

## 4. 软件与客户导入

供应链不只是制造链，还包括交付链。

要继续问：

- 客户是否要改软件栈
- 客户是否要接受新的调试和验证方式
- 认证周期是否过长

## 看公司时要先判断谁在控制链条

### Startup 主导路线

通常要问：

- 它是否只掌握芯片设计
- 它是否过度依赖单一制造伙伴
- 它是否缺少器件、测试或系统验证能力

### Memory vendor 主导路线

通常要问：

- 它是在扩展 memory 产品，还是在进入新的系统市场
- 系统价值是否足够大，值得改 memory 产品路线
- 是卖 memory component，还是卖 solution

### System company 主导路线

通常要问：

- 它是否只把 CIM 当成局部功耗优化手段
- 是否真正掌握软件、系统和客户入口

## 用几个案例快速建立直觉

### TSMC 16nm CIM macro

更适合用来理解：

- `CMOS-compatible` 路线为什么工程友好
- 为什么标准逻辑工艺兼容性很重要

### Mythic

更适合用来理解：

- startup 做 `analog CIM` 时最吸引人的叙事是什么
- 为什么供应链与量产验证能力会成为真正门槛

### Samsung HBM-PIM

更适合用来理解：

- 为什么 `HBM-PIM` 天然更像 memory vendor 的路线
- 为什么其价值更偏 system-level，而不是阵列级指标

### SK hynix AiM / AiMX

更适合用来理解：

- memory vendor 如何从器件走向 card / solution
- 供应链控制力如何转化成产品化姿态

## 做投资或尽调时建议直接追问

1. 这条路线最依赖的供应链节点是什么？
2. 它的主导权掌握在设计方、制造方还是 memory vendor 手里？
3. 它最难的环节是工艺、校准、封装、软件还是客户验证？
4. 它卖的是芯片、模组、卡还是系统？
5. 如果客户要导入，最先要改的是软件、主板、内存系统还是验证流程？

## 一个最实用的判断原则

如果一条路线：

- 技术叙事很强
- 指标主要停留在 `macro-level`
- 对工艺、测试、封装、软件和客户导入说得很少

那么它大概率还只是技术路线，不是成熟产品路线。

反过来，如果一条路线已经能清楚回答：

- 谁制造
- 谁封装
- 谁测试
- 谁集成
- 谁购买

那么它才更接近真正可落地的产业路径。
