# 实验室、合规与互通测试怎样分工？

上级：[设计与验证](./README.md)

实验室测量、指定标准的合规测试和真实对端互通测试回答不同问题。应先确定被测对象、参考面与判据，再选择仪器和测试程序。

## 一次接收端测试要记录什么？

1. **前提**：明确协议版本、速率、码型、参考时钟、温度、电压、TX / RX 与 FEC 配置，确认待测设备已按测试方法进入指定状态。
2. **激励**：按适用测试规范校准输入信号及其压力条件。BERT 可以发送指定码型，并与接收结果或设备报告的错误信息配合检查；不同测试的误码观察点可能不同。
3. **测量**：记录测试时间、实际检查比特数、错误计数、失锁 / 重启区间，以及夹具、线缆、探头和去嵌模型。去嵌将经表征的夹具影响按模型扣除，不会消除所有仪器不确定度。[Keysight：夹具去嵌](https://www.keysight.com/my/en/use-cases/de-embed-high-speed-test-fixtures.html)
4. **判断**：按指定判据报告通过或失败；对零错误结果说明统计假设和置信度。预期结果应能由保存的记录重新检查。

例如，在独立、固定误码概率的模型下，`3 × 10^12` 个已检查比特中零错误，对应约 `10^−12` 的单侧 `95%` 置信上界。它不是“误码概率为零”，也不覆盖未测环境。完整推导见 [BER、置信度与 FEC](../05-signaling-and-metrics/ber-confidence-and-fec.md)。

## 各种“通过”各证明什么？

| 证据 | 可以支持的结论 | 单独不能支持 |
| --- | --- | --- |
| 内部样片测量 | 所测样片在记录条件下的观察结果 | 所有批次、对端或长期可靠性 |
| 某项电气合规测试 | 被测对象在指定版本、项目和测试条件下达到该项目判据 | 完整协议测试或所有系统互通 |
| 指定对端互通 | 所测设备组合、配置和环境下能够互操作 | 对所有对端、版本和环境都互通 |
| 生产与可靠性数据 | 对规定抽样、筛选与使用条件的统计证据 | 未覆盖的工作条件或无限寿命 |

[PCI-SIG 合规项目](https://pcisig.com/developers/compliance-program)列出电气、配置、链路和事务等测试，并区分合规与互通测试。完整项目的要求以对应版本和计划为准；不能把其中一项 TX / RX 电气通过直接写成“整个系统已互通”。
