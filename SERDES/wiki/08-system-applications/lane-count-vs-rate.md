# 增加 lane 还是提高单 lane 速率？

上级：[系统应用](./README.md)

总线路容量可由 lane 数与每 lane 速率共同决定。提高单 lane 速率可以减少达到目标容量所需的 lane 数，但也可能增加对通道、时钟、均衡和测试的要求。更多 lane 则需要考虑引脚、封装走线、对齐、共享资源和面积。

## 一个相同总线速的例子

假设以下都是单方向 NRZ 链路，所有 lane 连续工作，使用相同的 `8b/10b` 编码；没有其他开销。数字只是教学输入。

| 项目 | 方案 A | 方案 B |
| --- | --- | --- |
| lane 数 × 单 lane 线速率 | `4 × 10 Gb/s` | `2 × 20 Gb/s` |
| 总线路速率 | `40 Gb/s` | `40 Gb/s` |
| 仅扣编码后的数据上限 | `32 Gb/s` | `32 Gb/s` |
| 单 lane UI | `100 ps` | `50 ps` |
| 符号率一半的参考频点 | `5 GHz` | `10 GHz` |

两个参考频点用于比较频率范围，不是信号的硬截止频率。不能仅凭频点或走线长度计算 BER；需要看相应频段的完整通道响应、噪声和收发器。

## 功耗比较也需要条件

再假设指定功耗边界内，共享电路两方案都为 `10 mW`；A 每 lane `20 mW`，B 每 lane `45 mW`。则总功率分别为 `90 mW` 和 `100 mW`。在上表 `32 Gb/s` 数据速率下，分别约为 `2.81` 和 `3.13 pJ/数据 bit`。

这些数值不是器件规格。换一组每 lane、共享电路或空闲功耗，排序可以改变。空闲、训练、FEC 和重传若未包含在分母或功耗中，也要另行说明。比较封装时，还要计入电源 / 接地、时钟、边带和冗余连接，不能直接把 lane 数当成完整引脚数。

多 lane 还可能需要字边界恢复与跨 lane deskew；单 lane 提速则可能缩小时间和电压判决余量。两者最终应在同一通道、温度、电源、吞吐和可用性目标下比较。相关公式见[带宽和能耗](../05-signaling-and-metrics/bandwidth-power-efficiency.md)，多 lane 机制见 [lane 对齐](../06-link-operation/lane-alignment.md)。
