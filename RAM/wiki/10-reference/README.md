# 参考资料

相关：[学习路径与各章节依赖关系](../01-overview/learning-roadmap.md), [MC 在 cycle-level 仿真里的建模方法](../06-memory-controller/mc-modeling-for-simulation.md)

## 这页在回答什么问题

这一章提供高频查阅材料，包括第一性原理、术语、速查表、checklist 和建模模板。

## 正文

前面九章的任务，是把 RAM 从器件、阵列、协议、控制器、系统、封装一路讲到 AI 芯片的数据流视角。到这里，主线知识已经基本闭合。最后这一章不再引入新的大叙事，而是把前面的结果压缩成一组方便反复查阅、复用和落地的工具。换句话说，这一章不是新的知识线，而是前面整套知识的 `reference layer`。

之所以需要这一层，是因为存储器问题很容易在两个极端之间摇摆。一种极端是只记住零碎术语和参数表，最后不知道为什么这些东西重要。另一种极端是只记住宏观叙事，真正做建模、排障或设计比较时又拿不出足够具体的清单和模板。前面各章已经尽量避免落到第一个极端；这一章要避免的是第二个极端。它的价值不在“再讲一遍”，而在“把前面的判断压成可拿来直接用的形式”。

所以，这一章里的页面大致分成四类。第一类是 `first-principles`，也就是最不容易过时的底层判断，比如为什么 SRAM 和 DRAM 会走向不同路线、为什么带宽和延迟天然冲突、为什么很多 AI 优化本质是在减少跨层移动。它们适合在你一时被细节淹没时，快速把判断拉回正确坐标。第二类是 `glossary` 和 `high-frequency-questions`，负责清理术语边界和高频误解，防止把不同层面的词混在一起比较。第三类是 `cheatsheet / checklist`，例如 timing 参数速查、SRAM 设计检查项、DRAM 排障检查项。这些页面不是讲新原理，而是把前面分散的注意点收成实际工程上的检查顺序。第四类是 `memory-modeling-template`，它会把前面多章里反复出现的“资源、状态、事件、约束、统计量”收成一个统一模板，方便做架构探索。

这四类东西虽然形式不同，但目的很一致：把“理解过”变成“可复用”。你会发现，真正难的常常不是第一次看懂一个概念，而是在几周后、换了一个问题场景时，能不能迅速知道该从哪里重新切入。参考资料层就是在为这种重复使用服务。

从阅读顺序上说，这一章并不要求线性读完。如果你已经完整读过前面内容，那么最值得优先看的通常是 `memory-modeling-template.md`，因为它能把前面零散的建模启示统一起来；其次是与你当前任务直接相关的 checklist 或 cheatsheet，例如做 DRAM 仿真时优先看 `dram-debug-checklist.md`，做片上 SRAM 组织评估时优先看 `sram-design-checklist.md`。如果你是中途回来查概念边界，`glossary.md` 和 `high-frequency-questions.md` 会更高效。

从用途边界上说，这一章也有一个明确限制：它不会替代正文。比如 `timing-parameter-cheatsheet.md` 可以帮你快速回忆 `tRCD / tRP / tRAS` 分别在等什么，但它不会取代 `05-dram-protocol-families/timing-parameters-trcd-trp-tras.md` 对物理原因的解释；`sram-design-checklist.md` 可以帮你检查端口、banking、Vmin 和 leakage 是否都想到了，但它不会替代 `02-sram-foundations/*` 对这些约束为什么会出现的展开。也就是说，这一章提供的是压缩后的入口，不是跳过前文的捷径。

如果用更抽象的话说，这一章是在把前面多层内容重新映射成三类可操作对象：

- `判断规则`
- `检查清单`
- `建模模板`

前两类帮你在分析和讨论时少走弯路，后一类帮你在真正动手做架构探索时，不会把关键状态漏掉。尤其对存储器这类跨层问题，漏掉一个关键状态变量，常常比公式略粗糙更危险。

因此，读这一章时最好的心态不是“再学一遍”，而是把它当成你之后反复折返使用的工具箱。前面各章建立的是脑中的地图，这一章提供的是地图旁边那套尺子、坐标系和检查表。

这一章不要求严格线性读完，但如果你想先建立一个最稳的参考层入口，建议按下面顺序：

- 准备正式搭 memory model：优先看 1、6、7

## 一句话理解

这一章不是新的知识线，而是把前面 RAM 全链路内容压缩成可重复使用的判断规则、检查清单和建模模板。

## 建模启示

如果把整套 wiki 当成一个可复用的方法库，那么这一章最重要的作用是把散落在各页的建模启示标准化。也就是说，后面做任何 memory-related 模型时，都可以先到这里拿一个统一问题框架，再决定哪些细节要展开。

一个最小的“参考层”使用顺序可以是：

```text
1. 先用 first-principles 确认问题属于哪一层
2. 再用 glossary / FAQ 校正术语边界
3. 用 checklist 找出容易漏的状态或约束
4. 用 modeling template 把问题正式写成资源/状态/事件模型
```

如果一个模型还没开始写，你就已经能用这四步把问题压缩清楚，后面的实现通常会稳很多。后续各页就是围绕这套顺序展开的。
