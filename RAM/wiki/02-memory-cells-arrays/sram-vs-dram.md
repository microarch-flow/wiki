# SRAM vs DRAM 对照

## 为什么必须先分清这两类

很多关于“内存”的讨论其实跨了两个层次：

- SRAM：片上缓存和本地工作集
- DRAM：片外大容量主存和高带宽外部内存

如果不先分清楚，后面谈 DDR、HBM、cache、带宽和延迟时会不断混层。

## 核心对照表

| 维度 | SRAM | DRAM |
| --- | --- | --- |
| 基本单元 | 典型 6T | 典型 1T1C |
| 是否刷新 | 不需要 | 需要 |
| 访问模式 | 直接按地址访问 | 先开行，再按列访问 |
| 延迟特征 | 更低、更确定 | 更高，且依赖 row hit/miss |
| 单 bit 面积 | 大 | 小 |
| 容量扩展性 | 差 | 好 |
| 成本 | 高 | 低 |
| 典型位置 | L1/L2/L3、scratchpad | DDR、LPDDR、GDDR、HBM |

## 第一性差异

### 差异 1：用什么保存数据

- SRAM：用晶体管状态保持
- DRAM：用电容电荷保持

这直接决定了是否需要刷新，以及单位面积能放下多少 bit。

### 差异 2：怎么访问数据

- SRAM：更接近“直接点取”
- DRAM：更接近“先打开一整行，再从行里取一段”

所以 DRAM 的协议、时序、控制器复杂度都高得多。

### 差异 3：更适合扮演什么系统角色

- SRAM：更适合供给核心计算的低延迟热数据
- DRAM：更适合承载大容量数据集和高总容量需求

## 工程判断

当你看到一个系统中的内存选择时，可以先问：

- 这里更缺的是延迟，还是总容量
- 这里更缺的是片上面积，还是片外带宽
- 数据是否具有强局部性，值得花面积做 SRAM

很多架构取舍，本质上都来自这三问。

## 一句话理解

`SRAM 负责快，DRAM 负责大；系统设计的核心，是把“少量快存储”和“大量慢存储”组合成一个能服务 workload 的层级结构。`
