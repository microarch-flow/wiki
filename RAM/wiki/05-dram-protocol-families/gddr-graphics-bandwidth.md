# GDDR：为带宽放弃了什么

上级：[DRAM 协议层](./README.md)
相关：[HBM：从协议层面看它和 DDR 的根本不同](./hbm-stacked-wide-io.md), [DDR、LPDDR、GDDR、HBM：四种 DRAM 协议的 trade-off 全景图](./ddr-lpddr-gddr-hbm-tradeoff-map.md)

## 这页在回答什么问题

GDDR 为什么会成为独立 GPU 和很多高带宽加速卡的主流外存路线。更准确地说，它为了把单 pin 速率和总带宽推高，主动放弃了哪些功耗、距离、封装和系统通用性边界。

## 正文

如果把 LPDDR 看成“为了功耗和移动集成重排 trade-off”的路线，那么 GDDR 可以看成另一种非常鲜明的选择：为了尽可能榨高外部带宽，尤其是单位引脚上的传输能力，愿意在功耗、信号完整性和系统边界上付出更激进的代价。它依然站在 DRAM 的物理基础上，也仍然要面对 refresh、row buffer、prefetch、burst 这些底层约束；但它不再像通用 DDR 那样优先考虑容量扩展和生态通用性，也不像 LPDDR 那样优先压低待机与 I/O 能耗，而是把重心明确押在图形渲染、GPU 访存和高吞吐并行负载所需要的总带宽上。

先看为什么 GPU 会特别需要这条路线。GPU 及类似图形/并行加速器的典型特点，是计算单元数量多、并发线程多、吞吐导向强，且很多访问流虽然不一定有优秀的 CPU 式缓存局部性，却对总带宽极度敏感。也就是说，它们常常更怕“喂不饱”，而不是更怕“单次延迟稍高”。在这种系统里，如果外存接口不能持续提供很高的数据吞吐，再强的 shader array、SIMT 阵列或向量算力都可能变成空转。因此，GDDR 的设计逻辑就是：在还能维持板级独立显存形态的前提下，尽量把外部 DRAM 接口的带宽顶上去。

它的第一类主动选择，是更激进地追求 `单 pin 速率`。相比通用 DDR 和尤其是 LPDDR，GDDR 更愿意接受更高的 I/O 活动、更紧的信号和训练要求、更苛刻的布线与封装设计，以换取每条数据线更高的实际传输能力。这样做的好处很直接：在总线位宽有限、封装仍要维持独立显存芯片布局时，你可以靠更高的 pin rate 获得很高总带宽。坏处也同样直接：I/O 动态功耗显著增加，信号完整性压力更重，对板级走线、封装、终端设计和时钟训练的要求更高。

第二类放弃是 `低功耗优先级`。GDDR 并不是完全不在乎功耗，但它显然不像 LPDDR 那样把待机、轻载和深度省电状态放在设计中心。独立 GPU、显卡和高性能加速器更常面对的是“满载长时间工作”的场景，而不是“多数时间待机、偶尔短突发”。在这种工作负载画像下，工程上更愿意为持续带宽付功耗，而不是为待机省电牺牲峰值吞吐。常见误解是把 GDDR 理解成“功耗更高的 DDR”；更准确的说法是，它有意识地把功耗预算重新分配给高带宽持续输出。

第三类放弃是 `更温和的板级与封装边界`。GDDR 仍然保持外置显存芯片路线，这让它比 HBM 更容易沿用相对熟悉的板级独立封装模式，但代价是你必须在较长电气距离上跑极高数据率。这与 HBM 的“靠极短近距互连换带宽”完全不同。GDDR 选择的是：继续接受离计算 die 有一定距离的外部显存布局，但把这段距离上的接口设计做到更激进。换句话说，它没有放弃独立显存的系统形态，却因此要在高速串扰、功耗和布线上承担更多成本。

这里的关键 trade-off 可以概括成一句话：GDDR 更像是在“现有板级外存范式里把速度压榨到很高”，而不是重写整个内存-计算关系。也正因为如此，它特别适合独立 GPU 这类系统：GPU die 可以留在自己相对熟悉的封装与板卡生态里，显存芯片围在周边，通过高 pin-rate 接口拉起很高带宽，而不必立即走向 HBM 那种更深度的堆叠与先进封装耦合。

但这条路的天花板也很清楚。因为它本质上仍在长于片上互连、长于 HBM 近距互连的板级距离上工作。你可以不断提升接口训练、调制、通道质量和每 pin 数据率，但每往上推一步，功耗、热和 SI 成本都会明显增加。也就是说，GDDR 能把板级外存路线推得很远，但它并不能消灭“长距离高速 I/O 很贵”这个物理事实。这正是它与 HBM 最终分流的根因：一个选择继续在较长距离上压 pin rate，另一个选择缩短距离、扩大位宽、降低每 pin 压力。

从协议层看，GDDR 的“更快”也不是孤立发生的。它同样依赖更深的 prefetch、burst、bank 并行组织以及与高数据率配套的训练和时序约束。也就是说，GDDR 并不是在推翻 DDR 家族前面建立的逻辑，而是在那套逻辑上，把 `I/O-side aggressiveness` 这一维推得更远。它仍然需要 core/I/O 桥接，只是桥的外侧跑得更快、更热、更难。

对系统架构师来说，GDDR 最值得抓住的不是规格书上的峰值带宽，而是它的适用边界。它适合那些：

- 需要很高持续带宽
- 能接受外置显存及相关板级功耗
- 不愿意承担 HBM 级别封装成本和复杂度
- 愿意让功耗和散热为带宽买单

这也是为什么 GDDR 在独立 GPU 上长期很成功，但在手机和超低功耗终端上并不合适，在极端高带宽密度的 AI/HPC 场景里又会逐渐遇到 HBM 的竞争。它不是“中间态”，而是一条对自己的系统假设非常明确的路线。

还有一个常见误解需要收紧：GDDR 不只是“比 DDR 更高频”的同类物。更高频当然是结果之一，但更本质的是它接受了不同的系统边界。普通 DDR 更在意主存通用性与容量生态，LPDDR 更在意功耗和近封装集成，GDDR 更在意在外置显存形态下榨高带宽，HBM 则更进一步改变互连距离和封装结构。只看频率差异，会把这些路线真正押注的变量全都抹平。

所以，理解 GDDR 的关键不在于记住某一代 GDDR6 或 GDDR7 的速率数字，而在于看清它是在说：“如果我还想保留独立显存与较长板级互连这套系统形态，那我就愿意为更高 pin-rate 和总带宽付出更高的 I/O 功耗、训练复杂度和信号完整性代价。”只要这一点立住，GDDR 和 LPDDR、HBM 的边界就会非常清楚。

## 一句话理解

GDDR 的本质，是在保留外置显存和较长板级互连前提下，通过更激进的高 pin-rate 接口把带宽顶上去，因此它用功耗、热和信号完整性成本为持续高带宽买单。

## 建模启示

在模型里，GDDR 不能只被抽成“峰值带宽更高的 DDR”。更稳妥的做法是把它建成 `high-io-rate / high-io-energy` 路线，也就是显式保留更高的 I/O 吞吐能力，同时也保留更高的每 bit 接口能耗和更强的持续满载倾向。

一个够用的参数化草图可以是：

```text
GddrModel {
  peak_bw_GBps: float
  io_rate_mtps: int
  io_energy_per_bit_pJ: float
  sustained_bw_efficiency: float
  board_signal_integrity_complexity_norm: float
  package_distance: enum { OFF_DIE_BOARD_LEVEL }
}
```

如果只关心吞吐上限，`peak_bw_GBps` 和 `sustained_bw_efficiency` 可能已经够用；但只要你要做系统功耗、散热或路线选型比较，`io_energy_per_bit_pJ` 和 `board_signal_integrity_complexity_norm` 就不应该省。因为 GDDR 的真正代价，不是“协议更复杂一点”，而是高带宽在较长互连距离上的实现成本。

一个实用的比较框架可以写成：

```text
route_value = f(peak_bw, sustained_bw, io_energy, packaging_cost)
```

这里 GDDR 通常会在 `peak_bw / sustained_bw` 上表现强，但在 `io_energy` 和更高带宽继续扩展时的 `packaging_cost / SI pressure` 上逐渐承压。这正是它与 HBM 分流时最值得建模的地方。
