# DDR1 到 DDR5：每一代的核心改变是什么

上级：[DRAM 协议层](./README.md)
相关：[DDR：为什么要在时钟两边都传数据](./why-double-data-rate.md), [DDR、LPDDR、GDDR、HBM：四种 DRAM 协议的 trade-off 全景图](./ddr-lpddr-gddr-hbm-tradeoff-map.md)

## 这页在回答什么问题

DDR 代际升级到底升级了什么。更准确地说，DDR1 到 DDR5 的演化并不是“频率和带宽越来越高”这么一句话，而是每一代都在回答同一个问题：当核心阵列、I/O、bank 并行和功耗边界继续被推紧时，协议还可以在哪一层补新的桥接机制。

## 正文

很多代际对比文档喜欢把 DDR1、DDR2、DDR3、DDR4、DDR5 摆成一张参数表：速率更高、容量更大、电压更低、bank 更多。这种表对查资料有用，但对理解演化逻辑帮助不大。因为它默认所有参数都在同一个方向自然进步，好像“新一代”只是把旧一代整体拉大了一圈。真实情况更像是一场持续的结构补丁工程：每一代都在试图继续提高外部传输能力，同时又不让 core 阵列、信号完整性、功耗和控制复杂度先崩掉。

如果把这条主线压到最简，可以把 DDR 代际演化看成四个不断重复的问题。第一，如何继续提高 I/O transfer rate，而不要求 DRAM core 同步线性提速。第二，如何在更多 bank、更多并行事务下维持可调度性。第三，如何在时序窗口越来越紧时保住信号和采样可靠性。第四，如何把增长中的带宽和容量需求，限制在可接受的功耗预算内。每一代的“核心改变”，其实都是在这四个问题上的新回答。

`DDR1` 的历史意义，在于把“双边沿传输”这件事正式定成主流接口路线。它不是在重新发明 DRAM 阵列，而是在说：既然 SDR 再往上推受到时钟效率限制，那么就在同一时钟周期内做两次 transfer。也就是说，DDR1 的核心不是“比 SDR 更快”这么空，而是建立了后面所有代际都会沿用的基本桥接思路：I/O 速率的提升，先从每周期 transfer 数下手。

到了 `DDR2`，重点开始转向进一步拉开 core 与 I/O 的节奏分工。更深的 prefetch、更高的 I/O 速率和更激进的接口时钟，使它能在不要求核心阵列同步成倍提速的前提下继续拉高外部数据率。这里的真正变化不是某个宣传值，而是“内部较宽较慢、外部较窄较快”的分层变得更明显。换句话说，DDR2 不是单纯把 DDR1 打得更快，而是在更明确地依赖 prefetch 和接口边界逻辑来桥接节奏差。

`DDR3` 的关键意义，则更像是在继续提速的同时，把可实现性和能耗再往前推一截。外部速率继续提升、容量继续增大，意味着训练、时序对齐、电气条件和功耗控制都不能再停留在早期更宽松的水平。你可以把 DDR3 看成这样一个阶段：单靠“边沿更多利用”已经不够，必须让整个 I/O 子系统、供电和时序收敛能力一起升级，才能把带宽继续稳步推高。它并不是改变底层访问模型，而是让原有模型在更紧约束下仍然可用。

`DDR4` 的一个非常关键的变化，是 bank 并行与高频接口之间的关系开始被显式再组织，也就是 bank group 等机制的重要性上升。到了这个阶段，问题已经不只是“单 pin 更快”，而是“更多 bank 并行在高数据率下怎样不把内部资源和时序边界打爆”。这说明 DDR 演化的重心开始部分从“更快的 I/O”转向“怎样结构化地喂饱更快的 I/O”。如果说前几代主要在拉高桥的通行速度，那么 DDR4 开始更认真地重构桥两侧的匝道和并发组织。

到了 `DDR5`，这种趋势进一步加强。你不能再把它简单看成“DDR4 但更高 MT/s”，因为它所面对的系统问题已经变得更复合：更高容量器件、更大 refresh 压力、更细的 bank 并行组织、更重的数据中心功耗约束，以及需要更高有效带宽却又不愿意让控制器完全失控的现实。DDR5 这类代际演化，核心不在于某个单点数字，而在于继续把接口分段、并发分层、时序训练和电源完整性组织做得更细，使高带宽仍能在 commodity DRAM 路线上延续。

从这条线回头看，就会发现一个重要事实：DDR 家族的代际升级，并没有改变 DRAM 的基本物理本质。1T1C 仍然是 1T1C，row buffer 仍然在，refresh 仍然躲不开，bank 仍然是内部并行的关键单位。代际升级真正改变的是“系统如何围绕这些不变的物理约束，继续往外挤带宽和容量空间”。这也是为什么很多绝对时间量级不会像 I/O 数字那样等比例缩小，因为 core 侧的物理过程并没有被神奇抹掉。

这条演化逻辑也解释了一个常见困惑：为什么新一代 DDR 名义带宽提升了，某些真实工作负载的收益却没有按比例增长。答案通常不在“标准没用”，而在新一代带来的收益更多落在 I/O 能力、事务并发和容量上限，而 workload 是否能吃满这些收益，还取决于 row locality、bank 并行、控制器调度、读写切换和 refresh 干扰。也就是说，代际进步扩大的是上限，不是自动兑现的结果。

如果要把 DDR1 到 DDR5 压缩成一条最稳的主线，可以这样看：DDR1 确立双边沿传输，DDR2/3 继续把 core 与 I/O 的解耦拉大，DDR4/5 则越来越多地在高频接口与并行组织之间做结构化管理。这不是严格的“每代只有一个变化”，但它能帮助你抓住演化焦点：前期主要在把 I/O 提上去，后期越来越多在处理“提上去之后怎么不失控”。

还有一个很重要的边界需要守住：这条 DDR 代际线并不意味着“所有内存都会继续沿这条路升级”。当带宽密度、功耗或封装距离成为主矛盾时，系统会开始考虑 GDDR、LPDDR、HBM 这样的分叉路线。也就是说，DDR1 到 DDR5 是通用主存路线内部的持续修补与增强，而不是对所有场景都永远最优的单一路线。后面几篇讲其他家族时，这一点会变得更明显。

因此，本页真正要建立的不是代际记忆表，而是一种读代际的方式：每看到一次“新一代更快”，都先问它是在哪一层补短板。是 I/O 边沿利用更高了，还是 prefetch 更深了，还是 bank 并行组织更细了，还是功耗/训练/接口边界被重做了。只有这样，DDR 代际演化才不会沦为数字升级史。

## 一句话理解

DDR1 到 DDR5 的演化，本质上是在同一套 DRAM 物理约束不变的前提下，不断通过更深的 I/O-core 解耦、更细的并行组织和更复杂的接口管理，把带宽上限继续往外推。

## 建模启示

在模型里，DDR 代际差异不应该只被编码成一个更大的 `MT/s` 数字。更稳妥的做法是把代际拆成几组独立可变参数：`io_transfer_rate`、`prefetch_factor`、`bank_parallelism_shape`、`timing_guard_profile`、`power_efficiency_profile`。这样模型才能表达“为什么外部速率提高了，但某些工作负载收益有限”。

一个够用的参数化草图可以是：

```text
DdrGenerationModel {
  generation: enum { DDR1, DDR2, DDR3, DDR4, DDR5 }
  io_mtps: int
  prefetch_factor: int
  banks_per_rank: int
  bank_groups: int
  burst_length: int
  timing_profile: object
  voltage_profile: object
}
```

如果只做粗粒度峰值带宽估算，`io_mtps` 和 `bus_width_bits` 可能就够了；但只要你要比较有效带宽、controller 调度空间或刷新干扰，`prefetch_factor`、`bank_groups` 和 `timing_profile` 就必须显式存在。因为不同代际的提升并不都落在同一层，模型若只调一个速率旋钮，会把很多真实 trade-off 抹平。

一个很实用的建模原则是：

```text
peak_capability grows mostly with io_mtps
effective_capability depends on io_mtps + bank_parallelism_shape + timing_profile
```

这能防止模型把“代际升级”误解成“请求一律更快”。很多时候，请求个体的基本物理等待并没有同比缩短，真正扩大的只是总线吞吐上限与可并行服务窗口。
