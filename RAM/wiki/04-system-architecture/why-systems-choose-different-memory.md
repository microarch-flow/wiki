# 不同系统为什么选不同内存

上级：[04 系统架构视角](./README.md)

相关：[DRAM 家族对照：DDR / LPDDR / GDDR / HBM](../03-ddr-protocol-families/ddr-lpddr-gddr-hbm-comparison.md)、[带宽 vs 延迟](./bandwidth-vs-latency.md)

## 为什么不存在“一种内存统治所有系统”

因为不同系统最缺的东西不一样：

- 有的最缺容量
- 有的最缺带宽
- 有的最缺续航
- 有的最缺封装空间
- 有的最缺每比特能耗

所以内存路线本质上是系统目标函数的投影。

## CPU 服务器为什么长期以 DDR 为主

CPU 服务器通常更看重：

- 大容量
- 成本可控
- 标准化平台扩展
- 多槽、多通道部署灵活性

因此 DDR 是更稳妥的主存路线。

HBM 当然也会进入某些高端 CPU/加速型平台，但它通常不是替代所有 DDR，而是补高带宽层。

## 手机和轻薄设备为什么偏 LPDDR

移动系统最敏感的是：

- 功耗
- 电池寿命
- 板级面积
- 封装紧凑度

因此 LPDDR 的低功耗和更贴近 SoC 的集成方式会更有吸引力。

## 独立 GPU 为什么长期偏 GDDR

独立 GPU 处在一个很典型的位置：

- 需要高带宽
- 可以接受较高板级功耗
- 有空间在 GPU 周围铺设多颗显存
- 不一定每一代都愿意承担 HBM 的封装成本

所以 GDDR 成为一种很强的平衡点。

## AI / HPC 加速器为什么越来越偏 HBM

AI / HPC 场景更容易出现：

- 计算吞吐远高于传统主存供数能力
- 带宽成为一等瓶颈
- 每比特能耗直接影响整机功耗

这时 HBM 的优势会被极大放大：

- 超宽接口
- 封装级近距互连
- 更高带宽密度

这里最好加一个范围限定：这不等于 HBM 会替代所有主存路线，更准确地说，是它在高带宽 AI / HPC 加速器里越来越常成为主流选择。

## 系统选型时的四个判断问题

1. 最主要瓶颈是容量、带宽还是延迟
2. 能接受多高的封装和 BOM 成本
3. 功耗预算是在芯片级、板级还是整机级最紧
4. 产品是通用平台，还是高价值专用加速器

## 一句话理解

`不同系统选不同内存，不是因为某条路线“更高级”，而是因为每个系统愿意支付的代价和最痛的瓶颈不同。`
