# 带宽 vs 延迟

上级：[04 系统架构视角](./README.md)

相关：[DDR、数据率与带宽](../03-ddr-protocol-families/ddr-double-data-rate-bandwidth.md)、[从 SRAM 到 HBM 的系统分层](./cache-dram-hbm-system-view.md)

## 为什么这两个概念最容易被混掉

很多人看到某种内存“带宽更高”，就直觉以为它“访问也更快”。这不成立。

这两个指标回答的是不同问题：

- 带宽：单位时间内最多能搬多少数据
- 延迟：单次请求从发出到返回，最少要等多久

## 一个直觉比喻

可以把它理解成运输系统：

- 带宽像高速公路总车流量
- 延迟像一辆车从出发到到达要多久

道路再宽，也不代表第一辆车立刻到。

## 为什么 DRAM 常常是“高带宽但不低延迟”

DRAM 的延迟不仅取决于链路速度，还取决于：

- 是否 row hit
- 是否要 activate / precharge
- 是否遇到 bank 冲突
- 是否被 refresh 打断

所以即使总线带宽很高，单次随机访问的返回时间也不一定低。

## 为什么 SRAM 更像“低延迟资源”

SRAM 的优势主要不是超大总带宽，而是：

- 不需要开行和预充电
- 访问路径更短
- 常与计算逻辑同 die 集成

所以它天然更适合作为延迟敏感层。

## HBM 的正确理解

HBM 的核心价值主要是：

- 更高总带宽
- 更好的每比特能耗
- 更高带宽密度

但这不等于“HBM 对所有单次访问都显著更低延迟”。

在很多系统里，HBM 改善的是“供数能力”，不是把它变成 SRAM。

## 架构分析时应该怎么问

面对一个 workload，先问：

- 它是被单次访问 latency 卡住，还是被持续吞吐 bandwidth 卡住
- 数据是否有局部性，可以被 SRAM/cache 吸收
- 它是流式搬运场景，还是随机小块访问场景

不同答案，会直接决定你该堆 SRAM、扩 DDR 通道，还是上 HBM。

## 一句话理解

`带宽描述“能搬多少”，延迟描述“回来多快”；好的内存系统设计，永远是在分层里分别解决这两个问题。`
