# RAM 在解决什么问题

上级：[01 概览与问题定义](./README.md)

相关：[SRAM vs DRAM 对照](../02-memory-cells-arrays/sram-vs-dram.md)、[从 SRAM 到 HBM 的系统分层](../04-system-architecture/cache-dram-hbm-system-view.md)

## 核心问题

计算系统里几乎所有瓶颈，最后都会落到一个基本问题上：

- 数据能不能及时送到计算单元旁边
- 单位时间能送多少
- 为了做到这件事，要付出多少功耗、面积、成本和封装复杂度

RAM 体系就是围绕这个问题展开的。

## 为什么 RAM 不是一个单点器件问题

当我们说内存时，常常会把很多不同层次的对象混在一起：

- `SRAM / DRAM`：存储单元和阵列实现
- `DDR / LPDDR / GDDR / HBM`：外部 DRAM 接口和产品家族
- `Cache / Main Memory / Local Buffer`：系统中的功能位置
- `DIMM / PoP / 2.5D / 3D stack`：封装和集成方式

如果不先把层级分开，后面看带宽、延迟、时序、封装时就很容易混乱。

## 为什么会分化出这么多路线

不同 RAM 技术，本质上是在不同约束下做取舍：

- `SRAM`：低延迟、直接寻址、面积贵，适合片上缓存
- `DDR`：容量大、生态成熟、成本低，适合通用主存
- `LPDDR`：优先低功耗，适合手机和轻薄设备
- `GDDR`：优先高带宽，适合独立 GPU
- `HBM`：优先极高带宽和更好的 pJ/bit，适合 AI / HPC

所以 RAM 的演进不是“谁更先进就替代谁”，而是系统约束改变后，最优点发生移动。

## 今天为什么 HBM 和先进封装变得重要

过去可以更多依赖提高接口频率、增加通道数来提升带宽，但随着系统进入 AI / GPU / HPC 时代，问题开始改变：

- 计算吞吐增长快于传统 DDR 通道带宽增长
- 高频长距离 I/O 的信号完整性和功耗恶化明显
- 大模型工作负载对总带宽和每比特能耗都更敏感
- 封装成为内存带宽扩展的一部分，而不再只是后端组装

这就是 HBM 和 2.5D/3D 封装成为主线的原因。

## 一句话理解

RAM 的本质不是“存住数据”，而是用不同的物理单元、接口标准和封装方式，在 `带宽、延迟、容量、功耗、成本` 之间找到系统最优解。
