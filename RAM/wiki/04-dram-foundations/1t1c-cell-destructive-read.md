# 1T1C cell，一颗电容为什么改变了一切

上级：[DRAM 基础](./README.md)
相关：[刷新：DRAM 的原罪和它的代价](./refresh-the-fundamental-cost.md), [6T cell 为什么是 6 个晶体管，双稳态如何对抗扰动](../02-sram-foundations/6t-cell-bistable-storage.md)

## 这页在回答什么问题

为什么 DRAM 会选择一颗访问晶体管加一颗电容的 1T1C 单元，而不是像 SRAM 那样用双稳态电路直接保存状态。更关键的是，这个看似简单的面积优化选择，为什么会连锁地产生 refresh、破坏性读出、整行感测和更复杂的控制接口。

## 正文

如果只用一句话概括 DRAM 与 SRAM 的差别，最常见的说法是“SRAM 用 6T，DRAM 用 1T1C”。这句话在事实层面没错，但完全不够解释为什么后面的世界会变得那么不一样。真正关键的不是“元件数少了”，而是存储信息的方式彻底变了。SRAM 把一个 bit 存成一个会自我再生的双稳态电路状态；DRAM 把一个 bit 存成一颗极小电容上的电荷多少。前者更像在维持一个持续存在的局部平衡点，后者更像在暂存一小笔会自然流失的物理量。就是这一变化，把 DRAM 从一开始就推到了“高密度但高维护”的路线。

先看为什么 1T1C 会如此有吸引力。对大容量主存来说，决定可行性的第一约束不是单次访问多快，而是每 bit 占多少面积。SRAM 的 6T 结构之所以快，是因为它愿意为每个 bit 付出较大的晶体管和稳定性成本；DRAM 如果也走这条路，容量和成本都会很快失去竞争力。1T1C 把每个 bit 压缩到一颗访问晶体管和一颗存电容，单位面积能放下的 bit 数大幅提升，这直接决定了它更适合做大容量存储。常见误解是把 DRAM 看成“更落后的存储单元”；实际上，它是在高密度这个目标上做了极其激进的优化，只是这个优化方式把后续复杂性全都转移到了别处。

问题也正从这里开始。电容上的电荷不是稳定逻辑状态，而是一种会随时间漏失的模拟量。无论是通过结漏、亚阈值漏电还是其他寄生路径，这点电荷都会逐渐衰减。因此，DRAM cell 天生没有 SRAM 那种“只要不断电就能自保持”的能力。它存住数据的方式，更准确地说是“在电荷还没漏光前，周期性重新感知并写回”。这就是 refresh 的根源。也就是说，refresh 不是后来的维护动作，而是 1T1C 这条路线一开始就欠下的基本债务。

但 even before refresh，读取本身就已经很麻烦。因为单个 DRAM cell 里的电荷量非常小，远远不足以像 SRAM 那样被直接当作一个完整数字电平读出来。实际读出时，cell 会通过访问晶体管与一根事先预充到中间电压附近的位线相连，cell 电容与位线电容发生电荷共享，只在位线上制造出一个非常微弱的电压偏移。这个偏移小到不能直接被后续逻辑安全解释，必须先交给 sense amp 放大。这里的关键是：你不是在“读取一个稳定存在的 0/1”，而是在“测量一个非常小的电荷扰动，再把它放大成 0/1”。

这就引出了所谓 destructive read。因为在电荷共享和感测放大的过程中，原来存放在 cell 电容里的那点电荷本身会被消耗或重分布，cell 不再自动保留原始信息。换句话说，DRAM 的读不是“观察而不打扰”，而更像“把样本拿出来测量，测完之后样本本身已经变了”。所以 sense amp 在 DRAM 里不是一个单纯的读出加速器，它还必须在放大之后把正确结果重新驱回 cell，完成恢复。常见误解是把 destructive read 理解为某种边缘现象；实际上，它是 1T1C + charge sharing 这条读出机制的自然结果。

如果把这一步与 SRAM 对照，差异会特别清楚。SRAM 读取时，外围主要是在限制对双稳态节点的扰动，同时尽快感知哪一侧位线先掉；读完之后，cell 的正反馈结构仍然在，原状态会继续被维持。DRAM 则没有这种自我维持结构。它的原始信息强度太弱，读过程又必须借助共享位线和 sense amp 才能被看见，于是“读出”和“恢复”天然绑在一起。后面你会看到，DRAM 的 row buffer、ACT 命令甚至很多 timing 参数，本质上都和这件事有关。

再往上一层推，就能理解为什么 DRAM 不适合像 SRAM 那样按 bit 精细访问。因为每个 cell 太弱，真正有价值的感测电路不可能给每个 bit 独立配一套并始终在线；更现实的做法，是让一整行 cell 共享一排 sense amp。当某一行被选中时，这整行的 cell 同时接到各自位线上，与整排 sense amp 共同完成放大和恢复。于是 DRAM 访问天然变成了“先开一整行，再从这一行里选列”的结构，而不是“给定地址直接取一个小字”。row/column 组织不是接口层的历史选择，而是 1T1C 阵列和放大器共享方式向系统暴露出来的结果。

这也解释了为什么 DRAM 的复杂性虽然常在协议层表现出来，根却扎在 cell 物理里。你后面看到的 `ACT`、`PRE`、`row hit`、`row conflict`、`refresh`、`bank`，看起来像很多系统层术语，但它们都不是凭空发明的。`ACT` 来自一整行 cell 必须先与 sense amp 连接并被恢复；`row hit` 来自某一行已经驻留在 sense amp 一侧；`refresh` 来自电荷自然流失；`bank` 则来自为了维持并行度和感测共享而做出的阵列切分。换句话说，1T1C 不是一个局部小技巧，而是整条 DRAM 工程路线的源头。

从工程 trade-off 角度看，1T1C 的本质可以概括成一句话：用极高的面积效率，换来对时间、感测和恢复机制的持续依赖。它让 DRAM 获得了容量与成本优势，但也使每一次访问都变成上下文相关事件，使刷新成为系统级背景负担，使高性能设计不得不围绕 sense amp、row buffer 和 bank 组织来构建。你不能只看到“DRAM 更便宜、更大”，而忽略这些优势是在什么代价结构上建立起来的。

所以，“一颗电容为什么改变了一切”的答案并不抽象。它改变的是 bit 的物理表示方式，而这件事又直接改变了访问方式、读的副作用、保持方式、阵列共享方式以及系统最终看见的接口形态。只要这一层看懂了，后面 DRAM 的很多复杂机制都会显得是顺理成章的，而不是额外添加的麻烦。

## 一句话理解

1T1C 把一个 bit 从“可自保持的电路状态”变成“会漏失的少量电荷”，于是 DRAM 用面积换来了密度，也同时引入了 refresh、破坏性读出和整行感测这一整套复杂性。

## 建模启示

在架构探索模型里，通常不会显式模拟单个 cell 的电荷共享过程，但 1T1C 的后果必须被保留下来。最少要显式表达三件事：`cell state is weak`，因此访问必须经过感测放大；`read is destructive`，因此读后需要恢复；`charge decays over time`，因此刷新不可省略。很多过于简单的 DRAM 模型之所以误导，就是因为它只保留了“高延迟大容量”，却抹掉了这三个根因。

一个适合作为后续章节底座的最小草图可以是：

```text
DramCellDerivedModel {
  requires_refresh: bool
  destructive_read: bool
  sense_before_data_visible: bool
  retention_window_cycles: uint64
}
```

如果进一步往阵列层抬，可以立刻得到：

```text
DramBankState {
  open_row: row_id | INVALID
  row_buffer_valid: bool
  restore_in_progress: bool
  refresh_deadline: cycle
}
```

这里的关键不是字段名字，而是建模时承认：DRAM 访问不是“到达地址后直接读出”，而是必须先经过感测和恢复这两个阶段。若只关心粗粒度性能，这些阶段可以在后续折叠成行激活和刷新开销；但如果连这一层逻辑都不保留，后面关于 row buffer、timing 参数和 page policy 的模型就会失去物理根基。
