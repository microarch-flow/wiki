# DRAM 工艺路线：平面到堆叠到 3D

上级：[DRAM 基础](./README.md)
相关：[HBM 的 2.5D/3D 集成与 TSV 技术](../08-packaging-integration/hbm-2.5d-3d-tsv.md), [为什么 HBM 的成本结构很高](../08-packaging-integration/why-hbm-is-expensive.md)

## 这页在回答什么问题

DRAM 为了继续提高容量密度、带宽和每 bit 能效，为什么工艺路线会从长期的平面阵列逐步走向更深的堆叠和 3D 方向。这里关注的不是系统封装方案本身，而是 DRAM die 这一层为什么越来越难只靠传统平面缩放继续前进。

## 正文

到这一章前面为止，DRAM 的主线已经很清楚了：它靠 1T1C 单元和整行感测机制赢得了密度，却也背上了 refresh、row buffer、bank 并行和接口桥接这些复杂性。接下来再往前推一步，自然会遇到另一个问题：既然 DRAM 的价值很大程度上来自“单位面积塞下更多 bit”，那它是否可以像早期逻辑工艺那样，靠一代代平面缩小不断线性提升？现实是，这条路越来越难走，原因不只是制造更难，而是 DRAM 的核心目标本身把它推向了和逻辑工艺不同的优化方向。

先看平面 DRAM 为什么曾经如此成功。1T1C 的价值就在于把每个 bit 压到极小面积，而 row/column + sense amp 共享又把外围电路摊薄到了非常大的阵列上。只要工艺还能让 cell 电容、访问晶体管和阵列布线继续缩小，同时保持足够的感测裕量和 retention，平面扩展就能稳定带来更高密度、更低每 bit 成本。这也是 DRAM 长期能作为主存主角的根本基础。

问题在于，平面缩放不会永远只带来好处。对 DRAM 而言，核心压力至少来自三方面。第一，cell 电容不能无限缩小，因为你缩得越小，可存的电荷越少，感测信号越弱，retention 也更脆弱。第二，访问晶体管缩小后，导通能力、漏电和可控性之间的张力会变大，读写窗口更难收敛。第三，阵列越大、bank 越多、I/O 越快之后，单纯在一个平面上继续堆密度，不一定能同步解决带宽和能效问题。也就是说，平面缩放先碰到的不是“我们不想缩了”，而是“继续缩下去开始伤到存储物理的根”。

这里最关键的是 cell 电容。逻辑工艺很多时候关心的是晶体管开关速度和面积，而 DRAM cell 还必须保住一个足够可感测的电荷量。你可以把 DRAM 的工艺难点理解成双重约束：既要像逻辑一样缩器件，又不能让“一个 bit 存下的那点电荷”小到 sense amp 难以可靠判别。于是工艺进展在 DRAM 上经常不是简单做小，而是要围绕电容结构、材料、深沟槽或堆叠式电容等方向，不断寻找“在更小 footprint 下仍保住足够电荷”的办法。常见误解是以为 DRAM 缩放只是在复制逻辑节点演进；实际上，DRAM 很多关键创新都在于如何保住电容而不是只保住晶体管。

这也是为什么 DRAM 工艺路线很自然会逐步走向“立体化”。如果平面面积越来越难再提供足够的电容或足够好的每 bit 成本，那么一个直接方向就是把更多结构往垂直维度借空间。对单颗 DRAM die 来说，这首先表现为 cell 电容结构越来越立体，而不是简单二维摊开。再往后，当容量、I/O 数和带宽需求继续上升时，仅靠单层平面 die 的扩展也会越来越吃力，于是 die 级堆叠、垂直互连和更高密度集成开始显得合理。

这里要小心分层。本文说的“走向堆叠和 3D”，第一层含义是 DRAM 自身工艺和 die 组织越来越依赖垂直维度，而不只是二维缩放；第二层含义才是多 die 堆叠形成更高容量或更高 I/O 密度的内存 stack。至于 HBM 与计算 die 一起放进 2.5D/3D 封装，那已经是更高一层的系统级集成问题，会放到 `08-packaging-integration/` 再展开。这里先收住边界：本页只讨论 DRAM 自己为什么越来越需要“向上长”，而不是系统为什么要把内存和计算一起封装。

为什么垂直化对 DRAM 特别有吸引力，还因为它同时触碰了容量和带宽两个痛点。单 die 平面扩展的主要优势是容量密度，但外部 I/O 数、封装引脚和板级距离很快会限制总带宽继续提高。若通过多层 die 堆叠和更短的垂直互连把多个 DRAM die 更紧地组织起来，就不仅能继续提升总容量，还能为更高 I/O 密度和更近的带宽汇聚创造条件。也就是说，堆叠不是只为“多放几层存储”，而是在为后面的高带宽产品路线预先打开空间。

这条工艺演化线也解释了为什么 HBM 看上去像是突然出现的“新一代内存”，其实它的很多前提早在 DRAM die 层就已经埋下了。HBM 的系统价值当然离不开 TSV、base die、interposer 和先进封装，但这些东西之所以有意义，前提正是 DRAM 自身已经走到一个阶段：单纯的平面 die 再往上推，无论在容量密度、I/O 密度还是每 bit 能效上，都越来越难独自满足高带宽计算系统的需要。

当然，走向堆叠和 3D 不是没有代价。每多一层垂直结构，制造流程、良率控制、热管理、测试和已知良品筛选都会变复杂。平面扩展虽然越来越难，但它的制造路径更成熟、测试边界更清晰、成本模型也更熟悉。堆叠路线之所以成立，不是因为它没有代价，而是因为在高容量和高带宽要求继续上涨时，平面路线的边际收益已经不足以覆盖系统目标。这一点和前面 SRAM 在先进制程下面积/稳定性一起失速的逻辑其实相通：不是技术突然不进步，而是旧维度上的进步已经不够用了。

从系统架构的角度回看，这条工艺路线有两个后果。第一，DRAM 的“密度提升”越来越不只是 cell 尺寸问题，而是工艺结构、die 组织和后续集成方式共同作用的结果。第二，容量路线和带宽路线开始越来越紧密地耦合到一起，因为一旦进入堆叠与垂直互连，系统就不再能把“存多少”和“送多快”完全分开看。后面到了 HBM、封装和 AI 芯片章节，这个耦合会变得更直接。

所以，这一页真正要建立的，不是简单一句“DRAM 从平面走向 3D”，而是更具体的判断：平面缩放越来越难同时满足 cell 电容、阵列密度和接口带宽要求，于是 DRAM 的工艺与 die 组织自然开始借助垂直维度延续密度和带宽演化。这条路线随后才会与 HBM、TSV 和先进封装汇合。

## 一句话理解

DRAM 走向堆叠和 3D，不是因为“3D 更先进”这句空话，而是因为平面缩放越来越难同时保住 cell 电容、每 bit 成本和 I/O 密度，垂直维度成了继续前进的现实出口。

## 建模启示

在架构探索模型里，这一页对应的不是某个立即可见的周期事件，而是对“容量扩展与带宽扩展代价曲线”的修正。也就是说，不能再假设更大 DRAM 容量只意味着更多地址空间，而要允许不同工艺/组织路线对 `capacity_density`、`io_density`、`energy_per_bit` 和 `thermal_risk` 产生联动影响。

一个够用的参数化草图可以是：

```text
DramTechnologyModel {
  organization: enum { PLANAR, STACKED_DIE, STACKED_3D }
  capacity_per_package_GB: float
  io_density_norm: float
  energy_per_bit_pJ: float
  thermal_complexity_norm: float
  manufacturing_complexity_norm: float
}
```

如果只关心粗粒度系统性能，`thermal_complexity_norm` 和 `manufacturing_complexity_norm` 也许不会直接进入周期级仿真；但只要你在做设计空间探索、产品路线比较或成本/功耗联合权衡，就不该把它们完全丢掉。因为很多“为什么不直接换更大带宽 DRAM”的答案，最终不在协议参数，而在工艺与集成路线是否还能承受。

更进一步，如果要把这页与后续 `08` 章连接起来，可以把 DRAM die 技术路线与系统封装路线分成两层对象，而不要混成一个标签：

```text
MemoryDieTech = { PLANAR_DRAM, STACKED_DRAM }
PackageIntegration = { DIMM, POP, INTERPOSER_2P5D, STACKED_3D }
```

这能避免模型里出现“HBM = 一种单一物理东西”的混淆。更准确的做法，是分别表达 die 组织和系统集成，再在后续产品路线里组合它们。
