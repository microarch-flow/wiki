# 为什么 SRAM 在先进制程下不再线性 scale

上级：[SRAM 基础](./README.md)
相关：[漏电、保持电压、low-power SRAM 设计](./sram-power-leakage-retention.md), [DRAM 工艺路线：平面到堆叠到 3D](../04-dram-foundations/dram-process-stacking-trends.md)

## 这页在回答什么问题

逻辑晶体管一代代缩小，为什么 SRAM 却越来越难同时把面积、最低工作电压和稳定性一起缩下去。更具体地说，先进制程究竟先卡住了 SRAM 的哪几个物理量，以至于“节点前进 = bitcell 自然变优”这条直觉逐渐失效。

## 正文

在很多架构讨论里，工艺进步常被默认理解为一个统一利好：晶体管更小、速度更高、功耗更低、面积更省，于是片上 SRAM 似乎也应该跟着同步受益。这就像假设”缩小所有零件就能做出更小更好的手表”——对齿轮和发条来说或许成立，但对游丝和摆轮这种依赖精密平衡的部件，缩小反而更容易失准。SRAM 正是芯片里的”游丝”。它不是一个只看单个器件开关速度的逻辑门，而是一个依赖器件强弱平衡、噪声容限和最坏角稳定性的双稳态模拟边界问题。逻辑路径能跑通，不代表 SRAM cell 就能稳住。

先看最直观的指标：bitcell 面积。按最简单的想法，制程缩小后，6 个晶体管占地都变小，bitcell 面积应该跟着接近线性下降。现实是，SRAM bitcell 的面积往往受非常强的 layout 规则限制，尤其受接触孔、金属间距、鳍片数量、栅极间隔和局部布线规则约束。也就是说，bitcell 不是一个可以自由变形的几何体，而是一个被工艺 design rule 严格卡住的重复模板。随着节点进入 FinFET 乃至更先进结构后，晶体管本身虽然更先进，但 bitcell 在版图上的自由度并没有同步增加，甚至可能更受限。因此你会看到 SRAM bitcell area 的缩放速度往往慢于逻辑标准单元，所谓“SRAM scaling stall”并不是口号，而是版图规则和稳定性共同作用的结果。

面积失速只是表象，更本质的问题在 `Vmin`。对很多数字逻辑来说，电压降低首先意味着速度下降，然后才在更低电压下逐步触碰功能边界。对 SRAM 来说，情况更尖锐，因为它必须同时满足 hold stability、read stability 和 write-ability。电压一降，噪声容限变小，器件失配变得更显著，读扰动更容易把内部低节点抬翻，写入时又更难把原状态压过去。于是 SRAM 经常会出现这样一种现象：逻辑电路在某个电压下还能算，SRAM 却已经不再可靠。这就是为什么很多 SoC 或加速器的最低系统工作电压，并不是由算术单元决定，而是被大片 SRAM 宏先卡住。

这里的关键不是“低电压更难”这么泛泛一句，而是 6T cell 的三个条件会在低电压下同时恶化。保持时，交叉耦合反相器的再生能力减弱，SNM 缩小；读取时，位线预充高电平通过访问晶体管对 cell 内部低节点的扰动比例变大；写入时，外围写驱动虽然也变弱，但 cell 内部正反馈并没有因此“变得更容易被推翻”，所以写能力窗口也在缩。也就是说，电压降低不是单纯让一切都慢一点，而是在压缩一组本来就彼此拉扯的稳定性三角形。

工艺波动和器件失配会把这个问题继续放大。想象一个管弦乐团：乐器越精密，对每位乐手的校准要求就越高。如果某位小提琴手的琴弦稍微跑调，在大乐团中这个偏差可能被淹没；但如果整个乐团只有六位乐手（就像 6T cell 只有 6 个晶体管），任何一位跑调都会被清楚听到。SRAM cell 很小，而越小的器件越容易受到随机掺杂、线边粗糙、阈值电压波动、鳍片数量离散化和局部应力变化影响。对一个普通逻辑门来说，这些波动大多表现为路径延迟分布变宽；对 SRAM cell 来说，它们会直接改变两侧反相器和访问晶体管之间的相对强弱，从而改变读稳定性和写能力。SRAM 关注的不是”平均晶体管好不好”，而是”最差那个 cell 在最差 PVT 角下会不会翻”。大阵列里 cell 数量极多，尾部失效才是真正决定良率和可用电压的那部分，所以先进节点下 SRAM 的设计与签核天然更像统计极值问题。

这也是为什么 `SNM`、`read margin`、`write margin` 在 SRAM 工程里如此关键。随着工艺缩小和供电降低，这些 margin 往往不会自动随节点提升，反而可能被侵蚀。于是设计者不得不采用一系列补救措施：重新 sizing，使用 assist circuit，读写分离位线，字线 boosting，negative bitline，局部电压域，甚至从 6T 转向 8T/10T 这样的 cell 变体。你可以把这些动作理解为一个共同信号：标准 6T 在先进节点下不再总能“自然收敛”，必须靠更多外围技巧或更胖的 cell 去买回原本的稳定性窗口。常见误解是以为先进制程下 SRAM 仍然只是”同样结构更小一点”；实际上，更像是在更小的场地上建相同功能的房子——你不是只缩小图纸，而是要重新设计结构加固方案。

速度问题也并没有因为器件变快就彻底消失。先进节点能提高晶体管驱动能力，但同时金属线 RC、局部互连拥挤、供电噪声和大阵列布线负担也会更突出。片上 SRAM 宏尤其容易变成“器件很快，阵列不快”的对象：bitcell 本身的内部门延迟未必是主因，真正限制周期的可能是长字线、长位线、局部感测裕量、跨 bank 布线和电源完整性。因此，先进节点下 SRAM 的性能改进常常越来越依赖组织和电路技巧，而不是单纯押注晶体管切换更快。

先进制程还会把功耗矛盾推到更尖的位置。漏电通常更难压，低 Vt 器件虽有助于速度，却会进一步加重 standby leakage；提高稳定性可能要求更强的器件或更保守的电压，进而损失动态能效；为了保证低电压可写、可读，又可能引入 assist 电路和额外切换。这意味着 SRAM 不只是“面积缩放没以前爽快”，而是功耗、稳定性和速度三者一起变得更难同时最优。后面一篇关于 retention 和 low-power SRAM 的讨论，本质上就是这个问题在低功耗设计里的继续展开。

从系统角度看，SRAM scaling 失速的后果非常具体。第一，片上 SRAM 容量不再能理所当然地跟着计算密度同步上涨，因此“算力变大，片上 buffer 也自然够大”这条假设会失效。第二，最低工作电压和 DVFS 下限可能被 SRAM 宏卡住，而不是被算术单元卡住。第三，若为了稳定性改用更胖的 cell、更多 assist 或更分散的 bank，面积和功耗预算会更早吃紧。对 NPU 和大规模片上 buffer 尤其如此，因为你不是在放几 KB 小 cache，而是在和几 MB 甚至几十 MB 片上 SRAM 的面积、功耗和良率正面交手。

所以，“SRAM 在先进制程下不再 scale”真正指的不是它完全不进步，而是它不再满足那种简单、线性的缩放预期。节点前进依然可能带来速度、密度或能效收益，但这些收益越来越依赖你如何重新平衡 bitcell 面积、margin、辅助电路、阵列组织和工作电压。后面只要开始讨论大容量片上 buffer、低功耗 retention 或高并发 register file，这个限制都会不断回来。

## 一句话理解

SRAM 在先进节点下的真正瓶颈，不是晶体管会不会继续变小，而是 bitcell 面积、稳定性 margin 和最低工作电压不再能随节点一起轻松缩放。

## 建模启示

这篇对应的核心建模后果是：不能假设“更先进工艺”只会把 SRAM 的 `area` 和 `latency` 按比例缩小。对架构探索来说，至少需要把 SRAM 工艺世代影响拆成几条独立曲线：`density_gain`、`frequency_gain`、`vmin_floor`、`leakage_growth`。否则模型会系统性高估未来节点上大容量片上 SRAM 的可用性。

一个够用的参数化草图可以写成：

```text
SramNodeModel {
  process_node_nm: int
  density_scale_vs_prev: float
  read_latency_scale_vs_prev: float
  leakage_scale_vs_prev: float
  min_operating_voltage_mV: int
  retention_voltage_mV: int
  max_stable_capacity_per_macro_KB: int
}
```

其中最容易被忽略的是 `min_operating_voltage_mV` 和 `max_stable_capacity_per_macro_KB`。前者会限制 DVFS 和低功耗模式，后者虽然是粗化参数，但能在系统探索里表达一个现实：大容量 SRAM 宏并不会无限大而不付出频率、良率和组织代价。

如果要做事件级性能模型，这篇不要求你显式模拟 SNM 或 Monte Carlo 失配，但至少可以保留一类“模式切换约束”：

```text
guard supply_voltage >= min_operating_voltage_mV
guard macro_capacity <= max_stable_capacity_per_macro_KB or requires_extra_banking = true
```

如果忽略这些约束，模型很容易得出一种不现实的最优解：把片上 SRAM 无限做大、无限降压、同时还保持高频。这类解在真实 silicon 上通常先被 SRAM 打回去。
