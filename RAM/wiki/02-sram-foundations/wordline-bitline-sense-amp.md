# 字线、位线、读出放大器：SRAM 的电路骨架

上级：[SRAM 基础](./README.md)
相关：[SRAM 一次读写的 cycle-by-cycle 行为](./read-write-cycle-timing.md), [行列解码与读出放大：为什么 DRAM 必须先开行](../04-dram-foundations/row-column-decode-sense-amplify.md)

## 这页在回答什么问题

既然 6T cell 自己就能稳定存住一个 bit，为什么 SRAM 仍然需要字线、位线和 sense amp 这些看起来“阵列味很重”的部件。更具体地说，SRAM 的低延迟到底来自哪里，又在哪些地方仍然要为长导线、电容负载和微小电压差付账。

## 正文

理解 6T cell 之后，很容易产生一个误解：既然 cell 内部已经有稳定的 `Q/QB` 状态，读取它似乎只是“把内部值直接拿出来”而已。真实阵列里并不是这样。单个 cell 可以很局部，但一旦它被放进大规模阵列，访问它就不再只是两个反相器之间的局部行为，而是要通过共享导线把这一行的某个 cell 连接到阵列外围。字线、位线和 sense amp 的存在，本质上是在解决一个问题：怎样让成千上万个 cell 被规则地组织起来，同时又不让访问路径被长导线和共享负载拖垮。

先看字线 `wordline`。它的作用不是传输数据，而是选择“哪一行 cell 被允许接入位线”。同一行的所有 cell，共享一根字线；当字线拉高时，这一行中每个 cell 的两个访问晶体管同时导通，各自把内部节点连到对应的差分位线 `BL/BLB`。这意味着字线是典型的高扇出控制信号。阵列越宽，一根字线挂接的访问晶体管越多，驱动它所需的电流和上升时间压力就越大。常见误解是以为 SRAM 的延迟主要都在 cell 内部；实际上，字线驱动本身就是访问路径的一部分，尤其在大数组中，它往往不再是可以忽略的“小控制线”。

再看位线 `bitline`。位线才是真正承担数据交换的共享导线。一列中的所有 cell 都挂在同一对差分位线上，但一次只有被选中的那一行真正导通到位线。问题在于，这根位线不是理想导体，而是很长、很细、挂着很多未选中 cell 的寄生电容网络。即使只读取一个 bit，实际发生的也是“某个被选中 cell 试图轻微拉动一整根已预充的位线”。所以 SRAM 的速度虽然比 DRAM 高得多，但它仍然不是“直接读节点电平”，而是“让 cell 对共享位线制造一个足够早、足够可靠的差分信号，再由外围电路放大”。

这就是为什么 SRAM 也需要预充和差分感测。典型读操作开始前，`BL` 和 `BLB` 会被预充到高电平，且尽量保持相等。随后字线拉高，若 cell 当前状态为 `Q=1, QB=0`，则其中一侧位线会更容易维持高电平，另一侧则会通过 cell 的下拉路径开始轻微放电。此时真正有价值的并不是某一侧“已经完全变成 0”，而是两根位线之间出现了一个很小但方向明确的电压差。sense amp 的任务，就是在这个差分还很小的时候尽快识别方向，并把它放大为完整的逻辑输出。可以做一个有限度类比：sense amp 不是在等待位线自己慢慢掉到 0 再去读，而更像是在抓“哪一边先露出败势”的瞬间，然后迅速判定胜负。这个类比只适合帮助理解为什么感测可以提前发生，精确机制仍然是差分放大。

这里有一个经常被忽略的关键点：SRAM 和 DRAM 都有 sense amp，但两者角色并不相同。对 DRAM 来说，sense amp 同时承担“读出、放大、恢复数据”的职责，因为原始 cell 存的是极弱电荷，且读取本身具有破坏性。对 SRAM 来说，sense amp 主要承担“加速判决、减轻位线摆幅需求”的职责，因为 cell 状态本来就是稳定的，感测不需要负责把数据重新写回 cell。也正因为如此，SRAM 的 sense amp 可以更专注于速度和小摆幅检测，而不必像 DRAM 那样直接成为 row buffer 的一部分。后面到 [row-column-decode-sense-amplify.md](/mnt/e/wiki/RAM/wiki/04-dram-foundations/row-column-decode-sense-amplify.md) 时，这个差别会非常关键。

为什么位线往往用差分而不是单端？因为差分结构能显著提高抗噪声能力，并让 sense amp 更早做决定。两根位线在预充时尽量保持相同，读操作时只需要观察哪一侧略先下降，就能在共模噪声、供电波动和局部失配存在时保持更稳的判决。代价当然也很直接：每个存储 bit 在列方向上要占用两根共享数据线，外围预充和感测电路也更复杂。主流 SRAM 仍然普遍接受这个代价，是因为在高性能阵列里，感测裕量和速度通常比“省一根位线”更重要。

位线长度为什么会成为阵列设计的核心约束之一，也可以从这个角度看清。位线越长，挂接的 cell 越多，总电容越大；总电容越大，被选中 cell 制造出可感测差分所需的时间越长，能量也越高。这会直接推高读延迟，并逼迫设计者在阵列规模与速度之间做切分。于是你几乎不会看到一个现代高性能 SRAM 把所有 bit 简单做成一个巨大平面，而是会切成更短位线的子阵列、bank 或 mat。常见误解是认为 bank 划分主要为了并行访问；实际上，在 SRAM 中，bank 划分同样是在为位线长度、字线负载和周期时间付账。

写操作也沿着同一条骨架展开，只是目标相反。读的时候，cell 轻微拉动位线，然后 sense amp 尽快判决；写的时候，外围写驱动器先把 `BL/BLB` 强行拉成目标差分，再让字线导通，迫使 cell 内部一个节点被拉低，另一个节点被释放并由正反馈翻转。这里字线、位线、访问晶体管和 cell 内部强度之间的关系会直接决定写能力。如果位线驱动太弱，或者访问通路相对 cell 内部维持能力太弱，就会出现“看上去写了，实际上翻不过去”的问题。这也是为什么位线不仅是读路径的一部分，同样是写入能力的决定因素。

从工程角度看，SRAM 阵列骨架的真正难点不在“概念上分成 WL/BL/SA”这么简单，而在于三者会共同定义阵列的速度边界。字线决定选通成本，位线决定共享负载和摆幅成本，sense amp 决定你能在多小的差分上可靠做决定。把其中任意一项理想化，都会低估大容量 SRAM 的访问成本。尤其在片上大 buffer 或高频 cache 中，很多优化其实不是在改 cell，而是在切短位线、分层字线、局部化 sense amp、减少每次读写的摆幅。

因此，SRAM 的“快”从来不是无条件的。它快，是因为相比 DRAM，它把访问限制在更局部的阵列和更直接的读写机制中；但它仍然必须面对共享导线、电容负载、感测裕量和阵列尺寸的约束。理解这条骨架之后，后面再看 cycle-by-cycle 读写过程、多端口代价和 bank 组织，就不会把它们误以为是附属优化，而会看到它们都在围绕同一条访问路径做权衡。

## 一句话理解

SRAM 的电路骨架是“字线负责选通、位线负责交换、sense amp 负责尽早判决”，它之所以快，不是因为没有阵列成本，而是因为这些成本被控制在更局部、更小摆幅的访问路径里。

## 建模启示

在高层模型里，通常不会显式模拟位线上的连续电压变化，但这条电路骨架仍然应该留下几个离散后果。第一，`read_latency` 与阵列尺寸有关，不能被当成完全固定常数。第二，读取和写入可以共享同一对位线，但读是“cell 拉位线”，写是“位线推 cell”，因此两者的能耗和临界路径未必相同。第三，bank 划分不仅影响并行度，也影响单次访问时延，因为它改变了字线和位线长度。

一个适合保留这类影响的抽象参数集可以是：

```text
SramArrayTimingModel {
  rows_per_bank: int
  cols_per_bank: int
  wl_decode_cycles: int
  bl_develop_cycles: int
  sense_cycles: int
  write_drive_cycles: int
  precharge_cycles: int
}
```

如果只关心吞吐，可以把 `wl_decode + bl_develop + sense` 折叠成单个 `read_latency_cycles`，但在比较不同 bank 粒度、不同容量 SRAM，或者分析读写非对称时，最好保留这些分项，因为它们能解释“为什么把 buffer 做大后频率掉了”或“为什么切 bank 后虽然多了仲裁却反而更快”。一个简化事件流可以写成：

```text
event WlAssert(array_id, row_id)
event BitlineDevelop(array_id, col_group)
event SenseComplete(array_id, col_group)
event WriteDriveComplete(array_id, col_group)
```

这里不需要进入模拟电路级别，但至少要承认：SRAM 访问时间不是凭空给出的常数，而是由字线、位线和感测链路共同组成的。
