# SRAM 一次访问：电气阶段与接口时序

上级：[SRAM 基础](./README.md)
相关：[字线、位线、读出放大器](./wordline-bitline-sense-amp.md)、[DRAM 命令](../05-dram-protocol-families/commands-act-rd-wr-pre.md)

## 访问由哪些阶段构成

SRAM 的输入通常包括地址、片选、读写控制以及写数据；读操作输出数据。具体信号和有效边沿由宏接口定义。宏内部先准备共享位线并选择行，再进行读出或写入，最后恢复到允许下一次访问的状态。

下图只表示依赖关系，不把每个阶段标成一个周期。部分阶段可以并行或与前后访问重叠。预充的具体位置取决于宏实现。

```text
读：输入采样 → 地址译码、位线准备 → 字线选通 → 位线差分发展 → 感测/列选择 → 输出有效
写：输入采样 → 地址译码、写驱动准备 → 字线选通 → cell 翻转 → 保持并恢复
```

典型 6T 差分读中，预充使 `BL/BLB` 从接近相同的电位开始。字线打开后，cell 使一侧位线下降，产生可感测的差分。感测过早会受噪声和失配影响；过强或过长的读扰动也可能破坏 cell。写入时则由写驱动建立目标差分，迫使 cell 跨越翻转点。写成功还要求字线关闭后新状态保持稳定。不同阵列也可能采用其他感测或写入方式。

## 一个同步宏的接口例子

[OpenRAM 控制时序文档](https://github.com/VLSIDA/OpenRAM/blob/stable/docs/source/control_logic.md)描述一种同步接口：正沿采样地址和数据；高电平阶段进行输入采样、预充和译码；低电平阶段执行读写；读数据在负沿之后、下一正沿之前可用。这是该实现的接口描述，不是所有 SRAM 的规则。

以下数字仅是手算假设，单位为 ns，并非 OpenRAM 或某个硅宏的规格：周期 `T=2`，采样正沿为 0，负沿为 1，下一正沿为 2。假设读数据在 `1.55` 有效，接收寄存器要求在正沿前 `0.15` 稳定，则建立裕量为 `2 - 1.55 - 0.15 = 0.30`。假设其数据保持约束也满足，接收寄存器可在 2 ns 采样。输入端也必须满足宏规定的 setup/hold；不能只检查输出。

宏如果声明每个正沿都能接纳新请求，则该例的接纳间隔为 1 拍。输出在 1.55 ns 有效，接收端在下一正沿采样，属于不同的时间定义。假设写完成没有外部 `ack`，则不能从图中凭空推断 `WriteAck`：写入何时对后续读可见、同地址读写冲突如何处理，应查宏接口和库表。

## 工艺、频率与可见边界

真实宏的接口时间应来自选定工艺、电压、温度（PVT）、时钟波形、输入转换时间、输出负载和对应 timing library。检查输入 setup/hold、时钟到输出的最大和最小延迟、时钟高低脉宽、输出接收端 setup/hold，以及端口冲突规则。宏的允许周期和可用工作点也要单独确认。示意图不能证明任何工作点可运行。

接口延迟与接纳间隔不是同一参数。一个接口可以在请求后若干拍返回数据，同时每拍接纳一笔；也可以只在前一笔恢复后接纳下一笔。实际读写组合、端口和 bank 冲突可能改变接纳规则。

## 建模启示

离散模型应以宏规定的采样边沿为 `accept`，分别记录数据可见事件、接收边沿、写可见事件和下一次接纳的最早边沿。还应记录冲突及其结果。电路阶段若只用于解释，可保存为连续时间估计，不要把每个阶段各自向上取整成一整拍再相加。对接口有约束的结果，在所选时钟域的真实边沿上取整一次；并行和跨访问重叠要按实际依赖求关键路径，而不是简单求和。

```text
SramTiming {
  clock_domain, pvt, input_setup, input_hold, output_load
  read_visible_time_or_edge, write_visible_edge
  read_ii_edges, write_ii_edges, port_conflict_policy
}
accept(req, edge)  ->  schedule_visible(req, documented_time_or_edge)
next_accept_edge   = edge + documented_ii(req, port_state)
```

模拟器可观测的结果包括请求接纳边沿、数据有效或被采样的边沿、写后读结果、下一次接纳边沿及端口等待。若库只给接口级结果，模型不应声称验证了位线波形或 cell 稳定性。
