# bank、sub-array、mat：SRAM 阵列怎么划分才高效

上级：[SRAM 基础](./README.md)
相关：[单口、双口、多口 SRAM，端口数为什么是关键代价](./single-port-dual-port-multi-port.md), [NPU 里的 SRAM buffer：weight、activation、accumulator](../03-sram-applications/npu-weight-buffer-activation-buffer.md)

## 这页在回答什么问题

为什么 SRAM 阵列不能简单地做成一个“越大越好”的平面，而必须切成 bank、sub-array、mat 这些层次。更关键的是，这些切分不是命名习惯，而是在访问延迟、能耗、并行度、端口压力和布局布线之间不断妥协的结果。

## 正文

理解 SRAM 阵列组织的第一步，是先放弃一个直觉误区：容量扩大并不是把更多 6T cell 平铺上去就结束。只要阵列继续长大，字线会更长、位线会更长、挂接的访问晶体管和寄生电容会更多、预充和感测负载会更重、局部热点也会更集中。于是“更大 SRAM”并不是一个单一对象，而会自然分裂成几个层次：局部可快速感测的小块、若干小块组成的更大访问单元、若干访问单元再组成带有仲裁和接口的 bank。这些层次的存在，不是为了让文档结构更漂亮，而是因为物理实现已经不允许你把所有 bit 当作一个统一平面来对待。

最小的阵列组织单元常被叫作 `mat`，名字不重要，重要的是它所代表的工程含义。一个 mat 往往是一块局部位线和局部字线长度都相对可控的基本阵列片段，旁边配有自己的局部预充、局部 sense amp、局部写驱动和部分列 mux。你可以把它理解为“一个在时序和能耗上还算收得住的最小阵列砖块”。mat 做得太大，位线发展时间和字线驱动时间会先失控；mat 做得太小，外围感测电路、译码逻辑和边界开销占比又会过高，面积效率下降。因此 mat 的大小本质上是在“阵列共享效率”和“局部访问速度”之间找平衡。

多个 mat 再往上组合，往往形成 `sub-array` 或与之等价的中间层。这个层级的作用，是在不完全复制外围接口的前提下，把若干局部阵列块组合成一块更大的可管理区域。这里开始出现一个重要设计动作：层次化译码和层次化布线。也就是说，你不会再让全局地址直接驱动所有局部字线，而是先用更高层的选择信号选中某个 sub-array，再在局部做更短的译码和驱动。这样做的核心收益，是把本来可能跨越整个宏的大扇出控制和长导线问题，拆成几段更容易收敛的局部问题。代价则是多了一级选择、多了局部 mux，也可能增加了一点额外译码延迟。

再往上一层就是 `bank`。bank 的定义在不同文档里有时会有宽窄差异，但在系统视角下，你可以把它理解为一个相对独立的服务单元：它通常拥有自己的一组主要访问通路，可以与其他 bank 在一定程度上并行工作，也经常成为冲突建模和调度建模的最小粒度。这里要强调一点：bank 不只是为了提高并行度，它同样是在控制单次访问的物理代价。因为一旦你决定把 1 MB SRAM 切成 8 个 128 KB bank，你不仅获得了“最多 8 路并发”的可能性，也把单个 bank 内的字线、位线和局部 mux 长度都压小了。常见误解是认为 banking 只是系统层面的吞吐优化；实际上，它往往首先是阵列层面的时序和能耗优化。

为什么这些层次会同时影响延迟和带宽，也可以从一次访问怎么走来理解。若阵列完全单体化，一次访问可能只需要一次全局译码，但随后会面对非常长的字线和位线发展时间。若阵列切得很碎，每次访问可能要经过 bank 选择、sub-array 选择、mat 选择，再做局部感测，单次控制路径更长，但局部物理路径更短。两种极端都不好。高性能 SRAM 的组织，本质上是在寻找一个折中点：让控制层次增加的代价，小于长导线和大电容带来的代价。也正因为如此，mat/sub-array/bank 的划分从来不是一个纯容量公式能唯一推出的结果，它总是与目标频率、可接受功耗、端口需求和 floorplan 共同耦合。

端口需求会进一步改变这套组织。前一篇已经讲过，真多端口很贵，因此很多设计会先把并发访问需求翻译成 bank 并行问题，而不是直接加端口。这样一来，bank 划分就不再只是“把大阵列切小”这么简单，而是要和地址映射、数据布局和访问模式一起设计。比如 NPU 中的 weight buffer 和 activation buffer，常常希望让不同计算 tile 在同一拍访问不同 bank，从而用多个单口或 1R1W bank 近似实现高并发吞吐。如果你只从 bit cell 角度理解 SRAM，这些后续组织策略会显得像“系统层技巧”；其实它们从阵列切分这一步就已经开始了。

阵列切分还直接决定能耗曲线。一次读取如果只需要唤醒一个局部 mat，而不是整片大阵列，那么被充放电的字线、位线、局部 mux 和感测电路都更少，单次访问能耗就更低。反过来，如果切分过细，为了到达目标数据而经历的额外译码、跨层 mux 和控制翻转又会增加能耗。因此“更细粒度更省电”也不是绝对真理。很多低功耗 SRAM 宏会把局部字线、局部位线、bank 级 clock/power gating 和分段感测结合起来，本质都是在让“每次只唤醒必要局部”这件事成立，但它们也都会增加控制复杂度。

这套组织对物理实现的影响同样很硬。bank 怎么摆放，会影响它们与计算单元的距离、长线走向、电源分布和热热点；sub-array 和 mat 的纵横比例，会影响 aspect ratio 与 floorplan 拼接；local sense amp 和 global mux 的分布，会影响宏是否容易被上层系统整齐集成。因此 SRAM 宏的“内部组织”并不是藏在电路工程师手里的私事，它会直接向上游架构暴露出容量粒度、并发粒度、功耗粒度，甚至 floorplan 边界。常见误解是把 bank 当成一个纯逻辑概念；实际上，bank 往往同时是时序、能耗和版图的共同边界。

从系统和建模角度看，最值得抓住的结论是：SRAM 并不是一个均匀资源，而是一个分层资源。两笔访问如果落到不同 bank、不同 sub-array，成本可能明显不同；同样容量的两个 SRAM，如果一个切成更多局部块，另一个做成更少大块，它们的单次延迟、总吞吐、面积和每次访问能耗都可能走向不同方向。也就是说，“容量相同”远远不足以描述一个 SRAM 宏，阵列组织本身就是一级设计变量。

因此，bank、sub-array、mat 这几个词最重要的不是精确定义，而是它们共同表达了一件事：高效 SRAM 一定是层次化切分的。切分是为了缩短局部访问路径、控制电容负载、支撑并行访问、降低不必要唤醒范围，并把这些收益和额外控制开销重新平衡。后面再看 cache、scratchpad 和 NPU buffer 时，你会发现它们的很多上层组织差异，最终都要落回这套底层切分逻辑。

## 一句话理解

SRAM 阵列之所以要分成 mat、sub-array 和 bank，不是为了命名层级，而是为了把大容量带来的长导线、大电容和并发需求，拆成多个局部可收敛的访问问题。

## 建模启示

在架构模型里，最常见的错误之一是把一块 SRAM 只建成 `capacity + latency + bandwidth` 三个标量。这样做会抹掉阵列组织带来的关键差异，尤其是 bank 冲突、局部并行度和能耗粒度。更稳妥的做法是至少显式保留两级层次：`bank-level parallelism` 和 `intra-bank local access cost`。如果模型还要讨论面积/频率权衡，则最好进一步保留一个近似的 `subarray_granularity`。

一个可用的数据结构草图可以是：

```text
SramHierarchyModel {
  total_capacity_bytes: uint64
  bank_count: int
  subarrays_per_bank: int
  mats_per_subarray: int
  bank_select_cycles: int
  local_decode_cycles: int
  local_sense_cycles: int
  active_energy_per_bank_pJ: float
  active_energy_per_subarray_pJ: float
}
```

如果只关心粗粒度吞吐，可以把 `subarrays_per_bank` 和 `mats_per_subarray` 折叠掉，只保留 `bank_count` 和一个 bank 内固定延迟。但只要你要比较“做更多 bank”还是“做更深 bank”，或者要解释为什么大 buffer 的访问时间随容量恶化，最好把 `bank_select` 和 `local_access` 这两段逻辑分开。一个简化的事件流可以写成：

```text
event BankSelect(array_id, bank_id)
event SubarrayActivate(array_id, bank_id, subarray_id)
event LocalSenseDone(array_id, bank_id, req_id)
```

这里不需要真的模拟 mat 级所有电气过程，但至少要承认：并发能力、访问延迟和单次能耗，都是阵列切分方式的函数，而不是容量的简单函数。
