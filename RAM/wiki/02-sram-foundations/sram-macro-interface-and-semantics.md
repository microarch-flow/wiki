# SRAM 宏接口：怎样正确发起读写

上级：[SRAM 基础](./README.md)

相关：[SRAM 读写时序](./read-write-cycle-timing.md) · [SRAM 端口与代价](./single-port-dual-port-multi-port.md) · [SRAM 选型清单](../10-reference/sram-design-checklist.md)

<p class="ram-problem-lede">一块 SRAM 的容量和位宽，只说明它能存多少数据。要正确使用它，还要知道何时采样、哪些操作可以并发、数据何时有效，以及冲突时有什么保证。</p>

本文从使用者视角看 SRAM 宏的接口。它不要求所有宏采用同一组信号或同一种时序。具体设计应以所选宏的接口说明、工作模式和时序库为准。一次访问内部的电气过程见 [SRAM 读写时序](./read-write-cycle-timing.md)。

## 1. 宏向外提供什么？

SRAM 宏可以看成一个有明确容量和访问规则的存储模块。上游提供地址和操作；写入还需要数据和可能存在的写掩码；读取则在规定时间后提供数据。有些宏还暴露时钟、片选、复位、低功耗或测试信号。

| 需要确认的问题 | 为什么重要？ |
| --- | --- |
| 深度、位宽和地址单位 | 确定地址范围，以及一个地址选中多少数据。 |
| 端口类型和允许的组合 | 确定同一时刻能发起哪些读写。 |
| 采样沿、数据有效时间和接纳间隔 | 确定请求与响应如何对齐。 |
| 写掩码和同地址冲突规则 | 确定哪些位被修改，以及并发访问是否有定义。 |
| 复位、供电与低功耗行为 | 确定数据是否保持、何时可以恢复访问。 |

这些是要查询的项目，不代表每个宏都提供相应功能。下面先看一个公开的具体接口，再用带前提的例子解释它。

## 2. 从一个 64 × 32 bit 的宏读接口

[SRAM22 的引脚说明](https://sram22.com/docs/interface/pin-list/)给出了 `sram22_64x32m4w8`：它是一个同步 **1RW** 宏，包含 64 个 32-bit word。这个宏有 6-bit word 地址和 4-bit 写掩码，每个掩码位控制 8 bit。它的容量为 `64 × 32 / 8 = 256 B`，不包含额外系统封装或控制器。

对该文档描述的接口，假设复位未生效，并满足供电和采样条件：`ce` 为高时，在时钟上升沿采样地址和控制；`we=0` 选择读，`we=1` 选择写。读数据在该沿之后经过时钟到输出延迟才有效。`ce=0` 时不发起访问，输出保持原状态。它的 `rstb` 控制复位状态，但不初始化存储内容或读输出。

这些是该接口的规则，并非所有 SRAM 的约定。其他宏可能使用低有效片选、不同的采样沿或不同的复位行为。使用另一个宏时，须重新核对。

### byte 地址怎样对应 word 地址？

假设系统以 byte 为地址单位，宏从 byte 地址 `B` 开始映射；`B` 按 4 B 对齐。再假设连续的 4 个 byte 对应宏的一个 word，且不做重排。对于范围内的 byte 地址 `A`：

<div class="ram-calculation">
  <span>宏的 word 地址 = ⌊(A − B) / 4⌋</span>
  <span>word 内的 byte 偏移 = (A − B) mod 4</span>
</div>

例如，偏移 `0x14` 和 `0x16` 都属于 word 5，byte 偏移分别是 0 和 2。宏的 `addr` 接收的是 word 地址 5，而不是 byte 地址 `0x14`。系统如何把 byte 偏移映射到数据位，还取决于字节序和 wrapper 的接线；上面的公式不替代这些约定。范围外、跨 word 或未对齐访问也要由系统接口规定如何处理。

### 写掩码改变哪些位？

假设旧 word 为 `0x11223344`，输入数据为 `0xAABBCCDD`。按 SRAM22 的定义，掩码位 0 控制数据位 `[7:0]`，位 1 控制 `[15:8]`，以此类推。如果 `wmask=0b0101`，只更新第 0 和第 2 组 8 bit：

<div class="ram-calculation">
  <span>旧数据：0x11 22 33 44</span>
  <span>写数据：0xAA BB CC DD</span>
  <span>写入后：<strong>0x11 BB 33 DD</strong></span>
</div>

这个例子假设旧 word 已有有效内容，且写操作满足宏的时序条件。掩码为 0 的组保持原值。这里按位编号解释掩码，没有假设系统 byte 地址的字节序。

## 3. 数据有效时间与下一次接纳间隔

一次同步读取至少要分清三个时刻：宏采样请求的边沿、输出数据满足有效条件的时间，以及接收电路采样结果的边沿。它们不一定是同一个时刻。

例如，假设某个同步宏在上升沿 `n` 接纳读请求，输出在随后稳定；接收寄存器在上升沿 `n+1` 采样。这个例子还要求输出到接收端的最大延迟满足建立时间，最小延迟满足保持时间，且两端工作在所假设的时钟关系下。

**读延迟**描述所选起点到结果可见或被采样的时间；**接纳间隔**描述同一资源最早隔多久能再接纳请求。假设某宏允许每个上升沿接纳一笔读，它的接纳间隔就是一拍；这不意味着数据在请求采样的同一瞬间就有效。能否连续接纳、允许怎样的读写组合，都应以目标宏为准。

检查真实时序时，还应确认 PVT、输入转换、输出负载、时钟脉宽及输入 setup/hold 等条件。[OpenRAM 的表征说明](https://github.com/VLSIDA/OpenRAM/blob/stable/docs/source/characterization.md)展示了一个生成时序和功耗模型的流程；该流程的结果只适用于相应生成配置和表征条件。

## 4. 两个端口可以同时做什么？

下面的名称只表示常见的端口能力。实际支持的时钟关系、访问组合和冲突行为仍由宏定义。

| 端口类型 | 常见含义 |
| --- | --- |
| `1RW` | 一套可读或可写的端口；一次端口操作选择读或写。 |
| `1R1W` | 一个只读端口和一个只写端口。 |
| `1RW1R` | 一个可读写端口和一个只读端口。 |
| `2RW` | 两个可读写端口。 |

例如，`1RW1R` 的两个端口都可用于读取；`1R1W` 则有独立的读口和写口。但端口名称本身不能证明任意组合、任意时钟关系或同地址访问都受支持。

假设一个端口写 word X，另一个端口同时读 X，读口可能得到旧值、新值或未定义结果；有的宏禁止该组合。两个写口同时写 X 也可能受限制。**不能替目标宏选择一种结果。**如果接口没有给出所需保证，上层需要避免冲突，或在宏外实现并验证仲裁、等待或转发。只看仿真波形也不能证明未定义的碰撞在硅上安全。

## 5. 宏接口与系统接口在哪里分界？

一个系统接口可能有请求有效、接纳、响应有效和背压等信号。SRAM 宏未必直接提供这些信号。中间的 wrapper 或控制逻辑可能需要排队、仲裁、转换地址和掩码，并记录哪个请求对应后续读数据。[ESP 的 SRAM 集成说明](https://esp.cs.columbia.edu/docs/asic_tech_integration/asic_tech_integration-guide/)展示了用 wrapper 对接不同技术宏的做法。

例如，若宏输出在未读时保持旧值，wrapper 不能仅凭 `dout` 上有数据，就认定当前周期产生了新响应；它还需要按照接口时序跟踪此前已接纳的读请求。写操作如果没有完成信号，也不能凭空假设有 `ack`；写何时对后续访问可见，要按宏和 wrapper 的契约确定。

## 一句话理解

SRAM 宏提供的不只是容量，而是一组有条件的读写契约。使用者要同时确认地址、端口、时序、写掩码和冲突规则。

## 建模启示

先记录宏本身承诺什么，再记录 wrapper 增加了什么：

1. **宏配置**：深度、位宽、地址单位、端口能力、掩码粒度和允许的操作组合。
2. **时间边界**：请求采样、读数据可见、写入可见和下一次接纳的条件。
3. **状态与冲突**：已接纳的请求、端口占用、同地址碰撞及未定义行为。
4. **wrapper 行为**：地址转换、仲裁、排队、响应标记和背压；只保留实际存在的功能。

检查模型时，可以用一个完整 word 写入后，再做不同掩码的部分写入并读回；还要检查未选中、复位和接口允许或禁止的冲突。行为模型能检查约定的功能，不能单独证明电路时序、噪声裕量或实际芯片性能。
