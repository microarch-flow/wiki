# HBM、2.5D 与 3D 集成

上级：[05 封装、制造与成本](./README.md)

相关：[DRAM 家族对照：DDR / LPDDR / GDDR / HBM](../03-ddr-protocol-families/ddr-lpddr-gddr-hbm-comparison.md)

## 结论先说

现代 HBM 系统通常会把：

- `HBM stack`
- `计算 die`

一起放进同一个先进封装系统里，通过极短、极宽的互连完成高带宽连接。

但这里其实有三层不同概念，最好一开始就拆开：

- `HBM stack`：内存芯片自身的多层堆叠结构
- `HBM + compute die` 的同封装集成：当前主流通常是 `2.5D`
- 更广义的系统级 `3D integration`：计算 die 与内存 die 直接上下堆叠

## HBM stack 里有什么

典型 HBM stack 可概括为：

- 多层 DRAM die
- 垂直互连结构，例如 TSV
- 底部承接与分配信号/电源的 base 或 logic die

其目标是把大量 I/O 在很短距离内组织起来。

## 为什么要走 2.5D

如果仍然把 HBM 当作远距离板级颗粒来连，很多优势会立刻消失：

- 线太长
- 功耗太高
- 带宽密度不够
- I/O 数量难以落地

所以 HBM 需要借助中介层或同封装近距互连，把“远距离高速电链路”改造成“近距离超宽链路”。

## 2.5D 和 3D 在这里怎么区分

### 2.5D

通常指：

- HBM stack 和计算 die 并排放置
- 通过 silicon interposer 或类似中介层互连

这是目前高端 GPU / AI 加速器中最典型的 HBM 集成方式。

### 3D

通常指：

- 一个 die 直接堆在另一个 die 上方
- 更强调垂直方向的异构集成

对内存体系来说，HBM stack 本身已经包含 3D 堆叠；但整个系统是否属于系统级 3D 集成，还要看计算 die 与内存之间是不是直接上下堆叠。

## 先进封装在这里的真实价值

先进封装在 HBM 场景中的作用，不是“更高级的封装名词”，而是直接带来：

- 更短互连距离
- 更高 I/O 密度
- 更低每比特能耗
- 更高总带宽

所以 HBM 和先进封装不是偶然绑定，而是物理上互相成就。

不过常见表述也要收紧一点：当前主流高端 GPU / AI 加速器里，HBM 通常与 2.5D 先进封装强绑定；这不等于所有高带宽系统都会走同一条集成路线。

## 一句话理解

`HBM 的本质不是高频，而是通过堆叠和先进封装，把内存接口变成“超宽、超近、超密”的封装级互连。`
