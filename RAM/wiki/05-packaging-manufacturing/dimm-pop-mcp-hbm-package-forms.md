## 为什么要单独区分封装形态

很多人会把“内存类型”和“封装形态”混为一体，但两者不是一回事。

更准确的关系是：

- 内存类型决定基本技术路线
- 封装形态决定它如何落到系统里

## DIMM

DIMM 是最典型的通用主存模块形态。

特点：

- 可插拔
- 容量扩展方便
- 与 CPU 存在板级和插槽级距离

它适合服务器和 PC，但不适合追求极短距离和极致每比特能耗的场景。

## PoP

PoP 是 `Package on Package`。

直觉上可以理解为：

- SoC 和内存封装上下叠放
- 互连距离比板级更短
- 更适合移动设备

它服务的重点不是极限带宽，而是集成紧凑与功耗效率。

## MCP

MCP 是 `Multi-Chip Package`。

核心特征是：

- 多颗芯片被放进同一个封装中
- 目的是缩小系统面积、简化组装或提升集成度

它可以出现在多种产品路线里，不专属于某一种内存技术。

## HBM Stack + Advanced Package

HBM 不是普通“封装得更紧”的 DRAM，而是：

- 多层 DRAM stack
- 借助 TSV 形成垂直互连
- 再与计算 die 一起放入先进封装系统

这类形态更接近“封装即架构”的思路。

## 一个实用判断法

如果你看到某种封装方案，先问：

- 它是在解决容量扩展，还是在解决带宽和能耗
- 它允许多长的互连距离
- 它的代价主要体现在主板、封装还是良率

这样更容易把 DIMM、PoP、MCP、HBM 放到同一张图里理解。

## 一句话理解

`封装形态决定内存离计算有多近、接口能做多宽、代价落在哪一层，因此它本身就是内存系统设计变量。`
