## 这页在回答什么问题

看一篇 DMA 论文、白皮书或产品文档时，应该带着哪些问题去读，才能快速抓住真正有价值的部分，而不是停留在 feature list 或 marketing number 上。

## 必读问题

1. DMA 在这个系统里的主要角色是什么，是 I/O 辅助、异步数据通路，还是供数骨架。
2. 它搬的是哪几类路径，这些路径的完成语义分别是什么。
3. 任务是如何描述和提交的，是寄存器、descriptor、ring 还是 command queue。
4. burst、outstanding 和 completion 是如何组织的。
5. 一致性、地址翻译、隔离和 context 是如何处理的。
6. 真正的瓶颈更可能在 DMA、本地端点、NoC、外部内存，还是软件 completion 路径。
7. 它和同类方案相比，最关键的差异在哪里，是路径、完成语义、微架构能力还是 observability。

## 进阶问题

如果资料足够详细，再继续追这些问题：

1. 它区分了哪些完成阶段，哪些阶段被文档混写成同一个 `done`。
2. 它暴露了哪些 counter / histogram / phase state。
3. 它最值得建模的最小状态集合是什么。
4. 如果只关心性能，哪些细节可以折叠；如果关心功能正确性，哪些细节不能折叠。

## 为什么这套问题有效

因为它们强迫你先把 DMA 放回系统画像里，再去看功能与实现。这样读文档时，你会更快识别出“哪些 feature 是关键，哪些只是附属”，也更容易发现文档里真正没有说清的边界。

## 常见误解

常见误解：`先看支持多少带宽和多少通道最有效率`。实际上这通常是最容易把人带偏的入口。

常见误解：`只要回答了前几条功能问题，就足够判断方案`。实际上 completion 语义、系统接入和 observability 经常才是成败关键。

## 一句话理解

读 DMA 资料时，最有价值的问题永远不是“它有多少 feature”，而是“它如何把复杂系统里的数据移动组织起来，并让谁在什么时候真正继续前进”。
