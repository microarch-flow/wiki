# 自回归生成：从条件概率到下一个 token

上级：[专题导读](README.md)

自回归模型把联合分布分解为有序的条件概率。token 可以表示文本、图像离散编码或动作编码；生成顺序与 token 的物理含义是两件事。

## 模型学习什么

给定序列 $x_1,\ldots,x_T$：

$$
p_\theta(x_{1:T})=\prod_{t=1}^{T}p_\theta(x_t\mid x_{<t})
$$

常用训练目标是这些条件概率的负对数和。训练时目标序列已知，可以把多个位置一起送入模型，用因果掩码阻止当前位置读取后续目标。并行计算多个训练位置，不改变概率分解中的条件关系。

构造例：训练序列是“红 杯 在 桌上”。预测“在”的位置只能使用前面的上下文，不能读取“桌上”后再声称自己预测了未来。

## 一次生成的步骤

1. tokenizer 将输入编码为 token ID；模型读取前缀。
2. 模型输出词表上的 logits，softmax 给出下一 token 分布。
3. 解码策略选择一个 token，将它追加到上下文。
4. 更新所需状态，重复计算，直到结束标记或长度上限。

贪心选择最大概率项；采样从分布中选择。温度与截断策略会改变输出分布。模型定义概率，解码策略定义怎样从概率得到实际输出，两者应分开记录。

## 因果掩码与 KV cache

因果掩码约束可见信息。KV cache 保存已经计算的键和值，避免每次重新计算全部历史位置。缓存是一种执行优化，并非自回归概率分解的定义。

对标准增量生成，下一 token 依赖上一轮选择，单条序列存在串行依赖。但每轮内部的矩阵、head 和不同请求仍有并行机会。前缀处理与增量生成的执行细节见[推理阶段](../../inference-runtime/topics/01-prefill-decode.md)；该系列仍标有草稿状态，引用其数值时需核查前提。

## 训练与生成之间的差别

训练常使用真实历史 token，生成则使用模型自己的输出。一次错误可能改变后续上下文。低平均负对数似然不直接保证长序列任务成功，也不保证文本事实正确。

自回归适合明确有序的离散输出。连续动作也可以先离散化，但词表分辨率、序列长度和误差会成为新设计条件。与[扩散](diffusion-models.md)、[Flow Matching](flow-matching.md)比较时，必须固定输出对象和质量目标。
