# 视觉语言模型：图像表示怎样进入语言计算

上级：[专题导读](README.md)

视觉语言模型（VLM）关联视觉与语言。输出可以是匹配分数、共享表示或生成文本；能处理两种输入，不代表所有模型都以同一种方式融合，也不代表它能输出可执行动作。

## 三种常见接口

| 方式 | 计算路径 | 适合解释的问题 |
| --- | --- | --- |
| 双编码器对齐 | 图像、文本分别编码，再比较表示 | 图文检索与零样本分类 |
| 视觉投影后接入语言模型 | 图像编码器 → projector → 视觉 token → LLM | 视觉问答与对话 |
| 交叉注意力 | 语言侧 query 读取视觉特征 | 语言生成怎样使用外部视觉信息 |

CLIP 是第一类代表；LLaVA 将视觉编码器与语言模型连接；Flamingo 使用跨模态交叉注意力。实际模型可以组合这些设计。

## 视觉 token 从哪里来

构造例：一张 $224\times224$ 图像按 $16\times16$ patch 划分，得到 196 个空间位置。视觉编码器可以保留、合并或重采样这些位置，再通过适配模块改变特征维度。是否加入特殊 token、是否使用切图与多尺度，必须查具体模型。

两张图不一定只使最终 token 数翻倍。预处理可能改变裁剪数，适配器也可能固定输出 token 数。因此应沿“图像 → 裁剪 → patch → 适配器输出”逐级记录形状。

## 对齐训练与指令学习

双编码器可以用配对图文的对比目标建立共同空间。生成式 VLM 则可通过图像条件下的文本预测训练接口，并在视觉指令数据上进一步训练。冻结视觉编码器、冻结语言模型或联合更新，分别改变训练参数与计算图。

视觉编码器输出的特征不是“已经翻译好的语言事实”。投影和后续模型需要学习怎样使用它。图像细节在缩放、裁剪或压缩中丢失后，语言模型可能无法恢复。

## 从理解到行动还缺什么

VLM 输出“杯子在左边”，与策略输出末端位移之间还缺坐标定义、动作表示、本体状态与执行约束。VLA 增加动作接口及相应训练，见 [VLA 基础](../04-robotics-and-vla/vla-fundamentals.md)。

评估时应分别检查对象与空间理解、OCR、跨图推理和任务成功。流畅的文字不证明视觉依据正确。机器人还需要闭环评估，不能用视觉问答分数代替操作成功率。

## 工作负载延伸

分开统计视觉编码、适配器、语言侧前缀处理和输出生成。检索式双编码器不需要文本 decode；生成式 VLM 可能需要。有关缓存分配与批处理的实现留给推理运行时，模型侧接口见[语言模型](language-models.md)。
