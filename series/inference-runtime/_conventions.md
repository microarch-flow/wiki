# 写作规范 / Conventions

> 本文件约束本 wiki 所有条目的格式与风格,改规范前先在此文件讨论并记录,不在各篇里临时发明格式。

## 1. 读者视角(贯穿全篇)

本 wiki 的预设读者是**系统软件架构师 / 成本模型构建者**,而非通用入门读者。因此每一篇都默认带两条主线:

- **量化主线**:尽量把机制落到可计算的量上——roofline(compute-bound vs memory-bound)、算术强度(arithmetic intensity)、KV cache 字节数、HBM/链路带宽、Σseq_len 流量、固定成本摊薄等。
- **架构建模接口主线**:显式标注「哪些量是可扫的设计参数」「哪个公式换一档链路带宽(HBM ↔ NVLink ↔ PCIe/NVMe)即可复用」「哪些判定喂给 SLA 模型」。

硬件/编译器侧的类比可点到为止(假定读者熟);**软件机制要讲透**。

## 2. 每篇统一结构

每个 topic 文件按以下五段组织,标题层级固定为 `##`:

```
# <序号> <标题(中文)> / <English Title>

> 一句话定位:这篇解决什么问题 / 在栈里的位置。

## 概念 (Concept)
要解决的问题、名词定义、与上一篇的衔接。

## 机制 (Mechanism)
软件上具体怎么做。数据结构、控制流、不变量(invariant)。

## 量化与公式 (Quantification)
符号定义 + 量纲 + 关键公式;至少一个代入具体数字的算例。

## 与架构建模的接口 (Modeling Interface)
- 可扫设计参数(design knobs):…
- 可复用/可换档的公式:…
- 喂给仿真器 / SLA 判定的量:…

## 延伸阅读 (References)
交叉链接其它条目 + 外部来源(标注是否官方)。
```

长主题拆成多篇,用「概念 → 机制」边界切分,互相交叉链接,不要堆成巨型文件。单篇目标:一次能读完的密度。

## 3. 术语 (Terminology)

- 术语**首次出现**给出「中文(English, 缩写)」三件套,并链接到术语表:`[KV 缓存](glossary.md#kv-cache)`。同篇内再次出现可只用中文或缩写。
- 不确定的缩写**先确认再用**,不假设;拿不准的写成 `TODO(确认): …`。
- 术语表 `glossary.md` 是唯一定义源(single source of truth)。若某篇需要更精确的局部定义,在该篇展开,但不与术语表冲突;冲突时以讨论后更新的术语表为准。

## 4. 公式 (Math)

- 行内公式用 `$...$`,独立公式用 `$$...$$`(GitHub Markdown 已支持;KaTeX/MathJax 渲染器通用)。
- **每个符号给定义和量纲**。例:`$b$ = batch size(无量纲);`$s$ = 序列长度 [token];`$d_\text{model}$` = 隐藏维 [无量纲];带宽 `$BW$` [bytes/s]。
- 关键公式后给一个**代入具体数字的算例**,算例里写清单位与数量级。
- 约定常用符号表(各篇沿用,避免一符多义):

  | 符号 | 含义 | 量纲 |
  |---|---|---|
  | $b$ | batch size / 并发请求数 | — |
  | $s$ | 序列长度(上下文 token 数) | token |
  | $L$ | 层数 (layers) | — |
  | $h$ | 注意力头数 (query heads) | — |
  | $h_{kv}$ | KV 头数 (GQA/MQA) | — |
  | $d_h$ | 每头维度 (head dim) | — |
  | $d$ | 隐藏维 $=h\cdot d_h$ (hidden size) | — |
  | $P$ | 参数量 (params) | — |
  | $p$ | 每元素字节数 (precision) | byte |
  | $BW$ | 带宽 (HBM/链路) | byte/s |
  | $C$ | 算力 (compute) | FLOP/s |

  新增符号在该篇「量化与公式」段首次声明。

## 5. 数字纪律 (Numbers)

- **不编造数字。** 任何具体硬件/模型参数标注其性质:
  - `【精确值】` 来自官方规格/论文。
  - `【典型量级】` 业界常见档位,用于估算,非某型号精确值。
  - `TODO(核实): …` 拿不准、需联网或查官方来源核对的,留标记,不蒙混。
- 引用外部来源标注是否**官方**(厂商规格书/论文 vs 二手博客)。

## 6. 交叉引用与状态 (Linking & Status)

- 条目间用相对链接:`[分页 KV](05-paged-kv-cache.md)`;术语表锚点:`[…](glossary.md#anchor)`。
- 每篇顶部 front-matter 注明状态,README 索引同步:
  - `状态:草稿` / `状态:已审阅`(经你 review 后改)。
- README 是唯一的「阅读顺序 + 状态」总表;改条目状态时同步更新 README。

## 7. 语言

正文中文为主;术语、API、论文名、代码标识符保留英文原文。表达偏好:直接、分析密度高、结构化;少铺垫,多公式与表格。
