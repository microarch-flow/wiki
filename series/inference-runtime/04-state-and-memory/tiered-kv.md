# KV 分层存储：迁移、恢复与淘汰

上级：[本专题导读](README.md)

KV 分层存储是在不同存储位置之间保留或迁移请求状态。它可以服务于活跃请求卸载，也可以服务于冷前缀复用；两者的恢复时限和成本不同。

## 先区分两种对象

| 对象 | 为什么离开设备内存 | 何时需要恢复 |
|---|---|---|
| 暂停请求的活跃 KV | 为其他执行释放容量 | 该请求恢复计算之前 |
| 可复用的冷前缀 | 延长缓存保留范围 | 新请求命中并准备使用之前 |

活跃请求卸载常直接影响等待或 ITL；冷前缀缓存失效可以回退到重算输入。两者都不等于 PD 分离：PD 分离迁移执行阶段的所有权，分层存储迁移状态所在位置。

## 迁移必须有明确的完成状态

一个可行的状态过程是：设备驻留 → 复制中 → 后备副本有效 → 设备块可回收。恢复时反向执行，并在目标数据就绪后才允许内核读取。

复制期间源块需被固定，避免内容变化或重新分配。源数据不可变时容易复用；仍在追加的尾块需要快照、版本或其他一致性策略。取消或复制失败也要解除相应引用。

如果后备存储已有有效副本，淘汰设备副本可能无需重新写出；如果它不存在，必须计入首次写出成本。

## 搬运与重算怎样比较

设需恢复的数据为 $D$ byte，路径有效带宽为 $BW_{\rm eff}$，建立与协议成本为 $\alpha$，则一次恢复可估为：

$$T_{\rm restore}\approx\alpha+D/BW_{\rm eff}+T_{\rm layout}+T_{\rm wait}$$

若请求暂停前还需写出，应另算卸载成本。多跳路径分别经过 HBM、主机内存、网络或存储设备；它们不一定能完全流水，也不共享一个统一带宽。

构造例子：恢复 625 MiB，即 655.36 MB。在假定的 64 GB/s 有效载荷带宽下，单向纯传输项为 10.24 ms。若先写出再读回，两方向都不能漏算。

比较对象应是同一请求的恢复路径：读取后备 KV，或者从可用前缀重算缺失状态。重算还包含 Attention 与资源竞争，不能仅靠“空闲算力很多”认定其成本为零。

## 热冷分类与预取

优先保留近期会用到、恢复昂贵或复用高的状态是一种策略。预取只有在预测足够准确、提前量足够且容量允许时，才可能隐藏部分等待。

错误预取会占用带宽和设备块，甚至挤出正在服务的状态。报告收益时应同时给出命中率、无用传输、在途字节、恢复等待和设备占用。

SSD 扩展容量不代表可以直接按 SSD 带宽估算整轮 Decode；执行器究竟按块恢复、按层流式读取还是重算，需要单独描述。
