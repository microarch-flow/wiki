# 运行时状态与完整内存预算

上级：[本专题导读](README.md)

“权重能放进显存”只是模型可运行的一个条件。服务还需要请求状态、临时工作区、执行图缓冲区和通信资源。容量不足经常发生在这些部分同时达到峰值时。

## 按所有者和生命周期分类

| 状态 | 所有者与生命周期 | 容量变化 |
|---|---|---|
| 权重与常量 | 模型实例，通常跨请求复用 | 随模型、精度、切分与适配器变化 |
| KV 或循环状态 | 请求；缓存可保留共享副本 | 随模型结构、已处理位置与保留策略变化 |
| 激活与工作区 | 算子或执行计划 | 随本轮 token 数、形状和内核变化 |
| Graph 捕获与固定缓冲区 | 已准备的执行形状 | 随捕获范围和桶数变化 |
| 通信与传输缓冲区 | 并行组或传输任务 | 随并行布局与在途数据变化 |
| 请求元数据与输出缓冲 | 主机或设备上的请求状态 | 随并发、词表、输出和客户端速度变化 |

HBM 是封装系统中的高带宽堆叠 DRAM，不是计算芯片上的 SRAM。片上缓存与 HBM 的容量和流量应分开讨论。

## 单设备预算先于聚合预算

对设备 $r$，可以写：

$$M_r=W_r+K_r+A_r+G_r+C_r+O_r$$

各项分别表示权重、请求状态、激活／工作区、图与固定缓冲、通信、其他开销，单位均为 byte。实际应检查同一时刻的总量，而不是把所有阶段的独立峰值机械相加。

可运行条件是每个设备的实际峰值都不超过其可用预算。总显存足够仍可能因一个 rank 上的复制、层数或专家负载不均而失败。

主机内存也需要独立预算。请求排队、分词、卸载 KV、文本缓冲和加载中间副本都可能消耗主机内存。

## 不同模型状态不能共用一条公式

对标准全注意力，KV 有效载荷可按层和请求累计。若层 $l$ 的每位置状态为 $k_l$ byte，保留位置数为 $n_{i,l}$：

$$K_{\rm payload}=\sum_i\sum_l n_{i,l}k_l$$

这条写法允许不同层采用不同布局：

- 全注意力层通常保留全部有效历史位置。
- 滑动窗口层只需要其算法规定的窗口及实现所需附加状态；不能丢掉其他全注意力层的历史。
- MLA 缓存的压缩状态与标准 GQA 的完整 K/V 不同，需按具体实现计数。
- 循环或状态空间层保存其递推状态，不能按上下文长度直接套标准 KV 公式。

混合模型可能有多个状态池和不同块粒度。vLLM 的混合 KV 管理设计也按不同注意力类型和缓存组处理这些差异。

## 一个容量与增长的例子

假设某设备的可用预算为 24 GiB，权重 12 GiB，其他同时常驻与峰值工作区合计 4 GiB，则剩余 KV 预算为 8 GiB。若每条请求当前 KV 为 1 GiB，八条只能说明“当前有效载荷刚好装下”。

如果它们下一轮还要增长，或者需要块尾部、写时复制和暂存空间，就不能无条件接纳八条。调度器可以预留增长空间，限制本轮分配，或在压力出现时抢占；这些是不同策略，需分别评价。

平均长度适合估算期望容量，但不能证明最坏情况不会溢出。准入可以基于保守上限，也可允许受控超额承诺并配套恢复机制。

## 测量时避免重复计算

框架的 allocated、reserved 与设备总使用量可能属于不同边界。若一个缓存池已包含在 reserved 中，再把缓存池容量相加，会重复计数。共享前缀也应按实际分配块计一次，再另记引用关系。

建议按时间采样各池容量、已用块、活跃引用、工作区和峰值，记录触发峰值的批组成。后续的[分页](06-paged-kv-cache.md)、[前缀缓存](07-radix-prefix-reuse.md)和[卸载](tiered-kv.md)都应回到同一预算表。
