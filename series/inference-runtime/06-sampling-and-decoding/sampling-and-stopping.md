# 从 logits 到 token：采样、停止与输出

上级：[本专题导读](README.md)

模型执行通常输出 logits，而不是最终文本。采样器把 logits 变成 token，停止逻辑决定是否继续，增量解码器再把 token 变成可返回的文本。这些步骤都属于请求状态的一部分。

## 从分数到概率

设词表大小为 $V$，分数为 $z_v$。温度 $T>0$ 时，基础分布为：

$$p(v)=\frac{\exp(z_v/T)}{\sum_{u=1}^{V}\exp(z_u/T)}$$

实现通常先减去最大分数以提高数值稳定性。较小温度使概率更集中，但不等于无条件提高答案质量。贪心解码直接选择最大分数 token，应作为独立分支处理，不能在公式中令 $T=0$。

Top-k 保留分数最高的 k 个候选。Top-p 按概率降序保留累计概率达到阈值的最小候选集合，并重新归一化。平分、边界比较和最小保留数应由实现定义。

## 处理顺序会改变最终分布

重复惩罚、禁止 token、语法掩码、温度和候选截断的组合通常不可交换。运行时应把最终采样管线作为明确配置。

构造分数相同的三个 token，其中一个被语法禁止。如果先 top-k=1 恰好只留下被禁止的 token，再掩码可能得到空集合；先施加语法约束则仍有合法候选。因此后端必须定义处理顺序及空候选的错误处理。

[约束解码](13-constrained-decoding.md)会改变允许集合；[推测解码](09-speculative-decoding.md)的分布保证也必须针对同一个最终目标分布，不能仅针对模型原始 softmax。

## 采样状态属于请求

随机数生成器状态、已生成历史和惩罚统计需要随请求保存。不同批组成可能改变随机数消耗顺序；浮点归约也可能改变临界候选。因此“设置相同 seed”不自动保证跨实现、跨设备或跨批完全相同。

若需要复现，应记录模型修订、软件与内核版本、生成配置、输入、种子以及批执行相关设置。贪心一致、采样分布一致和逐 token 完全复现，是不同的验证目标。

## 停止不只有 EOS

常见结束条件包括 EOS、达到输出上限、命中停止字符串、外部取消、截止时间和执行错误。服务应保留结束原因，而不是把它们都标成正常完成。

停止字符串可能跨多个 token；判断与返回策略需要协调。例如生成了停止字符串的一部分时，可以暂存这部分文本，待确认后再决定是否发送。输出缓冲会改变客户端观测的 TTFT 和 chunk 间隔。

生成达到上限时，即使每一步都满足语法前缀约束，最终文本也可能尚未闭合。停止逻辑必须与约束状态共同判断“完整合法结束”。

## Token、文本与流式输出

一个 token 可以覆盖多个字符，某些分词表示还涉及字节片段。不能逐 token 独立解码后直接假定拼接等于完整增量解码。执行器应保留必要的解码状态，避免无效字符或重复文本。

输出通道要记录已经发送的文本与仍在缓冲的文本。停止时可以按协议处理尚未发送的片段，已经发送的内容无法撤回。慢客户端的限额、等待和超时策略见[超时与背压](../08-serving-lifecycle/request-resource-lifecycle.md#超时与背压)。
