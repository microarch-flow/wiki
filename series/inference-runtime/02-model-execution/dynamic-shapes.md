# 动态形状、数据布局与执行计划

上级：[本专题导读](README.md)

动态形状是输入和状态尺寸随请求变化。批处理策略决定本轮有哪些请求；布局决定这些请求怎样表示为张量；执行计划决定采用哪些内核。这三层相关，但不能互相替代。

## 请求数与 token 数不是同一维

假设本轮有两条 Prefill，请求长度为 3、5，隐藏维度为 $d$。矩形表示可用形状 $[2,5,d]$，其中两行位置是 padding；打包表示则使用 $[8,d]$，再用边界数组 `[0,3,8]` 标明每条序列的起止位置。

边界信息防止第二条序列读到第一条的状态。因果位置、KV 块表和每条请求的历史长度，也必须随布局传给内核。把多个请求首尾相接并直接做一次无隔离的注意力，会改变模型语义。

## Padding 与 packed 的真实取舍

对等头数、完整方形注意力的简化工作量，若实现连 padding 区域也执行，矩形批近似为：

$$F_{\rm padded}\propto B_{\rm req}s_{\max}^2,\qquad
F_{\rm packed}\propto\sum_i s_i^2$$

上面的长度 3、5 示例对应 50 与 34 个查询—键位置对。这里没有把不同请求之间的无效交叉注意力算成有效基线。因果裁剪与专用内核还会改变常数。

Packed 可以减少无用位置，但需要边界元数据和变长内核。Padding 可以提供规则形状，并提高某些内核或 Graph replay 的复用。选择依据是总执行成本，不是“是否存在 padding”这个单一指标。

## 形状分桶与优化范围

若常见本轮 token 数为 21、29、31，可以统一进入容量 32 的执行桶，也可以分别执行。前者增加空置位置，却减少计划切换。示例只说明权衡，不表示 32 是通用最优值。

有的编译后端允许动态维，但仍需要支持范围。TensorRT 的优化 profile 使用 MIN、OPT、MAX 形状：范围决定合法输入，OPT 影响优化选择。超出范围不能假装是同一已验证计划。

CUDA Graph 重放还涉及缓冲区地址、操作拓扑和动态参数。运行时可以准备多个捕获形状，或对部分图捕获。图断点、混合 Prefill/Decode、推测长度和不同 Attention 后端，都可能改变可复用范围。

## 计划选择必须保留语义

一个最小选择过程是：先检查输入是否合法；再根据 token 数、查询长度、KV 长度、数据类型和设备选择计划；最后准备对应布局与掩码。找不到计划时，应明确回退、重新编译或拒绝。

正确性检查应比较同一组真实 token 在不同布局下的有效位置输出。浮点归约顺序可能产生小误差，容差应按精度和算法定义；padding 位置不能参与采样或污染 KV。

内存也会变化：为多个桶准备固定缓冲区、保留编译工作区或捕获池，都要计入[完整内存预算](../04-state-and-memory/runtime-state.md)。
