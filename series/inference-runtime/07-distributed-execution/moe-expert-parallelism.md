# MoE 专家并行：路由、派发与负载不均

上级：[本专题导读](README.md)

MoE 在每个位置选择部分专家执行。专家并行将专家分布到不同 rank，因此一次层执行既包含计算，也包含按路由结果产生的数据派发与回收。

## 路由结果怎样变成执行工作

设本轮有 $N$ 个 token、$E$ 个专家，每个 token 选择 $k$ 个专家。忽略丢弃与重路由时，共有 $kN$ 份 token—专家分配，但每个专家收到的份数不一定相同。

一个典型过程是：计算路由分数 → 选专家并分组 → 将隐藏状态派发到专家所在 rank → 执行各专家矩阵乘 → 将结果送回并按权重合并。共享专家与其他稠密部分仍需另外计算。

输出必须恢复原 token 顺序。派发元数据要保存原位置、专家选择和合并权重。

## 一个不均衡的例子

构造 $N=8,E=4,k=2$，四个专家收到的分配数为 `[8,4,3,1]`，总数为 16。平均为 4，但最忙专家为 8。

若四专家各在一个 rank，且每份工作成本相同、没有重叠或其他负载，则最忙 rank 的工作量是平均的两倍。用平均 token 数预测完成时间会低估等待。

真实成本还受专家矩阵形状和小批效率影响。一个只有一行输入的专家，与一块大 GEMM 的单位 token 成本可能不同。

## 通信量从路由矩阵得到

定义 $T_{ij}$ 为来源 rank i 发给目标 rank j 的分配数。若每份隐藏向量维度为 d、元素字节为 p，则一次派发的远端有效载荷约为：

$$D_{\rm dispatch}=dp\sum_{i\ne j}T_{ij}$$

相同布局下，合并回传还需相应有效载荷；元数据、打包、协议和复制另算。落在本地专家的份数不应计成跨网络传输。

因此 all-to-all 的平均总字节不足以解释热点。链路和 rank 负载分析见[MoE 派发与合并](../../interconnect/SCALEUP/05-workloads-and-performance/moe-dispatch-and-combine.md)。

## 容量限制与负载平衡的代价

专家容量上限可能要求溢出 token 丢弃、改路或等待。它们会影响语义或延迟，必须按模型和服务实现说明。训练中使用的负载平衡损失也不保证每次推理批都均匀。

复制热门专家可以分担负载，但增加权重容量，并要求路由与副本选择协同。迁移专家或改变布局还有加载和同步成本，不能视为零成本的即时均衡。

## EP 与其他并行方式的组合

专家内部仍可使用 TP；不同层可以使用 PP；请求也可能分布在数据并行组。实际设备数和通信组由 rank 布局决定，不一定存在独立的 EP 乘法维度。

推理工作量不能只用“总参数量乘激活比例”概括：路由、共享专家、注意力、元数据与通信仍然存在。应同时给出总权重、激活专家计算和每 rank 峰值。
