# 七款数据中心 AI 加速器架构对照

<div class="chip-legacy-anchors" aria-hidden="true"><span id="云端-ai-推理-训练芯片架构横向对比报告"></span></div>

这七款芯片都在处理张量，主要取舍出现在三个地方。数据存在哪里，哪个单元负责推进计算，跨芯片时还要搬哪些数据。本文沿用 2026 年 6 月原报告的样本，比较 AWS Trainium2、Cerebras WSE-3、Graphcore GC200、Groq 第一代 TSP、Meta MTIA 2i、Microsoft Maia 100 和 SambaNova SN40L。数据来自规格、原始论文和厂商资料。每项实验结论都对应它的测试边界。

## 先找出要比较的对象

阅读时先固定工作负载，例如矩阵乘、推荐模型的 embedding 查表，或自回归解码。然后确定比较的是单个计算单元、单芯片、节点还是整个服务。选择芯片时，先验证模型和工作区的容量，再估算各层传输量和计算量。实际吞吐和分位时延需要同口径测量。系列的其他案例入口见导读。 [芯片架构实例](README.md)

## 单设备资源对照

| 对象 | 计算组织 | 数据存放 |
| --- | --- | --- |
| AWS Trainium2 | 8 个 NeuronCore-v3，每核有矩阵、向量、标量和可编程引擎 | 每个物理核有 28 MiB SBUF 和 2 MiB PSUM。芯片配置 96 GiB HBM。 |
| Cerebras WSE-3 | 90 万个计算核与晶圆内二维互连 | 晶圆内合计 44 GB SRAM。CS-3 的部分训练配置可由外部 MemoryX 提供权重。 |
| Graphcore GC200 | 1472 个独立 tile，按 BSP 协调计算和交换 | 每 tile 624 KiB SRAM。厂商演讲两页分别给出合计 896 MiB 和 897 MiB。外部 Streaming Memory 按系统配置。 |
| Groq 第一代 TSP | 矩阵、向量、存储和重排按功能切片布置 | 220 MiB 片上 SRAM。 |
| Meta MTIA 2i | 8 × 8 PE，PE 内由命令处理器协调专用引擎 | 每 PE 384 KB 局部存储，另有 256 MB 共享 SRAM 和 64–128 GB LPDDR5。 |
| Microsoft Maia 100 | 张量单元、向量处理器、拷贝引擎和异步命令队列 | 片上分级暂存区，64 GB HBM2E。厂商列出的 HBM 带宽为 1.8 TB/s。 |
| SambaNova SN40L | 可配置计算单元、存储单元和数据流网络 | 论文以单 RDU 计，520 MiB 片上 SRAM、64 GiB HBM、最高 1.5 TiB DDR。 |

## 架构取舍

同一个“矩阵乘、激活、输出”子图可以用来读下列机制。先检查矩阵块在哪累加，再找出中间结果交接的位置。即使输入形状相同，编译器安排、资源占用和通信边界也可能不同。

<div class="chip-legacy-anchors" aria-hidden="true"><span id="21-计算组织从一块大阵列到一片众核再到可重构数据流"></span></div>

### 计算资源怎样分配

Trainium2、MTIA 2i 和 Maia 100 都把矩阵计算交给专用单元，但计算引擎的控制边界和缓冲组织各有设计。Graphcore 和 Cerebras 把工作拆到许多独立的处理单元。Groq 把不同功能放在切片中，操作数沿流移动。SN40L 则给算子与中间缓冲分配物理资源，使多个阶段能在片上流水推进。实际利用率取决于张量形状和映射。 [各型号工作路径](#按产品查阅)

<div class="chip-legacy-anchors" aria-hidden="true"><span id="22-存储哲学sram-即主存-vs-hbm-即主存-vs-三层金字塔"></span></div>

### 权重和中间结果放在哪里

Trainium2 和 Maia 100 的设备内存使用 HBM。片上暂存区承接频繁访问的工作集。MTIA 2i 用共享 SRAM 和 LPDDR5 配合推荐推理。Groq TSP 与 WSE-3 的工作数据主要放在片上 SRAM，超出容量后要按各自的系统方案组织参数。SN40L 在片上 SRAM、HBM 和 DDR 之间增加了软件管理的模型放置与切换选择。应分别核对容量、实际传输字节与可用带宽。 [各型号存储资料](#一手资料与原始记录)

<div class="chip-legacy-anchors" aria-hidden="true"><span id="23-执行时序动态运行时-vs-编译期钉死program-model-谱系"></span><span id="24-数据流-vs-控制流数据触发计算走了多远"></span><span id="26-编程模型与软件栈编译器到底背多重"></span></div>

### 编译期安排和运行时触发怎样分工

| 对象 | 编译或程序负责 | 运行时执行条件 |
| --- | --- | --- |
| Trainium2、Maia 100、MTIA 2i | 安排张量、命令和依赖。 | 相应引擎或命令处理器在依赖满足后推进。具体同步机制按产品区分。 |
| Graphcore GC200 | 放置 tile 任务，编排计算及显式交换。 | 当前同步域满足 BSP 屏障条件后进入交换。 |
| Cerebras WSE-3 | 配置路由和任务绑定。 | 输入队列关联的 wavelet 可以激活数据任务。程序也能激活本地任务。 |
| Groq 第一代 TSP | 排定切片指令和流的周期。 | 消费指令和操作数按已编排的时序交会。 |
| SambaNova SN40L | 为图段放置计算级、缓冲和路由。 | 数据和流控条件允许时推进流水。 |

Groq 原论文中的一条 superlane 有 16 lane。20 个 tile 在切片方向组合，形成最多 320 元素的向量。这个编排模型有助于分析设备执行时间。部署时还要测量网络传输、排队与请求调度各自的代价。 [Groq 第一代 TSP](groq-tsp/README.md) · [推理运行时的测量方法](../inference-runtime/09-measurement-and-cases/README.md)

### 互连在哪个层级传输

- **片上或晶圆内。** Graphcore 的交换网络连 tile，Cerebras 的晶圆内路由器连 PE，SN40L 的 RDN 连接流水级。各自取用片上资源的粒度不同。
- **设备之间。** Trainium2 的 NeuronLink-v3 支持设备间集合通信。SN40L 有独立的封装内 die-to-die 路径和多 RDU 间的 P2P 路径。Groq 另有 ISCA 2022 多芯片互连论文，应按其配置讨论。
- **系统之间。** Cerebras 的部分训练配置通过 SwarmX 在多个 CS 间广播权重并归约梯度。Maia 100 使用基于以太网的后端，厂商演讲给出的 4800 Gb/s 对应 all-gather 与 scatter-reduce，另列 any-to-any 为 1200 Gb/s。应用带宽仍需按拓扑、通信量和操作类型测量。 [Cerebras Hot Chips 2024](https://hc2024.hotchips.org/assets/program/conference/day2/72_HC2024.Cerebras.Sean.v03.final.pdf) · [Maia 100 Hot Chips 2024，第 7 页](https://hc2024.hotchips.org/assets/program/conference/day2/81_HC2024.Microsoft.Xu.Ramakrishnan.final.v2.pdf#page=7)

### 比较吞吐要标明精度和稀疏条件

先记录操作数和累加精度、稠密或稀疏条件，以及乘加计为几次操作。例如，MTIA 2i 的 INT8 GEMM 标称值在稠密模式为 354 TOPS，在符合 2:4 模式时为 708 TOPS。Cerebras 的部分稀疏映射可以从发送端省掉零权重对应的 wavelet。通用 GPU 也可以运行 CSR 或 COO 等稀疏矩阵算子。它们的格式、调度和收益需要按各自的工作负载判断。 [MTIA 2i 表 2](https://aisystemcodesign.github.io/papers/MTIA-ISCA25.pdf#page=3) · [Cerebras 稀疏映射](Cerebras/README.md#为什么稀疏权重可以少发消息) · [NVIDIA cuSPARSE](https://docs.nvidia.com/cuda/cusparse/)

## 三个可以验证的比较问题

1. **数据能否放下。** 例如有 70 亿个权重，每个占 2 B，仅权重就需要 14 GB。若用这一输入估算，下一步要补齐 KV cache、运行时保留空间和分片开销。
2. **最忙的路径每次要搬多少。** 对同一批次记录计算前后的内存所在位置，统计各层实际经过的字节。片上 SRAM 聚合带宽和片外 HBM 带宽分别约束不同事件。
3. **谁在等谁。** 分别记录引擎依赖、屏障、跨设备通信和服务排队。固定设备时序与较低的端到端尾延迟需要不同的证据。 [容量和性能条件算例](../inference-runtime/09-measurement-and-cases/15-quantitative-estimation.md)
