# 缓存一致性、内存顺序与原子性：分别保证什么？

缓存一致性解释副本怎样协调。内存一致性模型（memory consistency model）规定程序中的内存访问允许被观察成什么顺序。两者协同工作，但不能互相替代。

## 四种不同的问题

| 概念 | 要回答的问题 | 不能据此推出的结论 |
| --- | --- | --- |
| 缓存一致性 | 同一位置的副本和写入如何协调？ | 不同地址的所有访问都按程序顺序可见 |
| 内存一致性模型 | 多线程执行允许出现哪些观察结果？ | 每个访问都直接到达 DRAM |
| 原子性 | 指定操作是否不可分割，粒度是什么？ | 整个临界区自动原子执行 |
| 持久性 | 故障后哪些修改仍然存在？ | 普通 store 返回就已经持久化 |

术语中保留英文，是为了区分中文里两个常被简称为“一致性”的概念。

## 两个地址为何仍需要顺序规则

用抽象机器事件表示下面的程序。x、y 初始为 0，分别位于不同缓存行；每次单变量读写是原子的。暂时不把它当作 C/C++ 普通变量程序。

| 核心 A 的程序顺序 | 核心 B 的程序顺序 |
| --- | --- |
| 写 x=1 | 写 y=1 |
| 读 y，记为 rA | 读 x，记为 rB |

顺序一致性要求存在一个保持两边程序顺序的全局访问顺序。如果 rA=rB=0，则需要“写 x 在读 y 前、读 y 在写 y 前、写 y 在读 x 前、读 x 在写 x 前”，形成环。因此该结果不符合顺序一致性。

若目标模型允许 store 后的不同地址 load 先被观察，写缓冲等机制可以使双方先读到 0。这并不要求同一个地址出现互相矛盾的副本历史。是否允许这个结果，必须查目标模型；不能只看系统是否支持缓存一致性。

## 发布数据需要建立同步关系

考虑单生产者、单消费者的一次发布：生产者先写 payload，再对原子标志 ready 执行 release store；消费者用 acquire load 读到这次发布的 ready 值后，再读取 payload。在相应语言模型下，这种配对可以建立所需的先行发生关系。

条件不能省略：消费者必须观察到对应发布或适用的 release sequence；payload 不能同时被其他线程无同步地修改；对象生命周期也必须有效。仅在两边各写一个“屏障”字样，不构成完整证明。

[Linux 内存屏障文档](https://docs.kernel.org/core-api/wrappers/memory-barriers.html)说明内核屏障的配对及其限制。它不是所有语言和 ISA 的统一规范。这里的抽象事件例子不能替代某个 C/C++、Arm 或 RISC-V 程序的模型检查。

## 原子更新不是把协议变成一条消息

原子读改写需要对外呈现不可分割的更新，但实现可以包含获取权限、读取、计算和写回。一次原子加法可能触发多个一致性消息。反过来，网络把一个数据包完整传送，也不保证包内表示的多个内存操作具有整体原子性。

分析时依次写出：操作粒度、观察者范围、允许顺序、同步关系、故障边界。不要用“硬件一致”概括这五项要求。下一篇讨论[一致性域与 I/O 访问边界](coherence-domains-and-io.md)。
