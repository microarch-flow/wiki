# 一致性域与 I/O：谁参与副本协调？

一致性域是协议保证生效的范围。判断一次设备访问是否一致，需要同时知道地址、访问属性、经过的端口，以及系统如何处理已有缓存副本。仅凭设备接在同一条总线上无法判断。

## 能访问内存，不等于持有可探查的缓存

设备可以通过一致性 I/O 路径访问 CPU 缓存中的最新数据，而自身不保存需要被 CPU 探查的缓存副本。另一类设备则保存一致性缓存，必须能响应探查并交出数据或权限。

这两个方向不同：前者要求系统为设备请求协调 CPU 副本；后者还要求设备参与后续副本管理。Arm CHI 的 RN-I 与 RN-F 就体现了这种区别，见[节点与通道](../03-chi/chi-nodes-and-channels.md)。

## 跟踪一次设备写入

假设 CPU 缓存了缓冲区的一行，设备准备更新该行。

| 检查点 | 一致性路径需要处理什么 | 非一致性路径需要谁处理 |
| --- | --- | --- |
| 地址映射 | 设备请求最终指向正确物理位置 | 同样需要正确映射 |
| CPU 旧副本 | 互连按协议失效或协调副本 | 驱动按 DMA API 交接缓冲区 |
| 写入完成 | 使用接口规定的完成及可见性条件 | 同样不能把发出请求当作完成 |
| CPU 再次使用 | 软件建立设备完成到 CPU 使用的顺序 | 还需要规定的缓存维护步骤 |

即使路径一致，CPU 也不能在设备尚未完成时读取半更新的数据结构。缓存一致性减少了某些缓存维护责任，却不消除缓冲区所有权和同步责任。[Linux DMA API HOWTO](https://docs.kernel.org/core-api/dma-api-howto.html)也明确指出，一致性 DMA 内存仍可能需要内存屏障。

## 三个常见误判

**有 IOMMU，所以自动一致。** IOMMU 的核心职责是地址转换与访问控制。是否维护 CPU 缓存副本，取决于系统的一致性集成和访问属性。映射正确不等于副本已同步。

**同一物理地址，任何属性都可混用。** 同一位置若通过不兼容的缓存属性或共享属性访问，可能落在体系结构不保证的组合中。不能靠增加探查消息补救不合法的软件映射。

**MMIO 和普通内存一样。** 寄存器读取可能有副作用，写入可能触发设备动作。缓存、合并和推测访问必须遵守设备内存属性，不能套用普通缓存行的数据复用规则。
