# 一致性与内存互连：谁持有最新的缓存行？

多个处理器或设备共享数据时，缓存可以减少重复访问内存，但也会产生多个副本。一致性机制要在指定的一致性域内管理这些副本和访问权限。它不自动规定不同地址之间的全部访问顺序，也不代替软件同步。

## 从一次写入看职责

假设两个处理核心都缓存了同一条数据，核心 A 需要修改它。一种构造方案是：A 向负责该地址的控制节点请求写权限；控制节点根据系统状态查询或通知其他缓存；所需响应完成后，A 获得写权限并执行写入。其他核心之后的读取需要遵守该系统的一致性协议。

具体协议可能采用目录、snoop 或其他组合。请求、数据、失效通知和响应怎样映射到网络，也取决于实现。片上网络负责传输这些消息；一致性协议定义消息与状态的约束。两者需要共同保证前进，不是二选一的两种网络。

Arm 的 [AMBA CHI](https://www.arm.com/architecture/system-architectures/amba) 是一致性接口协议的一个例子。它区分协议和传输层；采用 CHI 不意味着只能使用一种拓扑。本文只建立入口，具体事务和状态需要按所选规范版本阅读。

## 一致性与 CXL 的关系

CXL 面向主机与设备之间的 I/O、缓存和内存访问，包含不同用途的子协议。它不是 CHI 的别名，也不意味着设备自动加入系统中的所有一致性域。需要先确定设备类型、双方支持的协议、拓扑与配置。

例如，主机访问 Type 3 设备连接的内存，与加速器缓存主机内存，是不同的路径。前者可使用 CXL.mem；是否支持其他协议应按设备能力和规范版本判断。详见 [CXL：从设备发现到内存访问](./cxl-host-memory.md)。
