# 芯粒链路怎样测试：通过回环后能证明什么？

上级：[03 系统集成与验证](../SUMMARY.md#system-integration)

两颗裸片分别通过筛选后，封装内连接仍可能存在问题。测试结果能说明什么，取决于测试信号经过哪些电路、使用什么码型和条件，以及结果在哪里检查。

本文用两个**构造的回环路径**说明覆盖边界。回环点、测试发生器和检查器是否存在，以及信号实际经过哪些电路，都由具体芯粒和测试配置决定。

## 装配前后，测试对象不同

装配前，可以按器件支持的方式检查裸片内部逻辑、接口电路和可接触的连接。但封装尚未完成，不能用这一步证明最终的芯粒间通道已经连接正确。

装配后，可以进一步测试实际封装中的芯粒和互连。通过封装前筛选的 KGD 不是绝对无缺陷的保证；组装和连接本身也可能引入新的问题。测试覆盖与筛选边界见 [FAB：KGD](../../../chip-development/FAB/wiki/03-wafer-test-and-cp/kgd-known-good-die.md)。

OCP 的 [SiP 测试资料](https://www.opencompute.org/documents/d2d-submission-v8-docx-pdf)讨论了内部、外部回环和测试码型等方法。下面只构造可用于理解的路径，不假设所有接口都提供这些功能。

## 两种回环经过哪里

假设 A 和 B 各有发送器与接收器。测试已经正确配置，所需供电和时钟可用；发生器产生已知数据，检查器将收到的数据与预期比较。

**A 的近端回环**经过本例中的内部路径：

> A 的发生器 → A 的发送器 → A 内部回环点 → A 的接收器 → A 的检查器

一次通过说明该测试覆盖的 A 内部路径在所选条件下通过；它不经过芯粒间封装通道。

**B 端回环**经过本例中的往返路径：

> A 的发生器 → A 发送器 → 封装去程 → B 接收器 → B 的回环点 → B 发送器 → 封装回程 → A 接收器 → A 的检查器

一次通过说明该测试覆盖的往返组合路径在所选条件下通过。这个例子假设 B 的回环点位于接收器之后、发送器之前。实际回环可能绕过其中一些电路，或使用其他连接。只有先确定测试模式和回环点，才能判断结果覆盖了什么。

即使两种测试都通过，也只能说明所覆盖的路径在当时码型、速率、电压、温度和测试时长等条件下通过。它们不自动证明所有数据线、所有工作条件或上层事务都正确。

## 失败时怎样缩小范围

假设 A 和 B 各自的近端回环通过，但 B 端往今回环失败。该结果说明：在这些测试条件和覆盖范围内，内部回环通过而往返组合路径未通过。它**不能单独确定**故障在封装去程、回程、远端 PHY、时钟或测试配置的哪一处。

如果器件提供独立的远端发生器和检查器，可以在允许的条件下分别测试 A → B 和 B → A，再对照两端状态及错误计数。这可能缩小候选范围，但每次测试仍要注明观察点和经过的电路。若两方向使用不同码型或工作条件，结果不能直接归因为方向差异。

| 需要记录 | 用途 |
| --- | --- |
| 测试模式与回环点 | 确认哪些发送器、接收器和封装路径被覆盖。 |
| 两端配置与状态 | 核对速率、宽度、时钟、复位和所需的初始化状态。 |
| 码型、错误计数与检查量 | 确认检查了什么、检查了多少；注明计数器的观察位置。 |
| 环境与时间 | 记录电压、温度、运行时长和状态变化，便于复现和比较。 |

链路恢复、重训练或计数器清零可能改变观察窗口。相关现象需要结合时间线分析，不能只凭同时出现就断言因果。[SerDes：重训练与运行观察](../../SERDES/06-link-operation/retraining-and-observation.md)

## 零错误和链路就绪的边界

某个测试窗口内检查到零错误，不等于长期误码概率为零，也不能替代其他码型和工作条件的验证。统计上能得到什么结论，取决于已检查比特数和所用的错误模型；详见 [BER、置信度与 FEC](../../SERDES/05-signaling-and-metrics/ber-confidence-and-fec.md)。

同样，测试路径通过或链路状态显示就绪，不表示地址映射、权限和目标资源已经配置正确。是否能完成业务访问，还要在对应事务边界检查结果。[芯粒互操作与启动](./interoperability-and-bring-up.md)区分了这些准备步骤。[UCIe 2.0 可管理性白皮书](https://www.uciexpress.org/_files/ugd/0c1418_b6481ec611e24c6e91f1beb743b0c860.pdf)也说明了多芯粒封装测试与调试的可访问性挑战。
