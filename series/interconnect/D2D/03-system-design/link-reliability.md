# 跨芯粒链路出错后怎样检测和重放？

上级：[03 系统集成与验证](../SUMMARY.md#system-integration)

发送端把数据送上线路后，接收端可能因信号错误而无法正确还原数据。支持错误检测和重放的链路可以发现部分错误，并再次发送相关数据。重放发生在链路交付过程中；它不等于上层事务重新执行，也不表示事务已经完成。

本文以 UCIe 1.1 的一种配置为例，说明错误检测、反馈和重放的职责。具体格式、规则和错误处理要以采用的规范版本及双方配置为准。

## 先设定一条启用重放的链路

假设芯粒 A 和 B 已经完成初始化，双方使用相容的 UCIe 1.1 streaming flit 格式，并已按该配置协商启用适配器的重放功能。A 要向 B 发送上层数据；链路以 **flit** 为单位组织传输。

UCIe 联盟说明，1.1 的 streaming flit 可以使用 D2D 适配器提供的循环冗余校验（CRC）检测和重放。格式在初始化时协商。不同格式和配置的处理能力不能直接互换。[UCIe 1.1：错误检测与重放](https://www.uciexpress.org/post/ucie-1-1-provides-streaming-protocol-solution-for-error-detection-and-replay)

下面是**构造的单次错误案例**：一个 flit 在 A → B 的传输中受损，其他条件允许链路随后恢复。它不是产品实测，也不是完整的 UCIe 状态机。

## 沿一次错误看恢复过程

| 步骤 | 本例发生的事 |
| --- | --- |
| 1. 发送并保留 | A 的适配器组织 flit，加入相应校验信息，交给 PHY 发送。启用重放时，发送侧需要保留尚需确认的数据，以便必要时再次发送。 |
| 2. 传输出错 | 假设信号经过封装通道后，B 得到的内容与发送内容不同。 |
| 3. 检测并反馈 | B 对收到的信息做 CRC 检查，发现不匹配，将该 flit 判为无效，并触发重放请求。 |
| 4. 重放 | A 收到反馈后，按重放规则安排再次发送。重放的范围和顺序由所选规则决定，不能假设永远只重发一个 flit。 |
| 5. 接收与确认 | 本例假设后续重放通过检查，两端按协议继续推进；发送端根据确认进度回收相应重放缓冲。上层仍要按自己的协议处理数据。 |

UCIe 1.1 对 CRC 检查和 Retry 规则的定义可见[规范第 3.7–3.8 节](https://tmng-al.uspto.gov/resting2/api/casedoc/cms/case/99231699/tmdocument/20250612064611159321SPE0011.pdf)。这里的“反馈”表示逻辑上的确认或重放请求，不表示一定存在一根专用反馈线：UCIe 联盟说明，Ack/Nak 信息可以包含在 flit 头部。[UCIe 联盟问答](https://www.uciexpress.org/post/introduction-to-ucie-webinar-q-a-recap)

接收端不能把已判无效的数据当成正确交付的结果。具体实现可能对收到的数据提前处理；此时仍需按其规则处理随后发现的错误。本文不规定内部流水线怎样实现。

## 链路确认、发送授权和事务完成

这三个事件回答不同问题：

| 事件 | 回答的问题 |
| --- | --- |
| 发送授权 | 当前是否有条件发送，例如接收端是否提供了所需 credit？ |
| 链路确认 | 链路两端对已发送数据的交付进度如何推进？ |
| 上层事务完成 | 目标是否完成请求，发起方是否收到了符合协议要求的结果？ |

重放缓冲占用、反馈延迟和再次传输都可能影响后续发送与有效吞吐。链路恢复后，对端目标仍可能排队或返回错误。例如，在支持相应链路确认的 PCIe 承载案例中，A 仍需等待并检查 PCIe Completion，才能判断读取结果。[UCIe 1.1 读取案例](../ucie-pcie-read.md)；[跨芯粒流控与前进条件](./flow-control-and-forward-progress.md)

反过来，如果上层操作超时或系统复位，不能只凭链路重放机制断定目标没有执行操作，也不能自动得出跨复位的“恰好执行一次”保证。软件或上层协议是否可以重新发起操作，要看目标副作用、完成状态和系统的恢复规则。

## 检错、纠错、重放和坏线修复

| 机制 | 作用和边界 |
| --- | --- |
| CRC 检测 | 用校验信息发现其检测能力覆盖的错误；它不能保证发现所有可能的错误，也不负责直接恢复原数据。 |
| FEC 纠错 | 接收端利用冗余尝试纠正一定范围内的错误；能力取决于所选编码及错误模式。 |
| 链路重放 | 发送端按反馈和规则再次发送相关数据；持续故障、缓冲和恢复策略仍会影响能否前进。 |
| 物理线重映射 | 若接口和实现支持，可以用备用连接绕过某些坏线；这不是对每次瞬时误码的重传。 |

这些机制可以配合，但不一定同时存在。UCIe 联盟说明，Raw Mode 绕过包括适配器 CRC 检测和重放在内的多项功能；若系统需要可靠性，要在其他位置提供适当机制。不能把本文的重放过程套用到所有 Raw Mode 链路。[UCIe 1.1 模式说明](https://www.uciexpress.org/post/ucie-1-1-provides-streaming-protocol-solution-for-error-detection-and-replay)
