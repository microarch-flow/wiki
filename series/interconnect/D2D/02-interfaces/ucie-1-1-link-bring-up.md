# UCIe 1.1 链路怎样启动？从边带到主带训练

上级：[02 接口与案例](../SUMMARY.md#interfaces)

两颗芯粒的连接线已经做好，仍不能立即发送 PCIe 请求。两端需要先准备时钟与复位，建立边带通信，训练承载数据的主带，再确定共同使用的协议和格式。

本文以 **UCIe 1.1 平面连接、使用 D2D Adapter 承载 PCIe** 为例。它解释从复位到允许传送协议 flit 的主要阶段，不列出所有状态、报文和失败分支。UCIe-3D 及其他接口不能直接套用本流程。[UCIe 1.1 规范，第 3.2、4.5 节](https://tmng-al.uspto.gov/resting2/api/casedoc/cms/case/99231699/tmdocument/20250612064611159321SPE0011.pdf)

## 先区分主带和边带

假设芯粒 A 和 B 使用兼容的 UCIe 1.1 配置，封装连接、供电及时钟满足设计要求。A 后续要经 UCIe 向 B 发送 PCIe 读取，但此时两端还在启动。

**主带**（mainband）是本例中传送协议 flit 的数据路径，包含数据及其相关时钟、控制信号。**边带**（sideband）是另一组接口，在启动和运行中承载所定义的控制与管理消息。例如，两端使用边带交换训练和协议能力相关的信息。边带可以通信，不表示主带已经能可靠传输数据。[UCIe 联盟问答](https://www.uciexpress.org/post/introduction-to-ucie-webinar-q-a-recap)

## 从复位到传送 flit

UCIe 1.1 把本例的链路初始化概括为四个阶段：

- **阶段 0：各自准备。** 两颗 die 分别完成自己的复位和本地准备；两端完成的时间可以不同。
- **阶段 1：边带初始化。** 两端检测并初始化边带；适用时处理边带连接修复，建立边带消息交换。
- **阶段 2：主带初始化与训练。** 两端通过边带交换所需参数，以低速初始化主带，并按配置进行校准、必要的连接修复或降宽，再训练数据与时钟。是否修复、降宽或采用何种调整取决于配置和规范。
- **阶段 3：Adapter 初始化。** 两端 Adapter 交换能力，确定共同使用的协议和 flit 格式，并完成上层接口就绪过程。本例随后可以开始传送相应协议 flit；这还不是一次 PCIe 读取完成。

阶段 2 内的主带初始化和训练分别涉及 **MBINIT**、**MBTRAIN** 等物理层状态；上面是阶段概览，不是一张完整状态机。规范将物理层与 Adapter 之间的 RDI 进入 Active 作为阶段 2 完成的边界；阶段 3 完成还需要协议层与 Adapter 之间的 FDI 就绪。[UCIe 1.1 规范，第 3.2、4.5.3 节](https://tmng-al.uspto.gov/resting2/api/casedoc/cms/case/99231699/tmdocument/20250612064611159321SPE0011.pdf)

例如，如果两端的主带训练完成，但没有找到双方都支持的预期协议或格式，系统仍不能按该配置传送预期事务。反过来，双方都声明支持 PCIe，也不能跳过前面的物理连接检查与训练。

## 为什么要训练数据和时钟

发送端将数据与随路时钟送往对端。时钟和各数据线经过的电路、连接和布线可能有不同延迟。接收端需要在合适的时刻采样；收到时钟并不自动证明所有数据线都有足够的采样余量。

UCIe 1.1 使用训练码型和比较结果帮助调整采样关系。在所定义的训练阶段，实现也可以选择逐 lane 去偏斜；不能假设每个实现都采用同一种调整电路。[UCIe 1.1 规范，第 4.4、4.5.3.4 节](https://tmng-al.uspto.gov/resting2/api/casedoc/cms/case/99231699/tmdocument/20250612064611159321SPE0011.pdf)

下面只比较时间尺度。假设一个 NRZ 数据 lane 的一个传输占一个单位间隔（UI）：

| 每线传输率 | 1 UI | 假设的 20 ps 偏差占 1 UI |
| --- | ---: | ---: |
| 8 GT/s | 125 ps | 16% |
| 16 GT/s | 62.5 ps | 32% |

这里的 20 ps 是构造数字，不是 UCIe 的容限。相同绝对偏差在较短 UI 中占比更大；但 UI 不等于实际眼图开口。能否正确采样还取决于数据眼、抖动、噪声、接收器和训练结果，不能只凭这张表判断链路通过。

## 检测到坏线后一定能继续吗

不一定。UCIe 1.1 的 Standard Package x16 模块提供降为 x8 的方式；这与使用备用物理线修复不同。假设故障只出现在逻辑 lane 0–7，另一半 8–15 符合该配置的使用条件，则链路可以按规范选择后一半作为 x8。实际还要检查其他必需信号及训练结果。[UCIe 1.1 规范，第 4.3.7 节](https://tmng-al.uspto.gov/resting2/api/casedoc/cms/case/99231699/tmdocument/20250612064611159321SPE0011.pdf)

在每 lane 速率不变、只统计数据 lane 的假设下，x8 的单方向原始数据线速率是 x16 的一半。协议开销、事务并发和目标服务仍会影响有效吞吐；降宽不表示每个应用的吞吐或延迟都按同一比例变化。

## 链路就绪之后

链路完成初始化，只表示本例具备按选定配置传送协议 flit 的条件。系统仍需准备 PCIe 地址映射、目标设备和权限；读取还要等待对应 Completion。启动失败或读取超时，也不能仅凭一个状态判断故障一定在 PHY。[UCIe 1.1 读取案例](../ucie-pcie-read.md)；[芯粒互操作与启动](../03-system-design/interoperability-and-bring-up.md)
