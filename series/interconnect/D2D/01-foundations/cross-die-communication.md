# 一次跨芯粒通信怎样完成？

上级：[01 芯粒与连接基础](../SUMMARY.md#foundations)

封装中的连接线把两个接口接在一起。要完成一次读取，两端还要知道请求的含义、目标在哪里、何时返回结果，以及接收端暂时无法处理时怎么办。

## 先约定一个读取

这是**构造案例**。假设芯粒 A 上的计算模块要读取地址为 **0x8000_1000** 的 32 位寄存器；A 的地址映射将它送往芯粒 B 上的目标。两端已经具备相容的接口与地址映射，链路也已完成所需的复位、配置和初始化。假设 B 的目标成功返回 **0x1234_5678**。

这不预设某个具体协议，也不要求两端都使用 NoC。片内路径可以由总线、交叉开关、NoC 或其他结构实现。

## 请求经过哪些边界

| 环节 | 本例需要完成的事 |
| --- | --- |
| A 的发起方和片内互连 | 产生读取请求，将地址等信息送到 A 的跨芯粒接口。 |
| A 的接口逻辑和 PHY | 按选定的承载方式组织请求，由 PHY 将数据转换为通过通道的信号。 |
| 封装通道 | 通过焊盘、凸点和实际采用的封装布线等结构，把信号送到另一端。 |
| B 的 PHY 和接口逻辑 | 接收信号，还原并交付所承载的信息。 |
| B 的目标资源 | 接收读取，取得数据或错误状态，交给 B 的返回路径。 |

需要响应时，B 的接口再通过返回方向将结果送回 A。返回方向使用什么线路和规则，取决于所选接口。A 需要把结果与发出的请求对应，并按系统规定检查状态，才能向发起方交付结果。

## 怎样判断已经完成

假设请求已经经过封装通道，到达 B 的接口。此时，B 的目标可能还在等待本地资源；如果目标随后报告错误，也不能把这次读取当作成功。

因此，要区分三个事件：**信号被采样、请求被对端接口接收、读取结果返回并被发起方接受**。具体协议如何确认交付、是否检测错误或重传，都取决于所选模式和实现。

如果 B 的接口或目标暂时不能接收，请求可能在某处等待。缓冲容量和流控决定等待怎样传回上游；不是每个系统都有相同的队列和回压路径。需要深入分析时，可读 [NoC 网关与跨 die 互连](../../NOC/06-ai-noc-specifics/chiplet-and-die-to-die-interconnect.md)。

## 为什么连接线接通还不够

封装通道、PHY 和通信规则要同时配合。至少需要确认：

- **物理连接**：焊盘或凸点位置、连接数量和封装布线是否对应。
- **电气与时序**：电平、时钟方式及通道条件是否满足两端要求。
- **承载与语义**：数据格式、接口配置、流控和需要的请求与响应规则是否兼容。
- **启动与错误处理**：双方怎样复位、配置，以及如何发现和处理错误。

一个接口规范可能覆盖其中多个层次。以 [UCIe 规范](https://www.uciexpress.org/specifications)为例，它涉及封装级 PHY 和 D2D 协议等内容；但具体芯粒仍需支持相容的配置。封装结构、PHY 和协议是相互配合的不同部分，不能只凭其中一项的名称判断互通。
