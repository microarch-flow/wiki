# 怎样测试 TCP 与 RDMA：先验证路径，再比较性能

上级：[性能、诊断与查阅](README.md)

测试需要说明操作语义和计时边界。TCP 流吞吐、RDMA Write 带宽、Read 延迟和应用 RPC 时间不是同一种指标，不能仅把最大数字排成协议优劣榜。

## 建立四层证据

先检查物理端口、设备模式和网络可达性；再运行单连接端点测试；随后改变消息大小、并发与放置；最后运行真实应用。每层保存软件版本、设备与端口、MTU、CPU 亲和性、NUMA、内存类型、测试时长及完整参数。

同时保留正确性检查。微基准得到吞吐并不自动验证业务的数据所有权与完成协议；若工具提供数据校验，应记录是否启用及其性能代价。

## TCP 基线示例

以下命令仅为操作示例，本文没有在真实网卡上执行。192.0.2.10 是文档地址，运行时替换为测试服务器的可达地址。先在服务器启动，再运行客户端。

```sh
# 服务器
iperf3 -s
# 客户端：单 TCP 流，预热 3 秒，测试 20 秒，输出 JSON
iperf3 -c 192.0.2.10 -O 3 -t 20 -J
# 客户端：反向数据传输
iperf3 -c 192.0.2.10 -O 3 -t 20 -R -J
```

单流与多流结果应分开报告。增加并发可能缓解单流窗口或散列限制，也会改变 CPU 与网络负载。具体参数和计时含义以所安装的 [iperf3 版本](https://software.es.net/iperf/invoking.html)为准。

## RDMA Write 基线示例

假设两端已正确配置兼容 RDMA 网络，并选定可用的 mlx5_0 设备。下面使用 RDMA CM、64 KiB 消息和持续时间模式；两端使用一致的参数与兼容版本。

```sh
# 服务器
ib_write_bw -d mlx5_0 -R -s 65536 -D 10 --report_gbits
# 客户端
ib_write_bw -d mlx5_0 -R -s 65536 -D 10 --report_gbits 192.0.2.10
```

设备名是示例，必须替换为本机实际值。多端口设备、地址绑定和 GID 选择需按工具版本补充；先用 `ib_write_bw --help` 核对选项。没有 `-R` 时的连接参数交换与这里不同，不应混合两种启动方式。[perftest 官方说明](https://github.com/linux-rdma/perftest)

## 再扩大测试矩阵

分别测试 Send、Write、Read，以及主机内存和受支持的 GPU 内存。GPU 选项取决于构建及平台，不应仅复制其他设备的命令。单机结果正常后，再加入多连接、incast 和跨 leaf 路径，观察尾延迟、重传、ECN/PFC 与端点完成速率。

应用测试继续使用[多卡测试方法](../../SCALEUP/05-workloads-and-performance/benchmarking.md)。若没有 NIC／GPU 硬件，最多验证命令文档和预算计算，不能报告实际通信性能。
