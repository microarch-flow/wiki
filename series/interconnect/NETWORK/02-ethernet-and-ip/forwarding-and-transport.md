# Ethernet、IP、TCP 与 UDP：谁负责找到并交付数据？

上级：[Ethernet 与 IP 网络](README.md)

链路可达、IP 可达和应用可用是三个不同条件。网络设备可以成功转发一个包，而目标端口未监听，或应用尚未准备好接收数据。

## 跨子网发送一次数据

假设 A 向另一 IP 子网中的 B 发送。A 按路由表选择下一跳；在 Ethernet 链路上，A 需要下一跳的链路层地址，IPv4 通常使用 ARP，IPv6 使用邻居发现。A 把 IP 包放入发往下一跳的帧中。

桥接设备按二层转发规则处理帧。路由器去掉入链路封装，查 IP 路由、更新相应网络层字段，再在出链路重新封装。目的 MAC 因此可能改变，而最终目的 IP 在没有地址转换等额外机制时保持不变。

这个过程解释了为什么“目标 IP 不在本子网”不等于“无法连接”，也解释了 VLAN 连通为何不能代替路由配置。协议细节见 [ARP](https://www.rfc-editor.org/rfc/rfc826.html)与 [IPv6 邻居发现](https://www.rfc-editor.org/rfc/rfc4861.html)。

## 传输层还要提供什么

| 服务 | 向应用提供什么 | 应用仍需处理什么 |
| --- | --- | --- |
| TCP | 有序字节流、可靠传输及流量与拥塞控制 | 消息边界、业务状态、超时后的操作确认 |
| UDP | 数据报及端口复用 | 按业务需要实现可靠性、顺序和拥塞控制 |
| RDMA 传输 | 与所选服务匹配的消息或远端访问操作 | 合法内存、资源生命周期和消费同步 |

TCP 不保留每次发送调用的消息边界。读到部分数据不是协议错误。UDP 本身不承诺可靠性，但在 UDP 上承载的协议可以另行提供可靠传输；[RoCEv2](../04-roce/rocev2-packet-and-path.md)就是不能只看外层头判断语义的例子。

## 控制面与数据面

控制面建立邻居、路由与策略状态；数据面使用这些状态处理包。ECMP 表项存在，不说明每条路径都能达到同样吞吐；路由收敛期间还可能出现丢包或重排。本文只建立转发关系，路由设计条件见 [RFC 7938](https://www.rfc-editor.org/rfc/rfc7938.html)。

TCP 的现行基础规范见 [RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html)。下一步把可达路径放到[多路径拓扑](clos-ecmp-and-rails.md)中分析。
