# 系统网络的对象与分层：一次通信到底传输了什么？

上级：[基础概念](README.md)

分析网络前，先固定通信对象。应用交换的是消息或数据对象；网卡执行的是发送、接收或远端访问；交换设备处理的是帧或包。一个对象跨过接口后，表示方法会改变，完成条件也会改变。

## 从一条消息往下拆

假设应用要交付 1 MiB 数据。它可以写入 TCP 字节流，也可以提交支持该长度的 RDMA 操作。传输实现可能把数据分成多个包，再由 Ethernet 帧承载。接收端需要按所选服务恢复字节流或完成数据放置，应用最后再解释数据含义。

| 对象 | 输入与输出 | 不能据此推断什么 |
| --- | --- | --- |
| 应用消息 | 对象、长度、参与者 → 对端可使用的结果 | 一条消息只占一个包 |
| 传输操作 | Send、Read、Write 等 → 相应完成或错误 | 所有操作都具有相同通知语义 |
| IP 包 | 网络地址与上层载荷 → 下一跳 | 目的应用已经处理数据 |
| Ethernet 帧 | MAC 地址与帧载荷 → 相邻链路接收 | 一个 MAC 地址标识最终进程 |
| 物理链路 | 编码信号 → 接收比特及错误状态 | 线上比特率就是应用吞吐 |

Ethernet 的 MAC 与 PHY 由 [IEEE 802.3](https://standards.ieee.org/ieee/802/10422/)定义。桥接与 IP 路由是另外的职责。RDMA 是访问能力，RoCE 是其以太网承载方式之一；InfiniBand 则包含交换结构和传输服务。[IBTA 规范入口](https://infinibandta.org/ibta-specification/)

## 端点、节点和端口不能互换

一台服务器可以有多个 CPU、GPU、网卡和网络端口。一个进程可以持有多个通信端点；一个物理端口也可以承载许多连接。端口数相同不代表端点资源、独立路径或应用并发相同。

讨论“跨节点”时应说明节点如何划分。讨论 scale-up 与 scale-out 时应说明访问契约和部署目的，不能仅按机箱内外下结论。协议能力与物理距离并不是一一对应关系。

## 用三个问题建立观察边界

先问谁提交操作，再问数据经过哪些资源，最后问哪个事件允许消费者继续。比如源端 NIC 已读取发送缓冲区，只能说明该缓冲区的某一生命周期阶段结束；它不证明远端应用已完成计算。
