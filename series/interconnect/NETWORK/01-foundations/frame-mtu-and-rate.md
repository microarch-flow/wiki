# 帧长、MTU 与包率：额定带宽怎样变成有效数据？

上级：[基础概念](README.md)

同一端口发送大包和小包时，可以具有相同的 MAC 比特率，却需要完全不同的每秒包处理能力。计算前必须说明字节数位于哪一层。

## MTU 不是线上总长度

常见 Ethernet 接口的 IP MTU 为 1500 B，表示可承载的 IP 包大小；它不包含 Ethernet MAC 头和 FCS。TCP、UDP、RDMA 等头部还会占用其中一部分。VLAN、隧道和不同 IP 版本进一步改变有效载荷比例。

Jumbo frame 是部署能力与配置的组合，不能假设每条路径都接受同一数值。主机 netdev MTU、RoCE QP 的 path MTU 和应用消息长度也不是同一个量。路径中较小的限制必须纳入配置与测试。

## 一个经典 Ethernet 算例

采用传统完整帧口径：MAC 帧长 L 包含从目的 MAC 到 FCS 的字节；帧前导码与 SFD 共 8 B，平均帧间隔按 12 B 时间计。这里的 R 是 MAC 数据速率，不是计入物理编码后的串行原始速率。

> 包率上界 = R ÷ [8 × (L + 20)]。
>
> 应用有效带宽上界 = 包率 × 每帧应用有效载荷字节数。

在 100 Gb/s、64 B MAC 帧的构造算例中，包率上界约为 **148.81 Mpps**。若每帧 1518 B，上界约为 **8.13 Mpps**。两者还都没有证明 NIC、主机和应用能处理相应包率。

该预算采用[经典 IEEE 802.3 帧模型](https://standards.ieee.org/ieee/802/10422/)，不叠加计算已经由 PHY 吸收的编码开销。新协议的缩短帧间隔等能力需要另设模型，不能沿用此处常量。

## 一条链路上的多个效率

从 MAC 数据率到应用有效数据，会扣除帧及传输头部、必要空闲、控制包和重传等开销；网络排队和端点停顿还可能让链路不能持续发送。应分别说明“每个已发送帧的载荷比例”和“链路实际忙碌比例”。

提高 MTU 可以减少单位载荷的包数，但不能消除出口拥塞，还可能改变小消息的等待和丢包后的恢复代价。更多性能边界见[预算方法](../07-performance-and-reference/metrics-and-budget.md)。
