# 内存注册与访问权限：远端怎样获得合法目标？

上级：[RDMA 端点](README.md)

远端地址本身不构成访问授权。设备需要知道这段地址怎样映射到本地内存、允许什么操作，以及授权何时失效。MR 与访问密钥把这些条件连接起来。

## 注册建立哪些状态

应用向注册接口提供保护域、内存范围和访问属性。设备与驱动建立可用于 DMA 的映射及校验状态，返回 MR 对象和相应密钥。本地请求通常通过 lkey 引用合法缓冲；远端操作使用目标公布的地址或偏移及 rkey。

| 检查项 | 失败意味着什么 |
| --- | --- |
| 地址与长度在授权范围内 | 请求越界，不能访问任意邻近对象 |
| 操作权限匹配 | 允许远端读取不意味着允许写入或原子操作 |
| 资源关联符合规则 | 不同保护域的对象不能任意混用 |
| 注册与映射仍有效 | 旧地址和密钥不能继续代表已回收资源 |

具体属性及限制以 [ibv_reg_mr](https://github.com/linux-rdma/rdma-core/blob/master/libibverbs/man/ibv_reg_mr.3)为准。普通注册、ODP 与 dma-buf 注册具有不同的驻留和映射过程，因此不把“注册”定义成“一次性固定全部物理页”。

## 从授权到回收

构造流程：B 分配缓冲并建立允许远端写入的 MR；B 经可信的控制协议把地址、长度和 rkey 告知 A；A 在约定范围内提交写；双方按照完成与通知协议结束使用；B 确认不存在仍可能到达的访问后，撤销注册并释放缓冲。

“B 不再需要结果”不足以允许立即回收。A 可能已经提交请求，网络中也可能有重传。应用需要关闭新访问入口、处理在途操作并协调撤销。单纯改变一份软件指针不会让旧请求自动消失。

## 密钥和地址的边界

rkey 是设备权限检查的输入，不是对任意网络攻击的加密认证证明。授权信息的交换、网络隔离和设备策略仍需系统设计。虚拟化场景还要区分虚拟功能资源与网络可达性；VLAN 可达不代表 MR 权限合法。

注册缓存可减少重复注册开销，但必须跟踪分配释放和地址复用。把一个地址上的旧 MR 套到新对象，会破坏生命周期约束。GPU 内存还有自己的映射与释放通知条件，见 [GPUDirect RDMA](../06-system-integration/gpudirect-rdma.md)。

IOMMU 地址转换和 DMA 缓冲区交接细节由[PCIe 缓冲区文章](../../PCIE/04-data-path-dma-interrupts/host-memory-pinned-buffer-visibility.md)负责；本页重点是端点间的授权契约。
