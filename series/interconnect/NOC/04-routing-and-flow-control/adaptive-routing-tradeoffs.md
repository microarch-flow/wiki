# 自适应路由：怎样利用可选路径？

上级：[04 路由、仲裁与服务保证](./README.md)

相关：[路由算法分类](./routing-algorithm-classes.md)、[Turn Model 与逃逸资源](./deadlock-avoidance-turn-model.md)、[端到端服务保证](./service-guarantees-and-latency-bounds.md)

<span id="adaptive-routing-tradeoffs"></span><span id="这页在回答什么问题"></span>自适应路由根据运行时状态在允许的候选路径或出口中选择。它可能减轻部分竞争，也可能增加决策、验证和资源成本；具体结果取决于候选、观测信息和流量。

## 一次决策包含什么

<span id="它承诺的是什么"></span><span id="决策逻辑更复杂"></span>假设二维 Mesh 中一个 header 从 (0,0) 发往 (2,1)，且规则允许 East 和 North 都作为当前最短路径的候选。路由器可以读取各候选的本地状态，再按实现规则选择。若两个方向都不可发送，包需要等待或使用设计允许的其他资源。

选择前应先确定哪些候选满足路由与 VC 安全约束，再根据可观测状态进行选择。Credit 表示发送端当前掌握的下游槽位授权，不是整条后续路径的实时空闲度；反馈延迟和局部观察范围可能让判断滞后。具体实现可以只在 header 阶段选择，也可以采用其他明确的包转发契约。

## 多路径何时有用

<span id="收益成立的前提"></span><span id="1-必须真的有多条可用路径"></span>候选必须实际可达并能绕开所讨论的竞争资源。如果所有流最终都受同一个目的端服务能力限制，改变中间路径不能提高该目的端的能力。

<span id="2-拥塞必须是动态且局部的"></span>负载不必随时间变化才存在分流机会。[维序路由的构造例](./dimension-order-routing.md#固定路径怎样改变热点)中，两条持续流因为 XY 共享一条链路；改变其中一条路径可以消除该处重叠。静态规划或自适应选择都可能利用这样的路径，但自适应能否发现并持续利用它，还取决于观测、反馈和规则。

<span id="3-额外路径不能引入过高绕路成本"></span>非最短路径可能多占用链路和路由器资源，但也可能减少排队。额外 hop 对能耗和延迟的影响还依赖各边的物理成本、等待与端点；不能仅凭 hop 数断言尾延迟一定更长。仅在最短路径中自适应的算法不需要增加 hop。

## 变化的代价和正确性

<span id="它带来的真实代价"></span><span id="延迟更难预测"></span>更多候选可能增加状态采集、选择逻辑和验证工作。同一流的包走不同路径后，后发出的包可能先到达；如果接口要求按序交付，必须在路由、序号或接收端重排等位置提供相应机制。

<span id="验证和-debug-成本更高"></span>动态选路还要检查合法候选、资源依赖、活锁和仲裁公平性。避开一个局部热点可能使流量在其他位置汇合；局部负载下降不自动意味着端到端性能改善。[Turn Model](./deadlock-avoidance-turn-model.md)和逃逸机制分别给出安全分析入口。

<span id="它和-qos-的冲突"></span>QoS 目标也要覆盖所有实际可能使用的路径。单独拥有多条路径或独立 VC，不代表每条路径都有足够的服务份额、有限等待或可接收的端点。

## 怎样比较候选

<span id="为什么-ai-noc-往往更保守"></span><span id="哪些场景更适合考虑它"></span><span id="一个更务实的比较对象"></span>在相同端点、输入流量和实现预算下，比较固定路由、静态多路径与受限自适应。记录每条路径的使用、每条链路的负载、等待和端点服务，同时比较分位延迟、吞吐及未完成请求。更改 placement 或 VC 数量时，应把它们作为另一个明确变量。

<span id="建模启示"></span>模型需要标出状态来源、采样时刻、决策和 tie-break 规则，以及反馈延迟与安全约束。否则它可能使用真实路由器无法及时获得的信息。

<span id="一句话理解"></span>自适应路由的价值取决于可选路径、可用信息和实际流量，而不是“动态”这个名称本身。
