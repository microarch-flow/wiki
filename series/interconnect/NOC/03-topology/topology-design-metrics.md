# 怎样定义和比较 NoC 拓扑指标？

上级：[03 拓扑与物理组织](./README.md)

相关：[Mesh 与 Torus](./mesh-and-torus.md)、[拓扑选型](./topology-selection-framework.md)

<span id="topology-design-metrics"></span><span id="这页在回答什么问题"></span>拓扑描述节点之间有哪些连接。比较拓扑前，先定义网络图、端点和链路容量，再确定流量和选路规则。平均跳数可以描述距离，却不能单独预测拥塞、延迟或能耗。

## 先定义比较对象

<span id="指标与边界"></span>要复现一个指标，至少需要知道：图是否有向，路由器和端点如何连接，是否允许平行链路，每条链路的容量和方向，以及统计时包含哪些端点对。路径上的一条 router 间边记为一跳；注入和接收链路是否计入，应另行说明。

| 指标 | 含义 | 必须说明的条件 |
| --- | --- | --- |
| 直径 diameter | 可达节点对的最短距离中的最大值 | 哪些节点参与统计，以及图是否连通。 |
| 平均最短距离 | 节点对的最短距离按指定权重求平均 | 是否包括自身对；不同源、目的是否等权。 |
| 切面容量 | 给定划分中，跨越切面的链路容量之和 | 指定切面还是所有等分切面中的最小值；容量按哪个方向统计。 |
| 端口数 radix | 路由器的本地端口和网络端口数 | 是实际连接端口还是硬件配置端口；端口是否双向。 |
| 路径多样性 | 满足长度及其他约束的可选路径数 | 图上存在的路径不一定被实际路由算法允许。 |
| 物理跨度 | 已布局的链路两端相距多远 | 给出放置、走线路径和单位；图中一跳不代表固定线长。 |

切面容量有时称为 bisection bandwidth。严格比较时，应区分**某一个等分切面**的容量与所有合法等分切面中最小的容量。全双工链路应分别统计两个方向，避免把单方向和双方向合计混用。

## 4×4 Mesh 与 Torus 的构造例

<span id="一个可复算的-44-例子"></span>假设每个拓扑都有 16 个路由器，每个路由器接一个端点；相邻路由器间为全双工链路，每方向容量为 W。Mesh 不环回，Torus 在两个维度首尾相连。下面按 240 个有向、非自身端点对等权计算，只计路由器间的边。

| 指标 | 4×4 Mesh | 4×4 Torus |
| --- | --- | --- |
| 最短路径直径 | 6 跳 | 4 跳 |
| 平均最短距离 | 8/3 ≈ 2.667 跳 | 32/15 ≈ 2.133 跳 |
| 垂直等分切面，单方向 | 4W | 8W |
| 最大已连接端口数，含本地端口 | 5 | 5 |

若把 16 个自身对也算入均值，结果分别为 2.5 和 2 跳。这两种口径都可使用，但比较时必须一致。这里的垂直切面只是一项结构容量，不代表任意流量都能达到该带宽。

<span id="其他拓扑不能只由-n-推导"></span>例如 Mesh 中从 (0,0) 到 (2,2)，图上有 6 条最短路径；如果采用先 X 后 Y 的维序路由，只允许其中一条。对 Ring、Tree 或 Dragonfly，也要先给出具体连边和端点映射，不能只凭端点数推出全部距离和切面。

## 怎样使用切面容量

假设上面的 Mesh 左半区有 8 个端点，每个端点持续以 λ 的速率向右半区发送单播数据，单位与 W 相同。所有这些数据至少要从左向右跨过所选切面一次。长期稳定服务的必要条件是：

> 8λ ≤ 4W，因此 λ ≤ W/2。

这不是充分条件：某条内部链路、目的端或仲裁器仍可能先达到容量上限。反过来，完全留在左半区的流量不占用这个切面的左向右容量。需要分析的始终是**实际流量经过哪些资源**。

## 从连接图走向实现

<span id="从结构到时序和容量"></span>链路长度、频率和流水级数由布局及电路实现决定。延迟还受路由、仲裁、排队和接收端服务影响。Credit 的往返时间由正向传输、下游释放和反馈路径共同决定；具体窗口条件见[Credit 与反压](../02-router-microarchitecture/credit-based-flow-control.md#窗口深度与发送速率)。

<span id="建模启示"></span>先记录连接关系、每条链路的方向与容量、端点映射，以及允许的路由。再针对指定流量计算距离、路径和链路负载。比较物理代价时，补充布局、线长和时序假设，而不是从拓扑名称推断它们。
