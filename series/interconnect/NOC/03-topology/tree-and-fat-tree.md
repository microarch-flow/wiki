# Tree 与 Fat-tree：怎样组织汇聚和分发？

上级：[03 拓扑与物理组织](../SUMMARY.md#03-topology)；原章节：[03 拓扑与物理组织](./README.md)

相关：[广播、多播与复制](../06-ai-noc-specifics/broadcast-multicast-tree.md)、[归约与 Collective 网络](../06-ai-noc-specifics/reduction-and-collective-networks.md)、[层次化与混合互连](./hierarchical-and-hybrid-topology.md)

<span id="tree-and-fat-tree"></span><span id="这页在回答什么问题"></span>Tree 将节点组织成层级路径；Fat-tree 通过增加较高层的连接容量，缓解跨子树流量的集中。连接图决定可能的路径，是否能复制数据、执行归约或并行转发，还取决于节点能力。

## 树形路径不等于多播或计算

<span id="tree把流量方向性结构化"></span>在一棵连通、无环的普通树中，任意两个节点之间只有一条简单路径。叶节点向根节点发送时，上层边可能承载多个子树汇聚的流量；从根向多个叶节点分发时，路径可能在中间节点分叉。

分叉的图形本身不会复制数据。实现多播需要节点具备复制和输出调度能力，或者由源端分别发送多份单播。归约也需要明确的计算能力：如果两个子节点各送来 4 B 数据，中间节点只转发，则仍须向上发送两份 4 B；如果它能按指定运算聚合，并产生一个 4 B 结果，才可能只发送一份。参与者、数据类型、结果顺序和缓冲均需定义；浮点运算的不同归约顺序还可能改变舍入结果。

<span id="tree-的问题不是慢而是上层太容易被压"></span>若多个叶子持续把数据送往根，上行链路与根的接收能力可能先饱和。若通信主要发生在同一子树内，则不一定经过根。负载由参与者位置、方向、路由和通信操作共同决定。

## Fat-tree 如何增加上层容量

<span id="fat-tree承认上层要更胖"></span>Fat-tree 的基本思想是让靠近高层的连接提供更多聚合容量；可用更宽的连接、更多并行链路或多交换节点实现。Leiserson 的[原始 Fat-tree 论文](https://www.cs.uic.edu/~balajee/550-papers/fat-tree-orig.pdf)明确将通信能力与实现成本作为设计参数。其理论结果依赖论文中的模型，不能直接当作任意片上实现的性能保证。

下面是一个简化的四端点构造。端点 E0、E1 连接下层交换机 L0，E2、E3 连接 L1；L0 和 L1 分别连接上层交换机 U0、U1。每条连接每方向容量为 W。

| 节点 | 连接 | 已连接端口数 |
| --- | --- | --- |
| L0 | E0、E1、U0、U1 | 4 |
| L1 | E2、E3、U0、U1 | 4 |
| U0、U1 | 各连接 L0 和 L1 | 各 2 |

L0 有两条上行连接，因此上行链路的聚合容量为 2W。若交换机、目的端与路由都允许，两条流可以分别经 U0 和 U1 进入 L1。增加链路本身不证明所有流量无竞争，也不要求上层单个交换机的端口数高于下层。

## 作为通用网络还是专用网络

<span id="为什么片上通用主网络不默认选它"></span><span id="为什么它们在-ai-noc-里又很重要"></span>树形路径可以服务通用点对点通信，也可以与复制、归约资源组合，服务特定多目标操作。作为通用网络时，需要考虑不同子树之间的并发；作为专用网络时，需要考虑计算、复制和缓冲能力。

<span id="一个关键判断通用路径和专用路径不要混为一谈"></span>逻辑上的归约树也可以映射到一张 Mesh 上：树边会占用 Mesh 的物理链路。只有额外增加了专用硬件时，才是独立的物理 overlay。两种设计的共享资源和成本不同。

<span id="fat-tree-可作为比较方案"></span>比较 Tree、Fat-tree 和其他拓扑时，应列出每层节点、链路容量、端点放置及允许路径。还要检查上层连线的物理跨度；更多上行容量可能改善某些跨区流量，也可能增加布线与交换成本。

<span id="常见误解"></span><span id="一句话理解"></span>树形连接提供路径；复制、算术和服务能力必须由实际节点实现。

<span id="建模启示"></span>分别记录连接图、每层容量和路由，再记录复制、fan-in、运算服务率及结果大小。对 collective 计算阶段时间时，还需统计实际物理边上的共享负载。
