# 跨时钟域、复位与流控：空槽何时可以再次使用？

上级：[05 端点与系统集成](../SUMMARY.md#05-system-integration)

相关：[网络接口 NI](./ni-network-interface-design.md)、[Credit 与反压](../02-router-microarchitecture/credit-based-flow-control.md)、[事务拆分、顺序与完成](./transaction-ordering-and-completion.md)、[跨 Die 互连](../06-ai-noc-specifics/chiplet-and-die-to-die-interconnect.md)

一个端点和 NoC 不一定使用同一时钟。跨域接口既要传递数据，也要让发送端知道接收资源是否可用。接收端腾出空间后，这一变化不一定立即被发送端看到。复位还可能改变队列、在途请求和反馈的状态。

本文讨论 NoC 接口的资源与完成契约；异步 FIFO 的基本结构、同步和位宽适配见 [BUS 的 Bridge、CDC 与 Width Adapter](../../BUS/04-microarchitecture-integration/bridge-cdc-width-adaptation.md)。具体同步电路和时序约束仍以器件及实现为准。

## 先确定跨域边界和资源所有者

例如，端点 A 由时钟 A 驱动，NI 或 router B 由时钟 B 驱动。一个可选方案是在边界放置异步 FIFO：A 域按写侧接口送入 flit，B 域按读侧接口取出；写侧可用空间和读侧可读数据分别由各自时钟域中的状态判断。

| 需要约定 | 要回答的问题 |
| --- | --- |
| 数据和容量 | 哪一侧写入、哪一侧取出；FIFO 有多少槽；每个槽容纳什么单位？ |
| 流控和状态 | 发送端依据 FIFO 写侧 `full`、接口握手，还是另一个 credit 账本发送？每个空槽由谁授权？ |
| 可见时间 | 写入、读取和反馈何时对另一侧可见；状态同步带来什么延迟？ |
| 复位和完成 | 哪些在途对象被保留、排空或丢弃；谁报告失败；何时允许重新发送？ |

这些是设计选项，不规定所有跨域 NoC 都有单独的返回 credit 信号。如果同时使用 FIFO 状态和 credit，必须定义二者之间的关系；不能把同一个物理槽作为两份独立容量重复发放。

AMD 的独立时钟 FIFO 文档说明，读写时钟的频率和相位可以没有固定关系，写侧和读侧标志属于各自时钟域；标志变化的可见时间受时钟关系影响。[AMD PG327：Independent Clocks](https://docs.amd.com/r/en-US/pg327-emb-fifo-gen/Independent-Clocks-Block-RAM-and-Distributed-RAM)

## 一个两槽 FIFO 的构造例

假设 FIFO 深度为 2，写侧只在本域观察到 `full=0` 时写入，读侧按本域接口读取；同步和存储均按所选 FIFO 的正确实现工作。以下事件有先后顺序，但不假定跨域固定经过多少拍：

1. A 侧依次写入 F0、F1；写侧随后看到 FIFO 满，停止写入。
2. B 侧读取 F0。物理存储中已有一个槽被释放。
3. 读指针或相应空位信息经过跨域同步后，A 侧才看到 `full` 解除，随后可以写入下一个 flit。

在第 2 步与第 3 步之间，物理槽已空，写侧仍可能被保守地阻止。此时不能只看存储阵列就断言发送端有许可。反过来，若发送端提前使用尚未确认的空间，就可能覆盖未读数据。具体同步延迟、同时读写和标志行为要按选定 FIFO 的文档核对。

## 如果接口另有 credit

一种设计可以让上游按 credit 预留下游槽，另用跨域通道传输数据和反馈。必须分别说明：何时消耗许可、谁真正释放槽、何时生成反馈，以及反馈在哪个时钟域可用于新发送。

在**一个指定的单 VC 容量域**内，若每个槽恰好有一枚许可，不丢失、不重复，且正反向在途状态均已计入，可沿用守恒检查：

> 总槽数 = 可用 credit + 已预留的正向在途 flit + 已占用槽 + 返回在途 credit。

这个式子不是任意异步 FIFO 的通用实现要求。若存在额外预留、批量反馈、不同容量域或复位过程，需要扩展状态及证明条件。第九章的教学模拟器使用单时钟，不模拟亚稳态或上述跨域实现。

## 复位时怎样处理在途状态

只把某一侧计数器清零，不能自动证明另一侧队列、在途数据和旧反馈也已消失。设计需要约定复位范围与恢复顺序，例如先阻止新请求，按接口能力排空或取消已有工作，再按组件规定完成两侧复位与初始化，最后重新开放发送。能否排空、如何取消，以及请求应返回什么状态，都由具体协议和系统决定。

若允许单侧复位或保留另一侧运行，还需要定义旧数据、迟到响应和旧 credit 的处理。一种候选方案是使用可区分新旧状态的代际标识，并规定标识复用和在途对象清理条件；另一种是协调两侧清空并重新建立许可。代际标识本身不解决数据丢失、回卷或上层错误报告。

检查时至少覆盖两侧复位先后、发送和反馈在途、缓冲非空以及时钟暂停或恢复。安全通过接口模型测试不等于证明电路的亚稳态可靠性；后者还需要器件、同步结构和时序约束的证据。跨域吞吐也不能仅由较快一侧的频率推出。
