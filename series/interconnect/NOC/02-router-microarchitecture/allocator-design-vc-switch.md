# VC 分配和交换分配分别决定什么？

上级：[02 路由器与逐跳流控](../SUMMARY.md#02-router-microarchitecture)；原章节：[02 路由器与逐跳流控](./README.md)

相关：[路由器流水线](./router-pipeline-stages.md)、[仲裁策略](../04-routing-and-flow-control/arbitration-policies.md)

<span id="allocator-design-vc-switch"></span><span id="这页在回答什么问题"></span>多个输入希望继续前进时，路由器既要管理下游的逻辑通道，也要分配本拍的物理交换机会。两个决定可能由不同的电路完成，也可能被组合。

## 两类资源

<span id="vc-allocator决定-packet-能不能建路"></span>在本章的 wormhole 例子中，**VC 分配**为包选择目标输出上的一个可用下游 VC。获得许可后，本包的后续 flit 复用这个绑定。该许可何时能够分给新包，要按选定的释放策略判断。

<span id="switch-allocator决定这一拍谁过-crossbar"></span>**交换分配**为本拍的候选 flit 选择输入到输出的连接。一个常见限制是：每个输入端口和每个输出端口每拍至多参加一次匹配。下游 VC 已分配并不代表本拍一定能赢得交换；交换可用也不代表下游已有可用许可或 credit。

<span id="一个最小例子"></span>例如两个包都要去 East，下游有两个可分配 VC，两个包可以分别取得许可。但如果 East 输出每拍只发送一个 flit，它们仍要竞争该输出。本拍失败的包可以在条件允许时再次请求；等待可能持续多拍。

这里使用“先取得 VC，再竞争交换”的非投机流程。其他实现可以联合分配，或先进行投机的交换选择，再检查 VC 分配是否成功。资源的语义仍应分清。

## 一次匹配可能错过什么

<span id="常见两级-switch-allocation"></span>假设每个输入和输出每拍最多服务一个 flit，所有候选均已满足流控条件：

| 输入 | 可请求的输出 |
| --- | --- |
| I0 | O0、O1 |
| I1 | O0 |

如果先让每个输入只选一个候选，I0 选择 O0，I1 也选择 O0，那么输出仲裁后只有一个输入获胜，O1 空闲。另一种选择是 I0 → O1、I1 → O0，可同时服务两个输入。

这说明分级局部选择可能错过一个可行的并行匹配；它不说明更复杂的分配器一定更快。还要比较实现时钟、流水延迟、面积及实际请求分布。

<span id="为什么-allocator-复杂度会上升得很快"></span>若有 P 个输入端口、每端口 V 个 VC，最多有 P × V 个输入 VC 需要检查。实际仲裁规模还取决于每个输入可同时提出多少请求、每个输出允许多少连接，以及分配器是否分级。

## 匹配算法与实现

<span id="三种-allocator-与可复现的匹配"></span>可选方法包括分级仲裁、iSLIP 和 wavefront 等。它们使用的候选和实现方式需要单独说明；VC 分配还要检查下游许可，并处理跨多个 flit 的持有期。

以 iSLIP 的交换匹配为例，一轮包含 request、grant 和 accept。假设上表中的 I0 可以同时向 O0、O1 请求，I1 请求 O0；若两个输出都先授权 I0，而 I0 接受 O0，则本轮只得到 I0 → O0。剩余 I1 只请求已匹配的 O0，下一轮也无法补上 O1。若初始指针使 O0 授权 I1、O1 授权 I0，则可以得到两条匹配。

iSLIP 的指针更新与第一轮成功匹配有关；上述例子只说明请求和初始指针的影响，不是算法性能排名。[McKeown，iSLIP](https://yuba.stanford.edu/~nickm/papers/HOTI_96.pdf)

<span id="speculative-allocation-值不值得"></span>多轮匹配可以在一个周期内展开，也可以跨周期实现。投机分配可能减少某些等待，但必须处理 VC 分配失败或交换选择失效的情况。比较时应分别记录单次决策延迟、启动间隔、时钟频率、匹配数和验证成本。

## 仲裁策略和可观测状态

<span id="和-bus-arbitration-的相同点与不同点"></span>不同互连都可能在多个位置仲裁。轮询、固定优先级或加权策略决定如何在候选之间选择；它们不是 VC 分配和交换分配的另一组互斥类别。策略及饥饿风险见[仲裁策略](../04-routing-and-flow-control/arbitration-policies.md)。

<span id="常见误解"></span>VA 失败可能是没有可用下游 VC，也可能是本拍申请未获选。SA 失败则表示符合条件的候选未得到当前交换机会。诊断时应分别记录；credit 不足或链路不可用也不能一概计为交换竞争。

<span id="建模启示"></span>记录每拍候选、可用许可、目标输出、输入和输出的连接限制以及实际 grant。若研究多拍等待，还要记录许可持有、释放及仲裁指针；仅用平均匹配率不能还原包的持有时间或尾延迟。

<span id="一句话理解"></span>VC 分配管理逻辑通道许可，交换分配管理本拍连接；二者共同影响 flit 何时前进。
