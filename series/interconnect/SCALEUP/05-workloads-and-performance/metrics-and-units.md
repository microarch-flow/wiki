# 带宽与时延指标：先统一字节、方向和观察边界

上级：[负载与性能](README.md)

比较互连时，最大的误差往往来自口径不一致。链路线速、应用有效载荷、双向聚合值和集体通信归一化值不能直接互换。

## 每个带宽数字需要哪些标签

| 标签 | 示例与含义 |
| --- | --- |
| 单位 | 1 B = 8 bit；1 GB = 10⁹ B；1 GiB = 2³⁰ B |
| 方向 | 单向发送、单向接收，或二者求和 |
| 范围 | 每 lane、每链路、每设备，或全系统聚合 |
| 数据边界 | 线上编码数据、协议载荷，或应用字节 |
| 时间边界 | 单次设备执行、主机提交，或整任务完成 |

GT/s 表示传输率，不能不考虑编码与每次传输承载的位数就当作 GB/s。接口峰值也不能跳过协议开销、并发与目标服务约束，直接充当应用可持续带宽。

## NCCL Tests 的两种带宽

[NCCL Tests 性能说明](https://github.com/NVIDIA/nccl-tests/blob/master/doc/PERFORMANCE.md)定义算法带宽为算子规定的数据大小 S 除以时间 t，并按算子换算 busbw。对于 N 个 rank 的 AllReduce：

> algbw = S / t<br>
> busbw = algbw × 2(N−1)/N

构造例子：N = 8，每 rank 输入 S = 64 MiB，t = 1 ms，则 algbw ≈ 67.109 GB/s，busbw ≈ 117.441 GB/s。后者较大来自归一化因子，不表示额外产生了应用数据。

这个换算不是对每条物理链路的直接测量。发生网络内归约、多路径或层次化通信时，应结合实际映射解释资源利用率。AllGather、ReduceScatter 等算子对 S 的定义和换算因子不同，必须查对应工具说明。

## 小消息与大消息分别看什么

小消息常受启动、同步和往返开销影响。大消息更容易暴露持续带宽，但仍可能受目标内存或执行资源限制。可用下式作局部拟合：

> T(M) ≈ α + M / B

其中 α 是该测试条件下拟合出的固定项，B 是该区间的有效斜率参数。它不是所有规模通用的物理常数；算法切换、分块或饱和会改变曲线。

报告至少给出多种消息大小、参与者数量、重复统计及错误检查。均值不能代替尾延迟；全系统聚合速率也不能代替最慢 rank 的完成时间。完整测试流程见[下一篇](benchmarking.md)。
