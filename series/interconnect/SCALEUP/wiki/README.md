# 加速器互连：多颗加速器怎样访问对端资源？

当一个任务分布在多颗加速器上，计算之外还要交换数据、等待对端结果，并协调资源使用。互连需要定义端点可以发起什么操作、交换结构怎样转发，以及请求和返回怎样关联。

## 先看一条访问路径

假设加速器 A 需要读取加速器 B 的一段数据。A 先发起对 B 可访问地址的读取；请求可以经过一组链路和交换节点到达 B；B 根据系统允许的访问范围处理请求，并将数据返回给 A。多个请求同时经过共享端口时，排队和竞争会影响完成时间。

这是构造案例。远端地址如何建立、哪些操作被支持、何时视为完成，以及与缓存和软件同步的关系，都取决于具体协议与系统配置。仅有两端的物理连接，不足以说明它们能进行远端内存访问。

## 以 UALink 200G 1.0 为例

[UALink 联盟](https://ualinkconsortium.org/specification/)将 UALink 200G 1.0 定位为计算 pod 内加速器与交换组件之间的互连。联盟对该版本的介绍列出 read、write 和 atomic 等操作，以及分层的协议、事务、数据链路和物理层。[版本概览](https://ualinkconsortium.org/blog/ualink-200g-1-0-specification-overview-802/)

例如，对允许的远端读取，发起端需要保留足够的请求上下文，才能把返回数据关联到原请求。交换端口和目标端也会消耗缓冲及带宽。是否能达到某个任务吞吐，要看拓扑、流量、并发、交换和端点实现；规范能力本身不等于实测性能。

UALink 是本专题的一个标准案例。不同厂商的加速器互连可能采用不同协议和软件契约，不能仅凭“scale-up”或相同线速率推断互通。Scale-up 和 scale-out 的边界也要结合具体系统，而不是用固定距离划线。
