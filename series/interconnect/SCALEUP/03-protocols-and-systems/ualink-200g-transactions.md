# UALink 200G 1.0：一次内存事务怎样穿过协议栈

上级：[协议与系统案例](README.md)

UALink 200G 1.0 面向计算 pod 内加速器与交换组件之间的通信。它公开了读、写和原子内存操作，但这些操作仍需要合法地址、资源和软件同步。本文使用 1.0 作为分层案例；新规范组件见[版本关系](ualink-specification-family.md)。

## 各层分别承担什么

[联盟的 1.0 概览](https://ualinkconsortium.org/blog/ualink-200g-1-0-specification-overview-802/)给出了以下职责。这里解释数据路径，不复刻完整规范字段表。

| 层 | 处理对象 | 在一次事务中的职责 |
| --- | --- | --- |
| Protocol／UPLI 接口 | 读、写、原子及对应消息 | 表达操作，关联分离的请求与响应 |
| Transaction Layer | 事务传输资源及 TL flit | 管理信用，打包和解包 |
| Data Link Layer | TL 与 PHY 之间的数据传送 | 按该层协议传递数据 |
| Physical Layer | 编码后的物理信号 | 完成物理链路承载 |

多个未完成请求需要关联标识。接收响应时，发起端根据关联信息找到等待者及返回位置，不能只按响应到达顺序推断它属于哪一次读取。

## 把层次放回读取过程

假设 A 的地址映射已允许访问 B。A 的事务接口产生读取请求；传输层在资源允许时发送；物理链路承载经过交换结构的数据。B 接收并处理操作，再形成返回。A 收到返回后，完成匹配与数据交付。

目标内存尚未准备好、返回资源不足或出口拥塞，都可能延长这条路径。因而，链路速率不等于目标读取吞吐。[远端读取模型](../02-fabric-architecture/remote-read-path.md)中的在途窗口约束也适用于分析此类路径，但其示例参数不是 UALink 器件参数。

## 200G、规模与兼容性怎样理解

联盟把 200G 1.0 描述为每 lane 的 200G 连接能力，并给出最多 1,024 个加速器的 pod 范围。[规范入口](https://ualinkconsortium.org/specification/) 这个规模不是每个端点到所有其他端点同时达到线速的保证。实际 lane 数、协议开销、拓扑、端点和目标内存还需逐项计算。

UALink 物理层利用了以太网相关技术，不代表 UALink 事务就是普通 Ethernet 帧，也不代表可以直接接入任意以太网交换机。相同线速率、连接器或 SerDes 能力不足以建立协议兼容。

本页不把宣传材料中的效率或时延数字作为实测结果。需要设计寄存器、信用容量或错误状态机时，应查所选规范正文及器件资料，不能从这个概览推导未公开的实现细节。
