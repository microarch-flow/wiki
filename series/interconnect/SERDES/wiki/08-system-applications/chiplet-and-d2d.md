# Chiplet 与 D2D：怎样选择封装内互连？

上级：[系统应用](./README.md)

Die-to-die（D2D）描述芯粒之间的连接位置，不规定唯一协议或电路结构。封装内可以使用不同的串行化程度、数据宽度和时钟方式。是否需要某种 SerDes，要由实际接口决定，不能只根据距离回答。

## 把连接拆成几层

1. **系统语义**：两端要交换流数据、访存事务还是其他消息？顺序、可靠性与流控怎样定义？
2. **协议和适配**：选用什么版本、数据格式、重试 / 校验和初始化机制？
3. **物理接口**：数据线数、每线速率、信号电平、参考时钟、训练与容错如何规定？
4. **封装通道**：信号经过凸点、重布线层、中介层、桥接结构或其他路径；供电、回流与散热如何安排？

层与层之间需要明确映射。凸点、硅桥或混合键合是物理连接手段，本身不会自动规定事务协议或证明互通。

## 宽接口与较高速接口的取舍

在相同目标数据率下，较宽的数据接口可以降低每线所需速率，但需要更多连接、岸线、对齐与封装布线资源；较窄、较高速的接口可能减少数据线数，但对每条通道、时钟和均衡提出不同要求。两者都可能有串并转换或时钟域处理。距离短也不等于没有串扰、供电、热或测试问题。

[UCIe 联盟](https://www.uciexpress.org/specifications/ucie-3-0)将其规范定义为包含封装级 D2D 物理层和协议等内容。其[早期问答](https://www.uciexpress.org/post/introduction-to-ucie-webinar-q-a-recap)也区分数据 lane 和时钟 / 边带等开销；实际引脚、速率和训练要求应查项目采用的规范版本。作为另一种产品接口实例，[OCP 的 TeraPHY 条目](https://www.opencompute.org/chiplets/46/ayar-labs-in-package-optical-io-solution)描述其指定代际的 AIB 电接口。它们不能证明所有 chiplet 使用同一 PHY。

选型时应在同一参考面比较可用带宽、延迟、功耗、带宽密度、面积、可测试性、良率与生态支持；还要说明工艺、封装和对端。没有实际参数时，保留待验证项。
