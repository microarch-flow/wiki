# 多 lane 为什么需要对齐？

上级：[初始化与链路训练](./README.md)

多 lane 链路把一组信息分散到多条路径。各 lane 的通道延迟可能不同，所以属于同一组的内容不一定同时到达。逐 lane 恢复时钟与数据后，接收端仍可能需要按照协议的标记和规则重新对齐。

**lane 间 skew** 是相关数据到达时间的差异；**deskew** 是接收端按规定消除可容许偏差的过程。具体协议可能使用对齐标记、弹性缓冲或其他机制。FIFO 深度、允许 skew、标记间隔和错误动作都必须查相应规范与实现。

## 两条 lane 的教学例子

假设两条 lane 的符号率相同，每个 UI 为 `100 ps`。同一对对齐标记在 lane 0 的时刻 `0 UI` 到达，在 lane 1 的时刻 `2 UI` 到达。两条 lane 的标记到达相差 `2 UI = 200 ps`。

| 对应顺序 | lane 0 到达时刻 | lane 1 到达时刻 |
| --- | --- | --- |
| 对齐标记 | `0 UI` | `2 UI` |
| 第一组数据 | `1 UI` | `3 UI` |
| 第二组数据 | `2 UI` | `4 UI` |

若接收端能正确识别对应标记、缓存较早到达的内容，并在标记位置对齐后按相同顺序读取，就可以把两条 lane 的第一组数据重新配在一起。这里假设偏差稳定、两 lane 无错误、缓冲和控制满足要求。表格只展示逻辑关系，不规定 FIFO 在同一时钟边沿的读写行为。

仅知道 `2 UI` 的偏差，还不能算出实际器件所需的完整 FIFO 深度。还要考虑时钟容差、标记间距、读写时序、允许的动态变化、实现余量与协议限制。lane 间对齐也不能代替字边界恢复或跨时钟域处理。

[Altera Stratix V 收发器手册](https://docs.altera.com/r/docs/683779/current/stratix-v-device-handbook-volume-2-transceivers/deskew-fifo?contentId=cO~VnJWtO05NxONKzLfrpQ)给出了该器件 XAUI 模式中的对齐字符与 deskew FIFO；其参数不应视为其他协议的通用限制。
