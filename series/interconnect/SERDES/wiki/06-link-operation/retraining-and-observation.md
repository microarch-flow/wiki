# 重训练与运行观察：怎样定位变化？

上级：[初始化与链路训练](./README.md)

链路建立后，温度、供电、通道或对端状态可能变化。某些协议或实现会继续自适应，在指定条件下进入恢复、重训练、降速或重新初始化。触发条件和动作不是通用规则，应查看协议版本、器件手册和系统配置。

## 先建立事件时间线

| 记录项 | 要回答的问题 |
| --- | --- |
| 时间与配置 | 两端、端口、lane、速率、宽度、调制和固件版本是什么？ |
| 状态变化 | PLL / CDR、块对齐、训练状态和链路状态何时变化？ |
| 错误与环境 | 错误计数如何增加？温度、供电、复位或线缆状态是否同时变化？ |
| 恢复过程 | 谁发起、经过什么状态、耗时多久？是否改变速率或宽度？ |
| 业务影响 | 同一时间窗内吞吐、延迟、超时或重试发生什么变化？ |

这些记录应带时间戳和计数器口径。计数器清零、溢出、采样间隔不同或日志缺失，都可能改变结论。关联先后顺序有助于提出假设，但不能单凭同时出现就断定因果。

## 一个假设性的排查

假设日志依次显示：某 lane 的错误计数增加，随后链路进入恢复状态，最后以较低速率重新可用。事实是这几项观测按该顺序出现；**无法仅凭它们确定**通道损耗就是根因，也无法确认每次恢复都会降速。

下一步可以在允许的测试条件下，核对两端状态和错误字段，比较不同速率、码型与环境下的复现结果，并检查器件规定的状态转换。若缺少对端日志或出错前的计数器，只能保留待验证结论。不要把一次短时间恢复成功写成长期可靠性结论。
