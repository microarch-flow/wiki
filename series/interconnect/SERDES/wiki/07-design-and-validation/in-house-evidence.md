# 怎样判断自研范围和可用性证据？

上级：[设计与验证](./README.md)

“自研 SerDes”可以指需求、架构、数字逻辑、模拟电路、物理实现、测试或其中一部分。判断工作量时，先列出实际负责的边界和依赖，再讨论结果。购买 IP、使用工艺模型或委托流片本身不能说明其余工作是否由团队完成。

## 把职责和交付物对应起来

| 范围 | 需要的输入 | 可检查的输出 |
| --- | --- | --- |
| 系统需求与接口 | 协议、通道、对端、性能和环境目标 | 有版本的规格、参考面、接口与验收矩阵 |
| 架构、数字与固件 | 需求、时钟、训练和配置规则 | 模型、RTL / 固件、接口约束、仿真与覆盖记录 |
| 模拟电路与版图 | 工艺设计套件、器件 / 寄生模型、供电和封装约束 | 原理图、版图、提取后分析、PVT 与设计检查记录 |
| 样片与系统测试 | 测试芯片、板卡、仪器、测试软件和对端 | 可追溯的设置、原始数据、分析结果和问题记录 |
| 生产与维护 | 制造、封测、筛选和可靠性计划 | 批次 / 样本数据、测试程序、失效分析和版本管理 |

这些是可分工的工程工作项，不是说每个团队都必须独立拥有全部工具或从零实现每个模块。授权 IP 的功能、工艺、支持和验证责任应写清楚。

## 证据应和声明一一对应

| 如果要声明 | 至少要查什么 | 常见的不充分证据 |
| --- | --- | --- |
| “行为正确” | 指定功能、输入、覆盖与检查结果 | 一张框图或编译通过 |
| “电气目标达成” | 指定参考面、通道、条件、误码口径与样片测量 | 一张未注明条件的眼图 |
| “符合某项规范测试” | 规范版本、测试项目、方法及判据 | 功能演示或厂商预期 |
| “与某对端互通” | 对端型号 / 版本、组合、配置、环境与结果 | 单端 BERT 结果 |
| “具备规定的量产 / 可靠性证据” | 生产筛选、样本、批次、条件、可靠性计划与结果 | 一颗典型样片短时间运行 |

证据可以并行产生，也可以因项目迭代而回退。应维护需求到测试的映射，以及未覆盖项和异常，而不是把上述行当作自动通过的线性关卡。PCI-SIG 对[电气测试与系统互通](https://pcisig.com/blog/seamless-transition-pcie%C2%AE-50-technology-system-implementations-webinar-qa)的区分是一个协议实例。
