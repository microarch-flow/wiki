# 从论文到产品的路径

## 为什么 CIM 特别容易卡在产品化

很多 `CIM` 路线在论文里看起来很有吸引力，但真正往前走时，经常停在：

- 研究宏
- 测试芯片
- 工程样机

而走不到稳定出货的产品。

这不是因为论文“没价值”，而是因为 `CIM` 的价值链特别长。一个方案从原理成立到产品成立，必须同时跨过：

- 器件与工艺
- 电路与阵列
- 芯片与系统集成
- 软件栈
- 测试与校准
- 客户验证

任何一个环节断掉，路线都可能停在 demo。

因此，判断一条 `CIM` 路线时，不能只问“它能不能算”，而要问：

1. 它现在处在哪个产品化阶段？
2. 下一阶段最难跨过去的门槛是什么？
3. 它展示的指标属于哪个阶段？

## 一条更实际的阶段划分

可以把 `CIM` 的产品化路径拆成五级：

1. `paper / simulation`
2. `macro / test chip`
3. `chip`
4. `card / module`
5. `deployable system`

这五级不是简单放大关系，而是每一级都新增一层现实约束。

## 1. Paper / Simulation

### 这一阶段在证明什么

通常是在证明：

- 原理是否成立
- 某个阵列、电路或架构是否可行
- 某种 workload 映射是否有潜力

### 常见输出

- 电路仿真
- 阵列建模
- ideal / non-ideal analysis
- kernel 级 benchmark

### 这一阶段最容易出现的问题

- 指标停留在理想条件
- 外围成本没有算全
- 只证明局部 `MVM` 或局部 kernel
- 对系统协同和客户场景没有约束

### 这一阶段该怎么读

重点不是问“结果高不高”，而是问：

- 指标层级是 `array`、`macro` 还是 `system`
- 是否包含 `ADC / DAC / buffer / NoC / control`
- workload 是不是为硬件特意挑选的

## 2. Macro / Test Chip

### 这一阶段在证明什么

这是从“原理成立”走向“硅上成立”的第一步。

它通常证明：

- bitcell、阵列和外围电路能实际工作
- 某些非理想因素是可测、可控的
- 仿真与硅后数据是否大体一致

### 常见输出

- 小规模测试芯片
- 宏级 silicon result
- 精度 / 能耗 / 面积测量

### 这一阶段最常见失败点

- 硅后结果明显弱于仿真
- 非理想因素超出预期
- 校准成本过高
- 测试复杂度太高

### 这一阶段的核心限制

即使宏成立，也还没有证明：

- 多个宏如何组成 tile 和 chip
- 系统吞吐是否成立
- host 协同是否成立
- 软件是否能接得上

### 一个常见误判

把 `macro` 结果直接当成产品路线成熟度的证据。

这通常是错误的，因为这一级更多是在证明“物理与电路可行”，不是在证明“产品可以卖”。

## 3. Chip

### 这一阶段在证明什么

这一阶段开始回答：

- 宏如何拼成可工作的芯片
- buffer、NoC、controller、host interface 如何协同
- 指标是否还能在 chip 级保住

### 常见输出

- 边缘推理芯片
- 原型加速器芯片
- memory-side processing chip

### 这一阶段最常见失败点

- 宏收益被 `buffer / NoC / control` 吃掉
- 功耗和面积扩张过快
- 利用率明显低于理论值
- 软件栈只能人工 mapping

### 这一阶段必须补上的问题

- 哪些算子真的能上 CIM
- 哪些算子必须 fallback
- host 和 chip 的边界是什么
- 指标是峰值还是有效吞吐

### 这一阶段的真正门槛

不是“有没有芯片”，而是：

- 芯片能不能稳定跑目标 workload
- 芯片是否有清晰的软件入口
- 芯片能不能在真实系统中体现收益

## 4. Card / Module

### 这一阶段在证明什么

这一级意味着路线不再只是一颗芯片，而是在尝试进入可部署形态。

它通常要证明：

- 芯片或 memory-side component 能与 host 平台集成
- 板级供电、散热、接口和固件能闭环
- 客户能以较低摩擦接入现有系统

### 常见输出

- accelerator card
- memory module
- reference board

### 这一阶段最常见失败点

- 集成复杂度大幅上升
- 板级与系统级瓶颈掩盖芯片优势
- 驱动、runtime、工具链不完整
- 客户环境和 demo 环境差距过大

### 为什么这一级很关键

因为很多路线在芯片层“有故事”，但一到卡或模组层就暴露出：

- 真实接口代价
- 真实散热和功耗限制
- 真实软件接入成本

也就是从“可展示”进入“可集成”的门槛。

## 5. Deployable System

### 这一阶段在证明什么

这一阶段已经不只是技术可行，而是商业可交付。

它要证明：

- 客户能稳定部署
- 收益在真实 workload 中成立
- 可靠性、维护性、供应链和支持体系跟得上

### 常见输出

- 产品化系统
- 客户试点部署
- 面向真实业务的 solution

### 这一阶段最常见失败点

- 客户导入周期过长
- 维护和支持成本太高
- 场景价值不够刚需
- 供应链不稳定
- 软件生态太弱

### 判断重点

这一级最该问的是：

- 谁在真实付费
- 替代了现有系统中的什么
- 为什么客户愿意承受导入成本

## 每升一级，指标口径都在变化

这是读 `CIM` 公司和论文时最容易忽视的点。

### 在 paper / macro 阶段

更常见的是：

- `TOPS/W`
- area efficiency
- kernel-level accuracy

### 到 chip 阶段

必须增加：

- effective throughput
- utilization
- buffer / NoC / control overhead
- 软件可用性

### 到 card / system 阶段

更该看：

- end-to-end latency
- token latency
- energy per task
- host offload ratio
- 部署摩擦和运维成本

因此，产品化路径的本质之一，就是指标从“局部最优”不断向“系统可交付”迁移。

## 不同路线的产品化难度并不相同

## SRAM-CIM

相对更容易先走到 `chip`。

原因：

- 更兼容标准 `CMOS`
- 更容易嵌进现有 SoC
- 验证与测试路径相对更熟悉

但它也容易卡在：

- 容量不足
- 系统收益不够大
- 只是片上局部优化，客户感知不强

## ReRAM-CIM

最容易卡在 `macro -> chip`。

原因：

- 器件一致性、漂移、校准压力大
- 量产测试难
- 客户对长期稳定性要求高

它经常能证明“局部阵列很强”，但很难迅速进入可部署产品。

## DRAM / HBM-PIM

更容易在 `chip -> module / card -> system` 这段体现价值。

原因：

- 它的价值天然更偏 system-level
- 需要 memory、host、runtime、封装一起配合

它未必最早展示阵列指标，但更容易以“大厂主导的系统产品”形态出现。

## Flash / PCM / MRAM-CIM

难度取决于具体介质成熟度。

关键在于：

- 工艺是否成熟
- 写入和保持特性是否可控
- 客户是否接受其边界条件

## 一个实用的风险判断框架

当你看到一个 `CIM` 团队或公司时，可以先判断它卡在哪一段：

### 卡在 `paper -> macro`

通常说明：

- 原理还没被硅后证明
- 风险主要在器件、电路或模型假设

### 卡在 `macro -> chip`

通常说明：

- 阵列可行，但系统化困难
- 风险在外围成本、软件、集成和量产测试

### 卡在 `chip -> card/module`

通常说明：

- 单芯片能工作，但系统接口、板级集成和工具链还不成熟

### 卡在 `card/module -> deployable system`

通常说明：

- 技术已不再是唯一问题
- 主要风险转向客户导入、供应链稳定性和商业价值

## 哪些信号说明它更接近真正产品

- 不只展示 `macro-level` 指标
- 能明确说明产品形态
- 能说明 host 协同和软件入口
- 能解释为什么客户真的需要它
- 能清楚回答制造、测试、封装和交付链问题

## 哪些信号说明它更像技术展示

- 指标主要停留在局部 kernel
- 大量使用理想条件
- 没有说明 system integration
- 软件栈表述模糊
- 客户价值停留在“更省电”或“更高 TOPS/W”

## 用几个代表对象建立直觉

### TSMC 16nm CIM macro

更适合理解：

- `macro / test chip` 阶段证明什么
- 为什么 `CMOS-compatible` 会降低产品化阻力

### Mythic

更适合理解：

- 从 `chip` 走向产品时，analog 路线会遇到哪些额外门槛
- 为什么产品故事和工程现实之间会有距离

### Samsung HBM-PIM

更适合理解：

- 为什么某些路线天然更像 `system / module` 级能力扩展
- 为什么 memory vendor 的主导力很重要

### SK hynix AiMX

更适合理解：

- 从 memory component 到 accelerator card 的产品化姿态
- 为什么 `card` 级形态是很多系统路线的关键过渡层

## 一个最实用的判断原则

当一条路线声称“已经接近产品”时，至少继续追问：

1. 它现在属于 `macro`、`chip`、`card/module` 还是 `system`？
2. 下一阶段最难跨的门槛是什么？
3. 它的优势在升级一个阶段后还能保住吗？
4. 如果客户今天导入，最先要改的是软件、硬件接口还是验证流程？

## 后续可补充内容

- 分路线产品化时间线
- 不同阶段所需团队能力清单
- 不同阶段的资本开销与验证周期
