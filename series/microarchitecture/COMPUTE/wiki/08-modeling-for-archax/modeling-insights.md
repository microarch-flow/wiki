# 面向 archax 的建模建议：边界、事件与资源

上级：[08 · 面向 archax 的建模](./README.md)
相关：[计算与通信指标](../01-overview/compute-communication-ratio.md)

本页是建模建议，不证明 archax 当前实现了下列字段、接口或硬件能力。具体版本需要核对其设计和实现。可用 Resource 表示资源、Topology 表示连接、Interaction 表示事件、Capability 表示能力约束；具体映射是否适用仍需验证。

## 1. 分边界记录计算和通信

对选定工作量及边界，`useful_MACs / bytes_crossing_boundary` 的单位为 MAC/byte。分母为零时不定义该比值。RF、阵列、NoC 和片外存储分别统计；一个字节穿过多个边界时，各边界都可各计一次，不能把所有层的计数相加后称作片外流量。指标随边界、窗口和是否包含配置变化，不是跨层不变量。面积、MAC/s/mm² 和能耗是独立指标。

## 2. 格式、位宽与执行能力

记录元素和累加格式、块 scale、数据布局与实际运算能力。MXFP4 的 32 个 E2M1 元素加一个 E8M0 scale，在无额外填充时为 17 B。乘法部分积的 `p×q` 只是结构代理；FP4/FP8 的吞吐、面积和能耗须分别依据目标实现，不预设通用倍数。

## 3. RF 与阵列的资源预算

记录阵列尺寸、RF 容量、端口、面积、供数带宽和布局。`RF_area/N²` 只有在 RF 面积保持不变时才随 N 增大而下降。还要计算实际的填充、排空、供数和冲突，不能从门数代理或阵列形状直接推出最佳尺寸。

## 4. 权重加载与重叠

对每拍注入 `x` 个权重并同步移位的 `x×y` 阵列，冷装需 `y` 拍；最后一行到位已包含在这 `y` 拍内。首次计算和每次换 tile 以权重就绪为依赖。只有独立 bank、足够供数和无冲突写入允许时，才可用计算时间覆盖下一块加载。记录加载事件、bank、开始和完成边沿，以及冷启动与换块 stall。

## 5. Cache 与 scratchpad 的事件语义

scratchpad 的显式放置不保证固定访问时间。假设单 bank 单读端口每拍接纳一次，A、B 在周期 0 同时到达，仲裁让 A 先发，服务延迟各一拍：A 在周期 1 完成，B 在周期 2 完成。端口、bank、DMA 和仲裁必须进入模型。

cache 的命中依赖初态、地址流、替换、并发和仲裁。给定完整且确定的状态与规则，可以确定性模拟；未知输入或随机替换可使用标注前提的统计模型。两类资源都记录到达、接纳、完成与阻塞原因。详见 [cache 与 scratchpad](../../../../storage/01-memory-hierarchy/02-access-paths/cache-vs-scratchpad.md)。

## 6. 资源拓扑与跨单元流量

记录节点、连接、边界带宽、仲裁和数据方向。大阵列与多个小阵列可能呈现不同的供数、利用率与通信代价；必须根据具体拓扑与负载测量或模拟，不能用固定线数概括所有 TPU 或 GPU。

## 7. 时钟路径与反馈依赖

一个时钟域的周期下界由所有有效前馈和反馈 setup 路径共同决定，hold 另行检查。假设反馈路径完整要求为 1 ns、前馈为 1.4 ns，且没有更慢路径，则周期至少 1.4 ns，频率不超过约 714 MHz。不同域、CDC 与 I/O 分别处理。保留工作流的延迟、II、依赖距离和反压；没有 PVT 和 STA 数据时频率是建模假设。
