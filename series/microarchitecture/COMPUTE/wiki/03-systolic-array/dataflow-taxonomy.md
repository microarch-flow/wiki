# Dataflow：权重、部分和与输入如何复用

相关：[阵列边界流量](./why-systolic-array.md)、[权重加载](./weight-loading-and-trickle-feed.md)、[阵列 sizing](./array-sizing-tradeoff.md)

## Dataflow 的输入和输出

矩阵乘 `out[i,k] += in[i,j] * w[j,k]` 使用激活、权重和部分和。Dataflow 决定这些数据放在哪里、如何跨 PE 或存储边界移动，以及何时归约。Stationary 描述某个时间窗口内的驻留位置，不意味着该张量从未加载、从未移动或没有能耗。

## Weight-stationary

权重在 PE 或指定局部存储中驻留一段时间，多个输入可复用它；激活进入阵列，部分和按实现移动或归约。复用次数越多，首次加载可能越容易摊薄。首块、换 tile、容量不够及频繁更新时仍要计算加载。若 PE 阵列位于片上，驻留在 PE 的权重此时已在片上；上层片上缓冲区也可能另有副本。是否要从外存读取，取决于本次首次供应前的驻留状态、驱逐和重装；是否跨请求复用取决于驻留区间。

## Output-stationary

部分和在某个局部位置累加，直到完成该段 reduction，再按实现写出或合并。权重和激活必须被供应；局部部分和的存储、访问和归约也有成本。深 reduction 与较宽的部分和可能使减少跨某边界的部分和读写有利，但最终选择还受权重复用、带宽、容量和映射影响。

## Row-stationary 与卷积复用

卷积的 sliding window 可在相邻输出之间重用输入；同一卷积核权重可用于多个位置，部分和也有局部累积机会。Row-stationary 尝试结合这些复用，但具体数据在各层存储中的移动取决于映射与互连。比较时须同样计入加载、交换和输出。

## 为什么小 batch 不决定唯一瓶颈

小 batch 或 decode 可能减少同一时间窗口内的权重复用，并降低阵列填充。但权重是否跨 HBM 重读、片上是否足以驻留、模型与 tile 形状、多个请求能否并行，都影响实际结果。不能断言所有 stationary 都失效，也不能仅凭 batch 判断任务必然 memory-bound。即便 memory-bound，不同 dataflow 仍可能改变流量与性能。

## 建模启示

对每个 dataflow 记录 tensor 形状和位宽、每层存储容量、驻留区间、重用次数、加载和驱逐、部分和位置、跨边界字节及争用。计算和通信时间按依赖与资源日程组合。比较时报告同一工作量的冷启动与稳态窗口、各边界 MAC/byte、吞吐、延迟和能耗；最少 bytes 不自动等于最短时间或最低能耗。
