# Cache 与 scratchpad：数据放置和访问时间

上级：[06 · 存储 discipline](./README.md)
相关：[RAM：scratchpad 与 cache](../../../../storage/RAM/wiki/03-sram-applications/scratchpad-vs-cache.md)、[计算与通信指标](../01-overview/compute-communication-ratio.md)

## 两种数据管理方式

cache 通常根据地址和硬件状态查找数据；miss 可触发填充或替换。scratchpad 通常由软件显式放置和访问数据。前者提供自动管理，后者让软件控制局部容量与生命周期。具体一致性、权限和同步语义由实现定义。

地址和数据位置已知不等于整笔访问耗时已知。scratchpad 仍受端口、bank、仲裁、DMA 和其他请求影响。cache 的命中也不是本质随机：如果初始状态、地址流、替换和仲裁规则、事件顺序都确定，模拟器可以确定性复现命中和服务时间。未知输入或随机策略则可按分布建模。

## 同时访问的反例

假设 scratchpad 的一个 bank 只有一个读端口，每拍接纳一个请求，接纳后一拍返回。请求 A 和 B 在周期 0 同时到达同一 bank；两者地址和数据均已知。若仲裁让 A 先发，则 A 在周期 1 返回，B 要到周期 1 才能接纳、周期 2 返回。若到达顺序或仲裁改变，结果也可能改变。两个请求分别落到可独立服务的 bank 时，结果则可能不同。

这里的“一拍返回”是例子假设。真实系统还需检查写冲突、DMA、backpressure、频率和接口规则。只有资源分配、到达时间和冲突规则都已知，或已证明不存在争用，才可给出相应情况下的确定服务时间。

## 建模启示

对 scratchpad 保留数据放置、bank 映射、端口数、接纳间隔、服务延迟、仲裁和 DMA 请求。对 cache 保留初始状态、地址流、tag、替换、fill 和共享资源；也可在证据不足时使用明确标注的统计近似。两者都应记录到达、接纳、完成及阻塞原因。架构工具采用哪种默认模型是实现选择，不由本页推断。
