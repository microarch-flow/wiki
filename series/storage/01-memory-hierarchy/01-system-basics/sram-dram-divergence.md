# 同样是 RAM，为什么 SRAM 和 DRAM 走向了完全不同的工程路径

<span id="这页在回答什么问题"></span>
<span id="存储方式决定访问与密度"></span>

上级：[RAM 存储系统概览](./README.md)

相关：[RAM 分类与命名](./taxonomy.md) · [6T SRAM cell](../../02-sram/foundations/6t-cell-bistable-storage.md) · [1T1C 存储单元](../../03-dram/foundations/1t1c-cell-destructive-read.md)

<p class="ram-problem-lede">SRAM 和 DRAM 都能按地址访问数据，但常见单元保存数据的方式不同。这个差异影响保持、感测和阵列组织，也影响系统需要怎样安排访问。</p>

本文比较常见的 6T SRAM 和 1T1C DRAM。它们是有代表性的实现，不覆盖所有 SRAM、DRAM 或存储宏。具体延迟、密度、能耗和成本还取决于工艺、容量、外围电路、接口及工作条件。

## 1. 两种单元怎样保存一个 bit？

| 问题 | 常见 6T SRAM | 常见 1T1C DRAM |
| --- | --- | --- |
| 状态保存在哪里？ | 交叉耦合的反相器形成双稳态。 | 电容上的电荷表示数据。 |
| 保持需要什么？ | 满足供电、保持电压和噪声等条件；不需要 DRAM 式周期刷新。 | 满足供电等条件，并按器件要求维持各行的数据。 |
| 常见单元结构 | 6 个晶体管，包括存储电路和访问晶体管。 | 1 个访问晶体管和 1 个电容。 |

这是**单元结构**的比较。完整存储器还需要译码、感测、驱动、控制和接口电路。常见 DRAM 单元为高密度设计提供了有利条件，但不能只用“1T 对 6T”直接计算两种完整存储器的面积、成本或速度；制造工艺和外围开销也不同。

[MIT 的计算机结构课程](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/c14/c14s1/)介绍了 SRAM 和 DRAM 的基本组织。下面进一步区分一次读取中的动作。

## 2. 6T SRAM：读取要保持单元稳定

以典型的差分 6T SRAM 读取为例。外围电路先准备位线；选中字线后，cell 连接到位线，并使两条位线产生可供感测的差异。读出放大器或其他读出电路取得数据，随后宏按其接口时序提供结果。

读取会扰动 cell 的内部节点。**正确工作时，扰动不能使 cell 翻转**；读完后，cell 应继续保存原来的值。因此，SRAM 不需要像常见 1T1C DRAM 那样，为恢复被读取行的电荷而执行对应过程。但这不表示读取没有感测、预充、延迟或能耗，也不表示仅有电源就足以保证保持条件。

设计既要让读取时的扰动可控，也要允许写入电路改变状态。不同 cell 和读出方式有不同约束；[一项 6T 与 8T SRAM 的研究](https://ieeexplore.ieee.org/abstract/document/10382712)展示了读稳定性与单元结构的关系，但其仿真结果只适用于论文中的设计与工艺。

## 3. 1T1C DRAM：开行时感测并恢复数据

假设目标 DRAM bank 当前没有打开的行，控制器需要访问其中一行。以常见 DRAM 的简化过程为例：

1. 控制器发出 **ACT**，选择目标行。单元电容与位线连接并共享电荷，原有电荷状态受到扰动。
2. 感测放大器识别位线上的微小变化并放大；在单元仍与位线连接时，单元状态得到恢复。
3. 满足列访问条件后，控制器可以发 **RD**，从已打开行选择所需数据。恢复可能与后续列访问重叠，不能假设每次 RD 都重新执行一次 ACT。
4. 若之后要打开同一 bank 的其他行，当前行需要在满足相关条件后关闭并预充，然后才能打开新行。

第 2 步的恢复是行激活过程的一部分，不应额外假设每次 RD 后都有一条独立的“写回单元”命令。有关感测、恢复与列访问重叠的解释，可参考 [CMU 对 DRAM 延迟的研究](https://users.ece.cmu.edu/~omutlu/pub/understanding-latency-variation-in-DRAM-chips_sigmetrics16.pdf)。

命令何时可以发出，还取决于协议和器件。例如，在 DDR4 的一种简化模式下，假设 `AL=0`，且 CA parity 和 CS-to-CA latency 均关闭，`tRCD` 约束外部 ACT 到 RD/WR，`tRAS` 约束 ACT 后何时可预充；此前的 RD 或 WR 也可能引入其他预充约束。具体参考边沿和模式条件见 [DRAM 时序参数](../../03-dram/protocols/timing-parameters-trcd-trp-tras.md)。不能把这些参数直接当成所有模式下的完整端到端延迟。

### 读取恢复与周期刷新

读取恢复和周期刷新解决的是相关但不同的问题。开行时，所选行的单元状态会得到恢复；而器件仍须在规定窗口内满足**所有需要保持数据的行**的刷新要求，包括应用长时间未访问的行。控制器可以按目标协议发出刷新命令，或使用器件支持的自刷新模式。

不能只因为程序正在读写，就假设刷新要求自动得到满足。[Micron 的常见问题说明](https://my.micron.com/sales-support/sales/faqs)讨论了在规定时间内覆盖所有相关行的特殊条件；能否采用这种方式，仍应以目标器件、协议和系统保证为准。

## 4. 同一地址，为什么访问过程可能不同？

假设一笔读取已到达 DRAM 控制器，目标位于 bank 的 R5 行。bank 稳定处于对应的开行或预充状态，没有自动预充等未完成动作。先不考虑其他请求和刷新，只比较该 bank 原先的行状态：

| 目标 bank 的状态 | 本次读取可能需要的命令 |
| --- | --- |
| R5 已打开 | 满足相关约束后发 RD；不需为本次读取再次打开 R5。 |
| 没有打开行 | 满足条件后先发 ACT 打开 R5，再发 RD。 |
| 其他行已打开 | 满足关行条件后发 PRE，再 ACT 打开 R5，最后发 RD。 |

表中的命令关系和进一步解释见[存储系统为何难设计](./problem-statement.md)。每一步仍受目标协议、器件和共享通路约束。上表不包含命令间的等待或数据返回时间；在真实系统中，row hit 也可能排队，不能只凭行状态断言某笔请求的端到端延迟一定更短。

SRAM 访问同样可能等待。例如，两笔请求可能竞争同一个 bank、端口或返回通路。即使一个 SRAM 宏在指定条件下具有固定的接口访问延迟，**请求接纳之前的等待**仍可能随系统状态变化。

## 5. 这些差异怎样影响系统选择？

Cache 数据阵列和 scratchpad 常用 SRAM；主存或设备内存常使用 DRAM。SRAM 常被用于需要片上局部访问的场合，DRAM 常被用于需要较大容量的场合。这些是常见取向，不是角色与单元之间的一对一定义。Register file 也可以采用不同电路实现。

系统还要比较工作负载、接口和完整路径。增加本地 SRAM 容量可能减少外存流量，也可能增加面积或背景功耗；选择更宽的 DRAM 接口可能增加峰值带宽，却不保证每笔请求的延迟下降。讨论这些取舍时，应对齐测量边界和工作条件，见[速度·容量·成本·功耗](./memory-hierarchy-tension.md)。

## 一句话理解

常见 SRAM 用双稳态电路保存数据；常见 DRAM 用电容电荷保存数据。两种方式带来不同的保持和访问约束，但具体系统表现仍取决于阵列、接口、调度和工作负载。

## 建模启示

先定义模型要回答的问题，再决定保留哪些状态：

| 要研究的问题 | 可能需要保留的信息 |
| --- | --- |
| SRAM 端口或 bank 冲突 | 请求大小与地址映射、端口接纳规则、共享通路和响应时间。 |
| DRAM 行状态和命令调度 | 地址映射、bank 的打开行、命令时序、队列、调度与必要的刷新规则。 |
| 某固定条件下的粗略系统估算 | 指定边界内经过校准的延迟、带宽及其适用条件。 |

宏的访问延迟、下一次请求的接纳间隔和排队等待应分别定义；一个值不能自动代表其余两项。如果问题不涉及 DRAM 内部状态，可以采用有适用范围的简化模型；但这种模型不能单独解释改变地址映射、行状态或调度后的结果。[gem5 的 SimpleMemory 文档](https://www.gem5.org/documentation/general_docs/stdlib_api/gem5.components.memory.simple.html)提供了用于非存储子系统设计研究的简化模型示例。
