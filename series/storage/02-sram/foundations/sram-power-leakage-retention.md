# SRAM 低功耗：漏电、保持与唤醒

上级：[SRAM 基础](./README.md)

相关：<span id="漏电保持电压low-power-sram-设计"></span><span id="这页在回答什么问题"></span>[先进工艺与 SRAM](./sram-process-scaling-challenge.md) · [TCM 与实时性](../applications/tcm-itcm-dtcm-in-mcu.md) · [存储系统建模模板](../../reading-and-reference/02-reference/memory-modeling-template.md)

<p class="ram-problem-lede">SRAM 在空闲时也可能消耗功率。降低供电或关闭电源可以改变这部分代价，但系统还需要决定保留哪些数据，以及何时能再次访问。</p>

本文区分供电状态、数据保持和系统恢复。`sleep`、`retention`、`shutdown` 等名称在不同器件中可能有不同定义；不能只凭名称推断数据一定保留或丢失。

## 保持状态与供电模式

常见 SRAM 的双稳态需要满足供电及其他保持条件。没有访问时，cell 和外围仍可能有漏电；时钟、控制和电源电路也可能消耗功率。关闭时钟可以减少一部分切换，但不等于所有电源都关闭，也不代表漏电变为零。

下面是用于讨论的三类状态，不是通用接口标准：

| 状态 | 数据与访问 |
| --- | --- |
| 工作或可访问 | 满足宏的读写供电和时序条件；空闲时仍可能消耗背景功率。 |
| 保持 | 按目标宏的条件保留指定数据；进入该状态后是否还能直接访问，由宏定义。 |
| 不保证保持 | 相关存储电源可能关闭；系统不能假定数据仍有效，恢复后可能需要初始化或重装。 |

下图是用于说明边界的状态转换，不规定所有宏都具有这些状态或允许这些转移：

<div class="ram-calculation">
  <span>保持路径：可访问 → 进入保持 → 保持 → 唤醒 → 可访问</span>
  <span>不保持路径：可访问 → 断电或不保证保持 → 恢复供电 → 初始化或重装 → 可访问</span>
</div>

进入、唤醒与恢复期间能否接纳请求、内容何时有效，应按目标接口确认。保持电压与正常读写所需的最低电压应分别确认。即使保持状态保住了内容，也不代表可以在该状态立即执行正常读写；恢复时间、隔离信号和允许访问的时刻都要查目标规格。

以 [ST 的 STM32WBA 低功耗说明](https://wiki.st.com/stm32mcu/wiki/Connectivity%3ASTM32CubeWBA_Low_Power_Management)为例，其部分 Standby 配置可以选择保留 SRAM 内容，并使用低功耗供电。器件退出 Standby 还涉及系统复位与重新配置。这是器件级实例，不代表所有 SRAM 宏具有同样的模式或唤醒行为。

## 怎样比较空闲与保持的能量？

假设同一个观察窗口长度为 `T`，比较以下两个教学方案：

- 方案 A 一直处于可访问的空闲状态，背景功率恒为 `P空闲`。
- 方案 B 在整个窗口按 `P保持` 计背景功率；进入和退出保持额外消耗 `E切换`。假设切换时间为零，保持数据，无需重装，也没有其他活动。

两个功率采用相同测量边界。`E切换` 是**未计入背景功率的额外能量**，避免重复计算。在 `P空闲 > P保持` 且 `E切换 ≥ 0` 时：

<div class="ram-calculation">
  <span>方案 A 能量 = P空闲 × T</span>
  <span>方案 B 能量 = P保持 × T + E切换</span>
  <span>两者相等时：T = E切换 / (P空闲 − P保持)</span>
</div>

例如，假设 `P空闲 = 2 mW`、`P保持 = 0.5 mW`、`E切换 = 3 μJ`，则平衡时间为 `2 ms`。在这个理想模型下，窗口为 `1 ms` 时，A 消耗 `2 μJ`，B 消耗 `3.5 μJ`；窗口为 `5 ms` 时，A 消耗 `10 μJ`，B 消耗 `5.5 μJ`。这些数字只是手算，不是器件规格。

真实切换需要时间，切换期间的功率也可能不同。比较时应按各状态实际停留时间计算，并计入进入、唤醒以及必要的初始化或数据重装；不要同时把同一段能量算进背景功率和转换能量。即使能量更低，唤醒太慢也可能不满足请求的时间约束。

## 断电后怎样恢复？

如果目标 SRAM 在断电模式下不保证内容，恢复供电只使硬件有机会重新工作，不自动恢复原数据。系统可能需要重新初始化、从其他层装载，或等待生产者重新生成数据。恢复完成前能否接纳请求、旧内容何时失效，都属于系统契约。

如果存储受 ECC 保护，还要确认数据和校验位是否一起保留，以及何时完成初始化。部分写入若先读出整个校验字，未初始化的内容可能在读改写期间触发错误。[TI 的 TMSx70 说明](https://www.ti.com/lit/an/spna126/spna126.pdf)给出了该系列 RAM/ECC 初始化的具体流程；不能将其中的步骤直接套用于其他器件。

例如，假设某个临时 buffer 的数据在下一轮计算前本来就会重新生成，断电可能是一个值得比较的选项。若数据只能留在该 SRAM 中，或重装时间超出任务允许范围，则保持可能更合适。这是决策条件，不是对所有 NPU 或 MCU 的统一结论。

## 粒度为什么重要？

若一个宏或系统实际支持按 bank、页或其他分区独立控制，就可以选择只保持需要的数据。这样可能减少背景能量，但会增加控制、电源或数据管理代价。逻辑上划分了多个 bank，并不自动代表它们有独立电源域或保持控制。

做比较时，还需要知道数据放在哪些分区、它们会空闲多久、何时必须再次可用，以及工作负载是否允许重装。具体电路和可控制粒度以目标宏或器件资料为准。

## 一句话理解

低功耗策略要同时回答三个问题：省下多少背景能量、数据是否保持，以及恢复访问需要多少时间和能量。

## 建模启示

先定义观察边界和状态，再记录每种状态的功率、数据保持条件、允许操作，以及进入和退出的时间与能量。如果状态不保证数据有效，还要记录初始化或重装的来源、时间和资源竞争。

若只研究不受低功耗转换影响的短时吞吐，可以在说明条件后折叠这些状态；若比较空闲能耗、按 bank 管理或唤醒对延迟的影响，则需要显式保留相应状态与事件。状态名和参数应来自目标宏或系统设计，而不是给所有 SRAM 套用同一套模式。
