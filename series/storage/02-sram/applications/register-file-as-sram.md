## 这页在回答什么问题

Register file 的访问角色与 SRAM 实现之间有什么关系？本页从执行管线的操作数需求出发，分析物理端口、bank 和旁路。寄存器堆是一种系统角色，也可以由触发器、锁存器或其他结构实现。

## Register file 的访问角色与 SRAM 实现 {#寄存器堆的访问角色与端口}

一条双源、一目的的指令，在其执行过程中需要取得两个源值，并在适当时间产生一个结果。具体设计可能从寄存器堆读取源值，也可能从旁路网络取得；写回也可能发生在另一个流水阶段。因此，**两源一目的的逻辑需求不自动等于一个物理 SRAM 宏必须提供 2R1W 端口**。同拍最多有多少次物理读写，取决于发射、操作数就绪、旁路和写回调度。

[BOOM 的寄存器堆与旁路文档](https://docs.boom-core.org/en/latest/sections/reg-file-bypass-network.html)给出一个具体设计：读口静态分配给发射端口，旁路网络为相关指令转发结果。文档还讨论了动态调度较少读口的可能方案及其额外复杂度；该讨论不能当作上述静态分配实现的现有能力。

### 两个 bank 的冲突例子

假设寄存器按编号奇偶分到两个 bank，每个 bank 每拍只能接纳一笔物理读；当前没有旁路或同地址广播，两个请求都已就绪：

- 同拍读取 `R2` 和 `R3` 时，两笔请求分别到 bank 0 和 bank 1，可以各自接纳。
- 同拍读取 `R2` 和 `R4` 时，两笔都到 bank 0。即使 bank 1 空闲，bank 0 也只能先接纳一笔；另一笔要等待，除非设计提供其他服务路径。

复制阵列可以增加可用读路径，但写入需按实现更新副本。真多端口、增加 bank、时分复用和复制分别有不同的面积、布线、调度和一致性代价，见 [SRAM 端口与代价](../foundations/single-port-dual-port-multi-port.md)。对于读取同一个寄存器的多个请求，只有设计支持时才能合并或广播。

### 写回、旁路和可见性

假设较早指令正在产生 `R5`，较晚指令需要该值。如果值尚未写回，旁路可能直接把结果送到操作数输入；若旁路不可用，调度器需要按实现等待。若读写在相近时刻访问同一条目，还要确认阵列碰撞规则以及外部转发或仲裁行为。架构上的程序顺序与阵列内部“读旧值或新值”不是同一个约定。

## 一句话理解

寄存器堆连接执行管线与存储实现。分析它时，要把逻辑操作数需求映射到实际读写端口、旁路和调度。

## 建模启示

按流水阶段记录源操作数需求、值何时就绪、旁路覆盖范围、bank 映射和每个物理端口的接纳能力。再记录冲突时等待或重发的规则，以及写回和读出何时可见。如果只需要功能结果，可以使用更粗的抽象；比较发射吞吐或结构冒险时，就不能忽略这些服务路径。
