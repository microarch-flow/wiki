# AI 工作负载与系统建模

上级：[HBF Wiki](./README.md)

HBF 的潜在收益取决于数据是否能放下、请求是否能并行，以及计算是否能在数据到达前做好准备。建模应从工作负载和资源关系开始，再用有来源的参数校准；不能仅把 HBF 写成一个容量和一个峰值带宽。

## 不同数据有不同约束

| 数据或场景 | 应检查的访问特点 | 可能的系统问题 |
| --- | --- | --- |
| 模型权重 | 常驻容量、重复读取、模型更新频率 | 大块搬运、channel 分布、启动和更新成本 |
| MoE expert | 每次激活哪些 expert、大小和并发 | 稀疏请求、热点、预取是否及时 |
| KV cache | 读写频率、生命周期、布局和重用 | 小粒度访问、频繁更新、写入寿命和搬运放大 |
| 中间 tensor | 数据产生与消费时间、临时性 | 是否应优先留在更适合写入的缓冲 |
| 多模型服务 | 同时活跃的模型、每个模型的请求分布 | 带宽隔离、公平性和总容量 |

表中只是需要检查的问题，不代表 HBF 一定适合或不适合其中任何一类数据。尤其不能仅因 NAND 非易失，就把频繁更新的数据放入 NAND 而忽略写入约束。

## 预取什么时候有效

假设计算将来需要数据块 B。若编译器或运行时能提前知道地址，就可以在计算数据块 A 时发起 B 的读取。要隐藏等待，至少需要满足以下条件：

1. B 的地址和依赖足够早可知，读取本身不违反数据一致性。
2. 搬运和计算所需的资源允许重叠，且有空间容纳预取数据。
3. B 在被消费前到达；错误、排队和竞争没有使它错过截止时间。
4. 预取不会挤占更重要的请求，或造成过多无用读取。

例如，MoE 的实际 expert 在路由结果产生后才确定。预取可以采用预测或更早的路由信息，但错误预测会带来额外流量。是否净收益，需要测量命中率、浪费和排队影响。

## 一个容量与传输时间示例

假设某次操作必须读取 100 GiB 有效数据，稳定有效带宽为 0.8 TB/s，数据不能在操作前预取，也不考虑缓存命中，则仅传输该数据的时间下界约为：

**100 × 2³⁰ B ÷ (0.8 × 10¹² B/s) ≈ 0.134 s。**

这是根据**假设的有效带宽**计算的下界，不是 HBF 实测。排队、阵列、计算依赖和其他竞争可能增加完成时间；若数据可以预取或被重复利用，应用可见等待也可能不同。模型参数数量乘以每参数字节数只是权重容量的起点，还要计入量化元数据、冗余、其他数据和实际可用容量。

## 先定义模型的输入与输出

| 层次 | 建议输入或状态 | 可观察输出 |
| --- | --- | --- |
| 工作负载 | 地址、大小、读写类型、到达时间、依赖与截止时间 | 逻辑请求与有效数据量 |
| host 映射 | 全局地址到 channel 的规则、可发起请求数 | 各 channel 请求分布 |
| base die | 队列深度、缓存与顺序、调度和 ECC 参数 | 排队、命中、错误和完成状态 |
| NAND 资源 | bank 组织、服务间隔、冲突、P/E 与刷新条件 | 忙闲时间、访问和维护事件 |
| 数据路径 | 每段链路带宽、传输粒度、缓冲、背压 | 传输时间、流量和争用 |
| 系统 | HBM、片上缓冲、计算依赖和预取策略 | 应用等待时间、吞吐与资源利用率 |

上表是建议的建模范围，不是对特定产品内部结构的确认。若早期只做容量分析，可以暂时聚合资源；若结论依赖热点、尾延迟或写入寿命，则需要保留相应状态。

## 功耗和能耗怎样建模

功率的单位 W 是能量变化速率；能耗的单位 J 对应一段时间的累计能量。可以先定义同一观察边界内的基线功率与增量事件能耗：

**总能量 = 基线功率 × 时间 + 各类增量事件能耗之和。**

读取、内部传输、ECC、写入、擦除与刷新可以分别建模，但只应在参数具有可加性时相加。若某个测量已经包含 PHY 和 ECC，不能再重复加一次。活动重叠、温度和供电效率也可能改变功率。

GB/W 是给定条件下的容量与功率之比；pJ/bit 是能耗与传输或有效数据量之比。它们回答不同问题。没有测量或产品规格时，不应把任意功耗扫描范围写成厂商保证值。产品资料边界见[第 8 篇](./08-spec-and-industry.md)。

## 最少需要报告哪些结果

对一次模拟或实验，至少记录访问分布、预取策略、参数来源、平均和尾部延迟、有效带宽、缓存命中、各 channel 利用率、维护流量和错误假设。对比 HBM 或 SSD 时，还要说明容量、成本、封装、工作负载和观察边界是否一致。

这种模型可以用于探索设计；没有实测校准时，结果属于假设驱动的估算，不能证明产品性能、系统收益或硬件可实现性。可继续参考 [RAM 存储层级](../01-memory-hierarchy/01-system-basics/memory-hierarchy-as-system.md)和 [NoC 与存储系统](../../interconnect/NOC/wiki/05-system-integration/noc-meets-memory-system.md)。
