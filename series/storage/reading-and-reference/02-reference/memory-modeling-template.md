## 用途与输入输出

原“存储器在架构探索中的建模模板”首先要求写明设计问题、输入工作负载和预期输出。例如：在相同地址轨迹下比较两种映射的吞吐和 p99。记录模型边界、协议版本、工作点、参数来源、未知项和不支持的机制。

<span id="模型边界与统一骨架"></span>

## 按问题选择抽象

静态上界模型适合初筛容量和理想流量；排队模型可分析给定服务假设下的平均行为；命令级模型适合研究行状态和调度。它们的成本、输入和可解释结果不同，不要求所有模型共享一个事件循环。

<span id="1-资源对象先把系统里真正会被争用的东西列出来"></span>

## 1. 资源与静态能力

列出与问题有关的存储、端口、bank、队列、链路、控制器或 DMA。对每项记录容量、允许的读写组合、带宽、时钟、粒度与并发上限。静态能力不是实际占用。

<span id="2-连接关系写清资源如何连接而不是默认一切互通"></span>

## 2. 拓扑与连接语义

列出节点与有方向的连接，记录路径、传输单位、带宽、延迟、共享仲裁域及多播或复制语义。不可默认任意资源互通，也不可把不同边上经过变换的字节直接相加。

<span id="3-state别只记录参数要记录会改变未来决策的状态"></span>

## 3. 选择动态状态

根据目标保留请求队列条目、端口占用、数据驻留和搬运状态。若分析 DRAM 调度，还需按 channel、rank、bank group、bank 标识行状态和相关时限。未来的数据总线预留与当前 bank 状态是不同的状态。

<span id="4-运行时交互把系统里真的会发生的事情写成事件"></span>

## 4. 事件与可见性

必要时区分请求到达、接纳、命令发出、数据返回、写入可见、刷新和低功耗转换。说明事件同一时刻的处理次序、背压、完成条件及输入时钟单位。静态模型可以没有这些事件。

<span id="5-constraint用-guard-表达为什么现在不能做"></span>

## 5. 约束与合法动作

需要命令级行为时，用目标器件时序和模式限定 ACT、RD、WR、PRE、刷新及数据总线方向切换；列出共享命令总线、bank、端口、队列与数据通路的冲突规则。不能只检查一个 guard。DDR4 示例见 [时序速查](./timing-parameter-cheatsheet.md)。

<span id="6-能力边界把上界能力参数化但不要只剩它们"></span>

## 6. 参数和动态结果分开

能力上限、实际队列长度、实际带宽和 QoS 目标分别记录。把未知值标注为待测；使用假设时给出范围并做敏感性分析，避免将目标或标称峰值当作保证。

<span id="7-observation最后输出什么统计量决定模型能回答什么问题"></span>

## 7. 观测与统计定义

每项指标说明时间窗口、字节和请求分母、发起与完成端点、单位、统计粒度及样本数。需要尾延迟时报告分位数并保留每来源进展；未完成和超时请求不能悄悄从结果中消失。

<span id="8-怎么按问题裁剪精度"></span>

## 8. 依据问题裁剪模型

例如，比较容量上界只需容量与工作集；比较片上 bank 冲突需要地址映射、端口和并发；比较 DRAM page policy 则需要行状态和相关时序。不能用缺少对应机制的模型宣称比较已完成。[gem5 SimpleMemory](https://www.gem5.org/documentation/general_docs/stdlib_api/gem5.components.memory.simple.html)展示了延迟和带宽可配置的简化存储组件。

<span id="9-一个最小可复用骨架"></span>

## 9. 命令级离散事件示例

以下只是调度框架示意，不是通用模型接口：

1. 接收已到达请求，并处理当前时刻完成的事件。
2. 在各独立命令域，根据当前状态和全部 guard 生成合法动作，再按所选策略选择。
3. 对将使用的共享资源及未来 DQ 时间窗原子预留；后续同刻选择必须看到更新后的预留。另一种实现可先联合选择互不冲突的动作，再一次提交。
4. 更新状态、记录事件和统计，推进到下一事件。若仍有未完成请求却无法推进，应报告无进展原因，不能将其计为成功完成。

请求粒度、命令域和共享资源须按具体系统定义。

<span id="最后一个判断标准"></span>

## 验证与校准

先用小轨迹验证地址映射、同址冲突、行切换、刷新、总线预留及请求守恒；再与有出处的参考模型或同条件测量比较。区分代码正确性、参数校准和硬件预测能力；参考模型一致不等于实测硬件验证。

<span id="一句话理解"></span>

## 如何判断抽象是否足够

删去某状态后，若模型不再能区分本次问题中的候选方案，就需要补回相关状态或限制结论范围。仅增加细节并不能自动提高准确度。

<span id="建模启示"></span>

## 形成可复用记录

保存问题、输入轨迹、参数来源与单位、资源和连接、选择的状态及 guard、指标定义、验证结果和未覆盖条件。每次比较都记录具体版本，保证别人可以复现。
